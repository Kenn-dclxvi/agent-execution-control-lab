# Candidate301 C280のrootの`AGENTS.md`のMarkdownの書式を揃える

2026-10-09。利用者の指示（C280のMarkdownの書式が統一されていないので、書式を直したCandidateにしてから新しい系列を測る）を受けて、Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9に対応させた。この記録ではbundleを作成しない。

## 目的と役割

- 系列：汎用指示の改善系列のうち、[実行環境を切り離した新しい評価系列](agent-runtime-venv-isolation-record-r1.md)（`shell_environment.revision: fixed-path-workspace-venv-r1`）。C301は、この系列の基準として測る。
- 直接の親：C280（`the-caption-3ce91a4-execution-control-outcome-binding-r1`）。
- 位置づけ：制御を追加、変更、削除しない。C280のrootの`AGENTS.md`だけが、同じbundleの他の`AGENTS.md`（`docs/`、`scripts/`、`src/`、`tests/`）と違う書式で書かれているため、文字を変えずに書式だけを揃える。設計原則のとおり、文面が整ったことを改善の根拠にしない。
- 今後：この系列で測るCandidate（C298、C299、C300に相当するものを含む）は、C301の書式を親とする。

## 1. 比較の基準と、正常な最短経路

- 基準：新しい系列には保存済みの結果がないため、C301自身がこの系列の基準になる。C280の保存済みの結果（旧系列）とは比較しない。
- 正常な最短経路：C280と同じ。

## 2. 保存traceで確認した問題経路

- 保存traceで確認した失敗機序はない。この変更は、利用者の指示による書式の統一という一つの再構成目的だけを扱う。
- 書式の違い（C280のrootの`AGENTS.md`）：
  - 見出しが`###`（他の`AGENTS.md`は`#`）。
  - 第1項が箇条書きでない段落で、残りの3項目は`*`の箇条書き（他は`-`）。
  - 第2項と第3項に太字（`**`）がある（他の`AGENTS.md`には強調がない）。

## 3. 開いている記述と、TaskSpec・正本で防げない理由

閉じる経路はない。書式は、TaskSpecやリポジトリ上の正本では揃えられず、bundle本文を変える必要がある。

## 4. 変更の全件

root `AGENTS.md`だけを、次のとおり変える。他の18対象はC280とバイト一致を保つ。

1. 見出し`### 実行制御`を`# 実行制御`にする。
2. 第1項の段落を、`- `で始まる箇条書きの項目にし、後続の3項目と同じ一つの箇条書きにする（間の空行を除く）。
3. 箇条書きの記号`* `を`- `にする。
4. 太字の記号`**`を除く（`必要な成果 / 対象 / 実施方法 / 維持する条件`と`担当 / 判定対象 / 必要な結果`）。

文の文字、順序、項目の数は変えない。Markdownの記号と空白を除いた文字列がC280と一致することを、機械的に確かめた。全文は1,459バイト（C280は1,470）。

## 5. 禁止行動、開放経路、閉じる境界、反証

- 制御文の追加、変更、削除はない。四つの項目の禁止と限定の範囲はC280と同じである。
- 新しい操作の発行を求める文はない。
- 太字を除くことで、第2項と第3項の列挙の強調がなくなる。強調は許可の境界を定めていないため、境界は変わらない。ただし、モデルの読み方が変わる可能性はあり、新しい系列の基準として、その影響を含めて測る。

## 6. 維持する正常経路

C280と同じ。

## 7. 新しく増える判断と、変更対象外への影響

- 新しい判断、参照、例外はない。
- 固定分：11バイト減る。
- 第1項が箇条書きになることと、太字を除くことで、項目の間の相対的な重みが変わりうる。旧系列のC280との差としては測らない（実行環境が違うため）。

## 8. 評価ケース、比較単位、比較条件

- セル：Sol LowとSonnet low、各Standard14の全14ケース各N=5の計70件。
- 比較条件：[新しい系列のプロファイル](agent-runtime-venv-isolation-record-r1.md#4-計測の条件と系列)のうち、prompt identityだけをC301にしたもの。C280のプロファイルの条件（`shell_environment`を含む）をそのまま使う。
- 判定：この系列の基準として、品質（全件の`quality_score`）と3 KPIを記録する。比較の相手はなく、改善や悪化を判定しない。
- 診断（合否にしない）：A02でテストの確認を成功させてから報告したか、各runの`shell-environment/receipt.json`の`ok`。

## 9. 停止条件

- 発行前の確認（実行環境の記録を含む）が通らなければ、一件も発行しない。
- invalid、採点不能は基準として扱わない。外部失敗だけ、同じ枠で固定上限内に再試行する。有効な4点未満は削除、相殺、再実行しない。
- 各セル70件で記録し、自動で追加反復しない。結果に合わせてこの記録と案文を書き換えない。

## 判断の限界

- 書式の統一が品質やコストを良くするとは主張しない。
