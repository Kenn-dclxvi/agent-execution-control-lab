# Candidate300 Sonnet lowの累積N=20への延長

2026-10-09。利用者の依頼（C300の回数を増やして様子を見る。試験はSonnet lowだけで、N=20）を受けて、[再現性の判断方針](reproducibility-decision-policy.md)に従い、発行前に固定する延長の記録。プロンプトは変えず、[C300の設計記録](candidate300-c298-c299-combined-design.md)と[C300のN=5の結果](../evaluations/results/c300-sol61-low-sonnet55-low-standard14-n5_2026-10-09.md)を前提とする。

## 観測する対象

- Sonnet lowで、C300の全エージェントトークンの1反復（14ケース合算）あたりの値の分布。N=5では中央値がC280比+2.07%で、反復5のF03の1件（保存された155KBの出力を6回に分けて読んだ、352,289トークン）と、反復1の広い上振れが目立った。この上振れが、どのくらいの頻度で起きるかを見る。
- 診断として、保存された必須コマンドの出力をファイルから読み直す応答の数と、成功後の確認だけの応答の数。

## 開始時の累積Nと追加の上限

- 開始時：C300 Sonnet lowの有効N=5（result `5f515aa613cc47f5bd1890121f345c2c`）。
- 追加：各ケース15件（14ケースで210件）。累積N=20で止め、自動で50へ延長しない。
- Sol Lowは追加しない。

## 発行のしかた

- 反復回数は互換条件（`repetition_condition.iterations`）に含まれるため、反復20回の新しいプロファイルにすると、C280とC300のN=5の結果と互換キーが変わり、比較できなくなる。
- そこで、C300のN=5と同じプロファイル（`c300-claude-sonnet55-low-standard14-n5-cli2288-r1`、反復5回）と同じテンプレートで、5反復の試験を3回、別のcycleとして発行する（`c300-b2`、`c300-b3`、`c300-b4`）。それぞれを、C280と同じ互換キーの登録結果として記録する。
- 3回の試験は、b2、b3、b4の順に発行する（各試験70件、並列上限24）。3回を同時に発行すると同時実行が72件になり、固定した並列上限を超えるためである（発行前に訂正）。
- 発行前に、プロファイルの内容がC300のN=5のものと一致すること、評価コードのSHA-256、Claude Codeの実行ファイル、設定の隔離、実起動の照合を、C300のN=5と同じ方法で確かめ、preflight receiptを保存する。不一致があれば一件も発行しない。

## 判定の条件

- 品質：有効な4点未満を、削除、相殺、再実行しない。
- 主な値：累積20反復の、1反復あたりの合算トークンの中央値。比較は、保存済みのC280 Sonnet low（N=5、中央値832,616、反復の範囲797,727〜930,027）と行う。C280はN=5のままであり、基準側の分布の推定は粗い。この非対称を判断の限界として記録する。
- 判断のしかた：
  - 累積20反復の中央値がC280の中央値以下なら、N=5で見えた増加は反復間の揺れによるものと扱う。
  - C280の中央値を上回るなら、C300のSonnet lowでのコスト退行が続いていると扱う。
  - どちらの場合も、反復ごとの合算値の範囲と、上振れの反復の内訳（保存された出力の読み直しなど）を記録する。
- 経過時間は、計測の時間帯の影響と区別できないため、参考として記録する。

## 停止条件

- 互換条件の不一致、未確認があれば、一件目の発行前に停止する。
- invalid、採点不能は有効な結果として扱わない。外部失敗だけ、同じ枠で固定上限内に再試行する。
- 累積20で判断し、結果に合わせてこの記録を書き換えない。C280のSonnet lowをN=20へ延ばすかは、別の判断とする。

## 判断の限界

- 基準のC280はN=5であり、C300の累積20との比較は非対称である。
- 3回の追加試験は、C300のN=5とは別の時刻に発行するため、経過時間とトークンの一部に時間帯の影響が入りうる。
- この記録は採用、release、本体反映を決めない。
