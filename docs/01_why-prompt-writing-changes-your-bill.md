# AIへの指示は、短いほど安いのか？

> 実務者向けExecution Controlシリーズ 1 / 8（2026-10-12改版）

いきなり結論です。

**AIへの指示を0バイトから6行（1,687バイト）に増やしたら、試した4つのAIすべてでAPI料金換算が下がりました。下がり幅は11〜33%です。**

「いやいや、プロンプトを増やしたら、そのぶん料金も上がるでしょ？」

普通はそう思いますよね。でも、実際に測ったら逆でした。

同じAIに、同じ14個の課題を、同じ条件で5回ずつやらせています。違うのは、リポジトリのいちばん上に置く指示ファイル（`AGENTS.md`）だけです。中身が空のFree版と、最新版（C316）を比べました。

結果がこちらです。金額は14課題1セットあたりの中央値です。

| AI | Free（空） | 最新版（6行） | Free比 | 満点だった実行（Free → 最新版） |
| --- | ---: | ---: | ---: | ---: |
| GPT-6.1 Sol Low | $0.93 | **$0.64** | **31%減** | 69 → **70 / 70件** |
| GPT-6 Astra Low | $6.15 | **$4.12** | **33%減** | 68 → **70 / 70件** |

どうでしょう。

**4つのAIすべてで料金が下がり、品質は全部が70戦全勝になりました。**

1,000セット回すと、Sol Lowでは約`$934`が`$642`に、Astra Lowでは約`$6,148`が`$4,123`になります。差額はそれぞれ約`$292`と約`$2,025`です。

## なんで安くなったの？

ポイントは、AIがお金を使うのは、最初にプロンプトを読むときだけじゃないということです。

AIは作業中、ファイルを読んだりコマンドを実行したりするたびに、それまでの会話全体と新しく受け取った結果をまとめて読み直します。2回目以降に読み直す部分はキャッシュで安くなりますが、**新しく受け取ったファイルの中身やコマンドの出力は、そのつど通常の単価で数えられます。**GPT-6.1 Solでは、通常の入力はキャッシュから読む入力の20倍の単価です。

つまり、本当にお金がかかるのは、AIが余計に動いたり、受け取らなくていいものまで受け取ったりするときです。

- 「どのファイルを見ればいいんだ？」と探し回る
- 「念のため」と余計な調査を始める
- 誰が作業するのかを何度も考え直す
- 終わっているのに確認や検証を繰り返す

こういうことをするたびに、トークンが使われます。**AIが迷っているあいだも、料金メーターは回り続けるんです。**

Sol Lowで、14課題1セットあたりの中身を比べると、違いがよく見えます。

|  | Free（空） | 最新版（6行） |
| --- | ---: | ---: |
| ツールの呼び出し | 80回 | 58回 |
| 受け取ったファイルの中身やコマンドの出力 | 約526KB | 約287KB |
| そのうち通常の単価で数えた入力の料金 | $0.59 | $0.39 |

指示ファイルは1,687バイト増えました。でも、作業中に受け取る量が約240KB減ったので、全体では安くなっています。

## 6行で、何を止めたのか

最新版の6行は、次の無駄をそれぞれ止めています。

1. **やることが決まっていないのに作業を始める。** 「何をどうすればいいか」が依頼から決まらないのに、推測で編集やテストを始めてしまう。Free版の満点でなかった実行は、どのAIでもこれでした。
2. **念のための調査。** 方針が決まった後に、探索や再確認を足してしまう。
3. **終わった後の確認のやり直し。** 最後の確認と作業ツリーの状態の確認を同じタイミングで行い、全部成功していれば、それ以上コマンドを出さずに報告させます。
4. **短い間隔での様子見。** コマンドの終了を待つ時間を短く指定して、何度も様子を見に行く。
5. **確認コマンドの出力を全部受け取る。** テストの結果は、成功か失敗か（終了コード）と、判断に必要な部分（末尾など）だけを受け取らせます。
6. **長いファイルを丸ごと読む。** ファイルの本文は、判断に必要な範囲だけを受け取る形で読ませます。この1行を足した版では、その前の版と比べて、Sol Lowでは300行を超えるファイルを丸ごと読む回数が16回から0回になり、受け取る量が27%減って、料金が約10%下がりました。

下がり幅は、Codexで動く2つのAI（Sol、Astra）で大きく、Claude Codeの2つのAI（Sonnet、Opus）では小さくなりました。

## 前回の版から分かったこと

この記事の前の版では、約1万バイトの指示で、料金が約4割下がったと紹介していました（いまとは測定の条件が違うので、数値は直接比べません）。その後、項目を一つずつ外したり足したりして測り直し、効果が見えなかった項目や、この試験では使われない項目を削って、6行まで減らしました。

測り直して分かったことが3つあります。

- **長さではなく、何を止めるかです。** 効く項目は、AIの実際の作業記録を見て、どこで無駄が出ているかから決めました。効果が見えなかった項目は、外しても料金や品質が変わりませんでした。
- **「するな」より、「こういう形でやる」と書くほうが効きました。** 「1回で300行を超えて読まない」と禁止の形で書いたときは、小さなファイルまで細かく分けて読むようになり、料金ははっきりとは下がりませんでした。「判断に必要な範囲だけを受け取る形で読む」と、させたい形を書いたら、料金が下がりました。
- **回数より量です。** 最新版では、ファイルを読む回数はむしろ増えました。範囲を指定して小分けに読むようになったからです。それでも、受け取る量が減ったので安くなりました。

## これだけ覚えてください

**プロンプトをケチると、AIが勝手に残業します。**

削るべきなのは文字数じゃありません。AIが迷う余地と、受け取らなくていい出力です。

良いプロンプトは、長いから安いわけではありません。AIの無駄足を止めるから安いんです。今回の条件では、たった6行で、API料金が11〜33%下がりました。

では、AIに判断をやり直させないために、実際に何を書けばいいのか。続きは[「API料金を下げるプロンプトには、判断条件を書く」](02_how-to-write-prompts-that-cut-api-cost.md)にまとめています。

なお、金額は保存済みのトークン数（キャッシュを使わない入力、キャッシュから読んだ入力、キャッシュへの書き込み、出力）に各AIのAPI単価を掛けた換算値で、実際の請求額ではありません。数値は14課題を5回ずつ実行した中央値です。Codexで動く2つのAIでは、計測の始めにキャッシュが効かない実行が出ることがあり、その分も含めた実測のままです。Sol LowとSonnet lowは20回ずつまで測っても、全件満点で、料金もほぼ同じでした。別のリポジトリやAIでも同じ削減率になるとは限りません。測定の詳細は[計測の記録](../evaluations/results/free-c316-four-models-standard14-n5_2026-10-12.md)にあります。

すぐに無駄を減らしたい人は、[「AIプロンプトに書かなくてよかった7つのこと」](03_what-not-to-write-in-ai-prompts.md)から読んでも構いません。
