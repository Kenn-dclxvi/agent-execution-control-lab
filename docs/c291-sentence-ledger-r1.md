# C291のルートの指示ファイルの文ごとの台帳（r1）

2026-10-08。[C291の改善の検討記録](c291-improvement-review-r1.md)の案1（ルートの指示ファイルの文面を縮める）について、Candidateを作る前に、文ごとの対応を確かめた記録。[設計原則](prompt-control-design-principles.md)の「Candidateを作成する前の確認事項」の4〜7を埋めることが目的である。Candidateは作成していない。

## 結論

- C291のルートの指示ファイル（5,828バイト）は、41の文でできている。各文を、導入した段階、閉じる経路、Sol LowとClaudeでの観測へ対応づけた。
- **意味を保ったまま縮める案は、削れるのが141バイト（Opus lowの1反復あたり約2,600トークン、C280の合計の0.37%）で、Candidateにする価値がない。** 現在の文面は、すでに切り詰められている。
- **規則そのものを削る案は、Sol Lowで効果が確かめられている規則を、Claudeの観測だけで外すことになる。** 範囲の三文（S8〜S10）はSol Lowで外部の読み取りを9件から0件にし、検証の十文（S33〜S42）はC284でSol Lowのトークンを25.79%減らした。この二群はClaudeでは狙う行動が変わっていないが、外すと、Sol Lowで閉じた経路が再び開く。
- したがって、案1は、文面の編集ではCandidateにならない。C291のClaude lowでの増加の大半（固定コストの約82,000トークン）は、Sol Lowの削減に必要な規則が、全モデル共通の本文に入っていることの代価である。残る選択は、本文をモデル別に分けるか、この代価を受け入れるかであり、利用者の判断が必要である。

## 方法

- 文の分け方：C291のルートの指示ファイルを、箇条書きの項目ごとに、句点（「。」）で文に分けた。丸括弧の中の句点で割れた2片は1文に戻した（S17〜S18）。見出しと記号を除いた文の合計は5,708バイトで、ファイル全体（5,828バイト）との差は見出しの120バイトである。
- 導入した段階：C280、C284、C285、C288、C289、C290、C291の各ルートの指示ファイルを文に分け、現在の文面と完全に一致する文が最初に現れた段階を機械的に求めた。文面が途中で改稿された文は、改稿した段階になる。
- 閉じる経路：各段階の設計記録（[C284](candidate284-validation-single-call-design.md)、[C285](candidate285-repository-read-scope-design.md)、[C288](candidate288-scoped-read-batch-design.md)、[C289](candidate289-scoped-first-return-design.md)、[C290・C291](candidate290-candidate291-root-instruction-validation-exit-design.md)）の「閉じる境界」から引いた。
- Claudeでの観測：Opus、Sonnet、Haikuのlow（C280とC291、各70件。変更を伴わない15件を除く55件を使う指標あり）の保存transcriptのコマンドから、規則が狙う行動を数えた。コマンドの文字列で判定する簡易な指標であり、完全な証明ではない。
- Sol Lowでの観測：各段階の結果の記録にあるトークンと経過時間の中央値の変化と、記録された経路の診断を使った。文ごとのSol Lowの行動指標は、新たに数えていない。
- 固定コスト：増えたバイト数×0.3247トークン/バイト（C280→C291の実測比）×57.8リクエスト（Opus lowの1反復）で見積もった。1バイトあたり約18.8トークン/反復にあたる。

## 利用者の判断が必要な点

C291のClaude lowの増加の大半は、Sol Lowの削減に必要な規則が全モデル共通の本文に入っていることの代価である。

1. **本文をモデル別に分ける。** Claude Codeが読む`CLAUDE.md`と、Codexが読む`AGENTS.md`を別の本文にする。Claudeでは行動が変わっていない二群（範囲S8〜S10、検証S33〜S42、計1,623バイト）を外せば、固定コストで1反復あたり約30,000トークン（C291−C280の増加の約24%）を省ける見込みである。ただし、C288の設計記録は「モデル別の本文を作らず、SolとOpusへ同じ指示を出し、Markdownを統一」と定めており、同じリポジトリを複数の実行環境で使う前提と、この系列の方針に反する。
2. **この代価を受け入れる。** Sol Lowの−36.3%と、Claude lowの+2〜30%を、共通の本文の結果として記録し、系列を閉じる。
3. **Claude側の別の経路を探す。** 案2（指示ファイルの存在確認の依存）は、因果が未測定のまま保留している。

## 限界

- Claudeの指標は、コマンドの文字列による簡易な判定である。N=5の計測で、モデルも3種類混ざる。
- Sol Lowの文ごとの行動指標は、新たに数えていない。群ごとの効果は、段階ごとの結果の変化をもとにしており、群の間で分けられていない場合がある（開始時の読み取りと範囲限定の取得など）。
- 固定コストの見積もりは、C280→C291の実測比を使った推定である。
- この記録は採用、release、本体反映を決めない。
