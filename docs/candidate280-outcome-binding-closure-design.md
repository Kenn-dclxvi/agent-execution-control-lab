## 目的と対象

Claude Code Opus 5.5のStandard14でC276に残った誤経路を、プロンプトの許可範囲から閉じる。誤経路とは、利用者が決めていない結果を補い、確認を返す前に変更やテストへ進むことである。Candidate identityは`the-caption-3ce91a4-execution-control-outcome-binding-r1`（Candidate280）とする。直接の親はC276 `the-caption-3ce91a4-execution-control-r1`（bundle SHA-256 `4d2dcd4f34749b32155139138654cbc2bb33b78fc6841ba6eb14d29c8f7a678f`）であり、root `AGENTS.md`の1項目だけを置き換える。

利用者の依頼により、変更文は特定ケースの対策ではなく汎用の規則とする。THE-CAPTIONの実務は、リポジトリを開いて対話で直接指示する形で行われる。そのため、評価用TaskSpecの項目名、ケースID、modeの値、ファイル名、採点条件をプロンプトへ書かない。

## Candidate作成前の確認事項

基準はC276とControl-Freeである。結果が依頼に示されている作業では、C276の正常経路をそのまま保つ。必要な成果、対象、実施方法、維持する条件を一つの方針にまとめ、不足する情報だけを調べ、変更と検証を終える。結果が示されていない作業の最短経路は、依頼の確認と、依頼が求める事前確認を行い、未確定の結果だけを確認して終えることである。

### 3. 問題経路を許している記述

C276の第1項には次の二つの欠落がある。

- 「既存状態・過去の例・周辺情報から勝手に推測せず」は、何が推測にあたるかの判定をモデルに任せている。C276の失敗runは、候補を消去法で一つに絞ることを推測とは扱わなかった。
- 結果が未確定の間にしてよい操作が限定されていない。後半の「利用可能な情報や環境を確認し」は、調査やテストを広く許す。Freeの失敗runと同じ、テストを先に行う経路も開いたままである。

TaskSpecは「現在挙動を確認」とテスト許可を与えている。そのため、TaskSpec、リポジトリの正本、リポジトリの現在状態だけでは、確認前のテストと変更を防げない。この経路はControl-FreeとSol・Astraの過去の診断でも観測されている（[原因分析](astra-latent-mode-continuation-cause-audit-r2.md)）。

### 4. 変更する条件

C276 `files/AGENTS.md.txt`の第1項（3行目）だけを次の文に置き換える。見出し、空行、他の3項目、配下ファイルはbyte一致させる。

> ユーザーが求める結果（作業後にどうなっているべきか）は、ユーザーが示した内容と、それが従うよう求めている指示や正本が直接定めている内容だけで決まる。既存の状態、候補を消去法で一つに絞れること、過去の例、テストの期待値、実装上の都合は、結果を決める根拠にならない。結果が決まっていない間は、依頼内容の確認と依頼で指定された事前確認だけを行い、調査・変更・テストやその他の操作を始めず、決まっていない結果だけを確認して終える。対象の場所や具体的な実施方法が未確認なだけなら、利用可能な情報や環境を確認し、自分で決めて進める。

結果が決まっているかどうかは、利用者の入力と、すでに適用されている指示に書かれているかどうかで判定できる。結果を決められない根拠の列挙は、モデルが結果を補うときに使える材料を明示的に除くために置く。

### 5. 実行できなくなる問題経路

- 結果が未確定の間は、テストと変更が許可範囲の外になる。モデルが判断の順序を変えても、確認前のテストや試し変更は規則に違反しないと実行できない。
- 現在値、候補の残り、テストの期待値では結果が決まらないため、未確定の結果を「決まった」と分類し直して変更許可を得る経路がなくなる。
- 結果を決めるための調査も未確定の間は始められない。調査結果から結果を補うという依存関係がなくなる。

### 6. 維持する正常経路と情報の受け渡し

- 結果を決める情報は、利用者の入力と、すでに適用されている指示が持つ。どちらもモデルが最初から受け取っており、追加の読み取りなしで届く。
- 実装先や手段だけが未確定な作業（例: 壊れた起動経路を、リポジトリの正本に従って直す作業）では、最後の文によって調査し、自分で決めて進める経路を保つ。
- 依頼が求める事前確認（開始状態の確認など）は、結果が未確定でも実行できる。
- 読み取りだけのレビュー、範囲外の依頼の停止、確認だけを求める依頼は、結果が依頼に書かれているので変化しない。

### 7. 新しく増える判断と、変更対象外への影響

増える判断は「結果が依頼または適用中の指示に書かれているか」の一つである。結果が明示されたケースで、モデルが結果を未確定と誤って分類して停止すれば、品質が下がる。特に、正規の対象をリポジトリから決めるケースと、正本に従った同期のケースで、新しい停止や確認が起きていないかを診断する。
