# STD14専用評価の計画に対する規則の影響調査 第1版

2026年10月4日。結論は、**規則の適用範囲の曖昧さと古い工程限定指示が進め方を混乱させる要因になっている。一方、規則が今回の繰り返しを命じているわけではなく、私の適用判断にも問題がある**。規則を緩めれば現在の結果を同等代替と認定できる、という結論ではない。

対象はこの作業領域で適用されるルート・docs・evaluations・targets・専用ターゲットのAGENTS、比較の正本、元計画と工程7・8の記録である。目的は計画を拘束している条件の出所と適用先を特定すること。規則そのものは変更せず、[全体計画第2版](standard14-dedicated-evaluation-plan-r2.md)に適用区分を反映した。新しい評価・素材実装・外部変更は行わない。

## 1. プロンプト比較と素材移植の比較が、規則の文面では区別しきれていない

[ルートAGENTS](../AGENTS.md)39行は、保存済み結果を基準にする比較について「宣言したprompt identity以外の互換条件が完全一致」と定める。一方、同27行の `PROMPT_ONLY_COMPARISON` は「同一のprompt改善系列」を対象とし、[evaluations/AGENTS](../evaluations/AGENTS.md)120行も「プロンプト比較では」と限定している。

[元計画](standard14-dedicated-evaluation-plan-r1.md)45〜47行は、旧新のfixture、Git identity、実装量、検査集合が異なることを明示し、素材移植の別系列として、同じ実行プールへ入れずに要求と動作の対応を比較すると定めている。今回の利用者要求も、全14ケースを保った低コストな別素材の作成である。

したがって「素材が違うからプロンプト比較の互換条件を満たさない」は当然であり、それ自体を素材代替の不成立理由にしてはいけない。旧新を同じプールへ混ぜない規則は維持し、専用系列内のプロンプト比較に完全一致を適用する。素材対応では、変える素材と保持する意味・環境を先に宣言し、保持すべき側の未宣言差を拒否する。

ただし、差を宣言しただけでは同等性の証明にならない。開始記録の事前宣言と実物の矛盾、判断材料として使われた履歴の差は、個別に説明が必要である。過去の発行前証明を追認しない判断も維持する。

**判定：文面上の適用範囲に曖昧さがある。工程7の「完全な比較互換性」という表現も、同じプールへの互換と素材の意味対応を混同させた。規則の一般化しすぎを計画側で是正する。**

## 2. Git内部を除く素材固定と、履歴を使う課題の間に確認範囲のずれがある

[比較手順の正本](prompt-comparison-workflow.md)80行では、fixture identityを「`.git`内部を除く」path・type・mode・content・symlinkから計算する。これは開始treeの固定に使えるが、それだけで、履歴、直接の親、branch状態が意味上対応した証明にはならない。

元計画は必要なseed・親・開始identityを保持する一方、それ以外の履歴削減を認めていた。工程7までの記録では、祖先関係を確認した後に、直接親、空seed、branch差を追加で調べている。現在treeのhashと履歴の意味対応を別の証拠として先に設計していなかったことが、確認項目が後から増えた具体的な要因である。

**判定：固定処理の不具合を実証したものではなく、今回の素材対応に必要な確認範囲の設計漏れ。hash検査を繰り返すのではなく、課題に必要な履歴関係だけを事前の対応表へ含める。**

## 3. 工程限定の禁止が常設指示に残っている

[専用ターゲットAGENTS](../evaluations/targets/standard14-dedicated-control/AGENTS.md)9行には「新系列のモデル発行は今回0件」「admission-r1.jsonのready=falseを局所検証からtrueへ変更しない」とある。工程2の実装・局所検証には適切だが、「今回」の対象時点が明示されず、後の測定計画と並存している。

これは、新しいチャットが局所検証だけで測定を始めないための境界としては有効である。しかし、後続の明示された測定依頼まで恒久的に禁止する根拠へ拡張してはいけない。利用者の明示指示を優先し、過去のadmission記録は上書きしない。

現在の追加モデル実行禁止とLow不再発行は、今回の引き継ぎ依頼にも明記されている。そのため、古いAGENTSの記述を削除すれば今すぐ再測定できる、という状態ではない。また、禁止されているのは評価モデルの追加実行であり、保存証拠の調査や比較設計まで禁止されてはいない。

**判定：古い工程指示は混乱要因。現在の追加測定禁止の直接根拠は利用者の今回の制約にもある。出所を混同しない。**

## 4. 別版保存と索引の規則は文書を増やすが、再審査を要求しない

[ルートAGENTS](../AGENTS.md)49〜50行、[docs/AGENTS](AGENTS.md)34〜38行、[evaluations/AGENTS](../evaluations/AGENTS.md)136〜141行は、固定版・結果をその場で上書きせず、新しい判断を別記録にする。これにより、修正のたびにファイルと索引更新が増える。

ただし、規則が要求するのは履歴の保持であり、各文書を新しい独立工程にすることや、受入済み箇所を再審査することではない。docsの索引は「現在の計画一つ」と「当時の固定成果」を分ければよい。完了した報告を現行の作業指示として並べ続ける必要もない。

**判定：記録負担への影響はある。繰り返しの必然的原因ではなく、私が局所結果ごとに次工程を増やした計画運用の問題。**

## 5. 続ける規則だけを強く読み、繰り返さない規則を弱く適用していた

ルート17行と[設計原則](prompt-control-design-principles.md)は、目的を縮小せず、成立しない案は別の境界へ分解して検討を続ける。一方、設計原則70〜71行は不要な再読と無関係な判断の失効を避け、85〜87行は停止効果の局所化と、検証終了後の追加確認を制限する。

前者を「未証明がある限り、何か次の確認を発行する」と読むと、完了済みの証拠を増やし続ける。必要なのは、その操作が未完了要件を直接満たせる場合だけ続けることである。今回、履歴を直しても新版の実測を取得できないという条件を先に扱わず、工程8へ接続したのは私の判断の問題だった。

ただし、追加測定禁止を理由に、計画見直しや今回の規則調査まで止めるのも誤りである。目的未達を明記したまま、現在許可された設計・調査は完了できる。

**判定：反復を義務づける規則ではない。停止範囲と派生作業の必要性を、私が適切に限定できていなかった。**

## 6. 作業モデルの切替と修正粒度

Sol Mediumによる実装、Astra Highによる最終確認は、汎用AGENTSから要求されたものではなく、元計画で選ばれた担当方法である。モデル変更時に別チャットへ切り替えることは、その後の利用者指定である。この指定は保持する。

一方、各小さな確認ごとにモデルを往復させる義務はない。ルート46行は「一つの変更で一つのアーティファクト単位」とするが、docsとdescriptorは対象外で、Gitのcommit・branch・PRの粒度規定でもない。関連する開始構成を一つの固定版へまとめ、変更範囲を一回受入することを禁止してはいない。

**判定：切替には作業負担があるが、今回の細分化は必須ではない。今後は意味上つながった変更を一つの受入単位へまとめる。**

## 7. 評価対象が読む指示と、この作業を拘束する指示は別

専用ターゲットAGENTSの6行は、`fixture/base/`のAGENTSを測定素材とし、この作業の権限指示ではないと明記している。設計文書・採点・今回のチャットを測定対象へ配送しない境界もある。今回の作業用ルールが、そのまま評価対象モデルへ配送されたとする証拠は本調査では得ていない。

これとは別に、旧側のモデルが過去rootの削除を開始判断に使ったことは[保存応答と開始出力](../evaluations/targets/standard14-dedicated-control/registrations/stage7-history-semantics-evidence-r1.json)に結ばれている。これは課題中の判断材料の影響であり、現在有効な作業用AGENTSが停止を命令したこととは違う。両者を「リポジトリ指示のせい」とまとめない。

## 今回の反映と、規則本文に必要な整理

今回、AGENTSや評価基盤の正本は変更しない。調査依頼に対して、広範な比較規則の変更まで暗黙に行う必要はない。改訂計画では次を明記した。

- プロンプト効果の比較と、利用者が指定した素材代替の対応検証を分離する。
- 素材対応を同一プールへ登録せず、許容する素材差と、保持必須の意味・環境の不一致を分ける。
- 古い工程限定の禁止、現在の利用者制約、私が作った設計上の条件を区別する。
- 追加測定禁止を計画・調査の停止条件へ広げない。
- 確認済み成果は再審査せず、工程8の自動実装を取り下げる。

規則本文を今後整理する場合の変更対象は、ルート39行の適用範囲をプロンプト比較として明示すること、別インスタンスを同じプールへ混ぜない規則と素材対応研究の区別を明記すること、専用ターゲット9行の「今回」を工程2の期限付き条件へ限定することである。未宣言差の禁止、事前証拠、旧結果の不変、個別結果の保持は削除しない。これは今回適用済みの規則改訂ではなく、調査から特定した修正候補である。

以上は文面と保存された進行記録による因果の整理であり、規則あり・なしのモデル比較試験ではない。個々の規則が何トークン・何分の増加を生んだかは測定していない。
