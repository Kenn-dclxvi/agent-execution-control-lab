# Candidate289 検索と限定本文の初回受領を一体化する

2026-10-08。Candidate本文の作成前に固定する設計記録。

## 目的と対象

C288を直接の親とし、読み取り対象の位置だけを最初の外側呼び出しで受け取り、次のモデル応答から本文取得を発行する経路を閉じる。必要な結果は、C288の一般ファイルの範囲限定を維持したまま、名指しされた対象の位置特定と該当する定義・節の本文取得を一つの外側呼び出しの結果へまとめるroot指示である。SolとOpusへ同じ本文を渡す。対象はroot `AGENTS.md`の読み取りに関する三項だけとし、他18対象、Markdown書式、成果・担当・検証に関する条件はC288からバイト一致で保持する。C288、C286および保存済み評価結果は改変しない。

## 保存記録で確認した経路

[C286・C288追加N=15の実行ログ監査](candidate288-candidate286-n20-log-behavior-audit-r1.md)では、C288のF03とF06で、最初の呼び出しが対象内の検索と指示取得、次が`sed`などによる範囲取得、三番目が変更となる例を確認した。C286では最初の呼び出しで名指しされたファイルの本文を取得し、次で変更する例が多かった。追加15件の平均で、F03・F06はC288の外側呼び出しが各1回、F10月次は約0.93回、F01は約0.94回増えた。変更前ツール結果量は減ったのに、これらのroot入力トークンは一件平均で約10,800〜19,300増えた。探索と本文取得の間でモデルへ結果を返すことが、保存済みの余分な依存辺である。

C288は「範囲が未確定なら対象内を検索して位置を特定する」とし、「先行結果によって対象・範囲が決まる読み取りは、その結果を受け取ってからまとめて発行する」としている。検索結果をいったんモデルへ返し、次の外側呼び出しで本文を読む経路を許している。TaskSpecやrepository authorityは必要な成果と情報源を定めるが、この返却時点を指定していない。C286の全文取得へ戻すと、F04・A02・F08でC288が減らした大きな出力が戻る。

## 閉じる境界と正常経路

| 禁止する行動 | C288で開いている経路 | 閉じる境界 | 残す正常操作 |
| --- | --- | --- | --- |
| rootが一般ファイルの位置検索だけを受け取り、本文取得を次のモデル応答へ送る | 検索結果を外側呼び出しの終端として返せる | 一般ファイル本文の位置検索を発行した場合は、検索とその一致箇所を含む定義・節の限定本文を、同じ外側呼び出しの結果へ含める | 検索一致なし、出力の欠落、読んだ範囲から直接参照先が初めて分かる場合の後続取得 |
| rootが限定取得を名目に実質的な全文を検索結果へ含める | `rg`などの検索が本文取得の範囲制限を迂回できる | 検索結果自体にもC288の本文取得範囲を適用する | 指示ファイル、明示された全文指定、定義・節が実際にファイル全体と一致する資料の取得 |

前者は一般ファイルの位置検索を発行する全ての場合へ適用し、必要性の自己分類やファイル長の閾値を導入しない。検索結果が一致しなければ本文は取得できないため、その結果を返す。必要な定義・節を一つのツール呼び出し内で特定できない場合でも、検索一致箇所と、その判断に直接関わる限定された周辺本文を同じ結果へ含める。足りない未取得部分だけを後続で読む。検索を禁止せず、検索と本文取得の間でモデルへ戻る依存辺を閉じる。

## 処理方法の適格性と反証

- 適用条件は、一般ファイルの本文位置検索を発行したという観測可能な操作の種類だけで決まる。成果未確定時の調査許可は増やさない。
- 保存rolloutの外側呼び出しの入出力から、検索結果だけの返却、同じ呼び出しでの限定本文の受領、取得範囲、後続の再取得を観測する。新しい指示の遵守率は未測定なので、静的な文面だけで制御成立を宣言しない。
- 一つの呼び出しの内部で位置検索と限定本文の取得を続けられる。検索の結果が空、出力が切り詰められた、直接参照先が初めて判明した場合の合法な後続取得と、変更後の検証を維持する。リポジトリ外の実行器やツールを変更しない。
- 特定のコマンド、case ID、固定行数、モデル名を本文へ入れない。実行時の例としては検索結果に限定した周辺本文を含める、または同じ外側呼び出しの内部で対象の定義・節を取得する方法があるが、特定手順の成功を義務へ転記しない。
- 反証は、本文が必要な対象で検索位置だけを返すrun、検索により実質的な全文を返すrun、正常終了に必要な本文が届かないrunである。`rg`を使ったという事実だけでは遵守と数えない。

## 評価と停止条件

同一のStandard14と固定Layer 1を使い、まずF03、F06、F10月次、F01の追加往復が消えるか、F04・A02・F08の大きな取得量削減と品質が保たれるかを確認する。C288の保存済み互換結果を比較基準とし、評価前にprompt identity以外の互換条件を機械照合する。全14ケースへ拡張する場合はscore、全エージェントトークン、経過時間を比較し、ケース別の増減を保持する。品質低下、比較条件不一致、invalidまたは採点不能を有効な改善として扱わない。遵守率は3 KPIを置き換えない。採用、release、本体反映は別判断とする。
