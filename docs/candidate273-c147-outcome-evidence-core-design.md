# Candidate273: C147の成果確定・探索制限を中心に残す再構成

## 目的と位置づけ

利用者の「C147から、『推測して進む』『周辺を広く探索する』自由度を閉じる部分を中心に残したCandidateを作成する」という依頼を成果条件とする。対象はC147と同じ`the-caption`改善系列であり、一般チャットやレビュー専用系列への移動はしない。直接の親と制御原文は`the-caption-3ce91a4-result-effect-scope-r1`（C147）。C144の失敗は再び開いてはいけない探索経路の証拠であり、親にはしない。

一つの再構成目的は、要求成果と必要証拠の境界を残し、実行者の細かな管理と実行順の最適化を外すことである。文章の短さやモデルの動作の一致自体を成果にしない。SolとAstraの差の縮小という会話上の説明は設計動機であり、本Candidateによる再現を確認した事実として記載しない。

状態は`design_complete / not_evaluated`。作成、整合確認を本作業の範囲とし、評価実行、採用、release、本体反映は行わない。

## 本作業の実行仕様

実行者は全操作でrootとする。判断基準の所有者は利用者要求と適用中のリポジトリ指示である。

| 操作 | 成果条件と合格条件 | 許可と保持条件 |
| --- | --- | --- |
| 設計 | 原文、既存の具体的な問題経路、全条項の差分、正常経路、評価条件をこの文書へ固定する | C147、適用指示、形式の正本、指定した既存結果を参照する |
| 作成 | 新しい識別子で自己完結の完全バンドルを作り、索引から到達可能にする | rootの`AGENTS.md`だけを変更し、非rootの18対象、source identity、対象間関係を保持する |
| 整合確認 | バンドルのハッシュ、対象集合、差分、本文の条項集合、索引リンクを確認する | 新規バンドルと本作業の差分に限定し、既存の未コミット作業を保持する |

## 基準と最短正常経路

C147のbundle SHA-256は`51b0395d2a82b90e12b4d457d441c43a899577128cfa887c454618c9d2e0a5cc`。比較の出発点となる制御なし条件は`the-caption-3ce91a4-control-free-repository-r1`、本再構成の直接比較相手はC147とする。制御なし条件を新たに実行することは作成の前提にしない。

- 要求成果が未確定なら、その値だけを確認し、リポジトリから答えを推測しない。
- 成果が確定し実装方法だけが未確定なら、対象と適用指示・正本から全変更と保持関係を一つの実装方針へ結び付け、変更する。
- 必須検証の判断条件、順序、合格条件、停止条件を固定し、明示されたコマンドを守る。未指定の方法は受領済み情報から選び、必要な結果がそろえば完了する。
- 読み取りだけの依頼では、必要な未確認値を観測して結果を返す。別実行者が明示されている場合はその実行者の結果を使い、欠けた結果をrootが補わない。

必要な情報はTaskSpec、許可された対象、適用指示、正本から当該操作の実行者へ届く。作成する本文に外部componentへの参照は置かない。追加の読む権利を委任や検証の都合から作らず、全段階で同じ探索制限を適用する。

## 保存結果に結び付いた問題経路

[C143・C144の一次結果](../evaluations/results/candidate143-candidate144-required-outcome-validation-method-boundary-v14-medium-a01-a02-f01-f02-f04-f07-atomic-n5-cli0146_2026-08-02.md)のA02診断を使用する。生ログを新たに再解析したという意味ではなく、保存traceに対応づけられた既存の診断結果である。

- `c161f4c362fc425eaad440214703c417`では、変更対象を確定した後でREADME、entrypoint、関連testを再読してから変更した。
- `f695fa86e95f4d29af9800e0021afbfe`では、変更後に`tests/AGENTS.md`と既存routing testを読み、検証の実行票を確定した。必要な検証条件は既にあり、追加探索が方法選択のために開いていた。

TaskSpecの成果条件と正しい配置の指定だけでは、「もっと調べる」という呼び出し権限を閉じない。C147の`EVIDENCE_GATE`は、未完了・未観測の判断項目と欠けた観測値へ結び付かない取得を禁止し、この経路を閉じる。判断順を変えたり検証準備と呼び替えたりしても許可されない。

要求値の推測禁止は本依頼が残すよう指定したC147の既存効果であり、新しい失敗原因の推定から追加する条項ではない。A01の確認終了とA02の正本に基づく実装継続を組にして保持を評価する。成功runのコマンド順や読み取り回数は新しい義務へ転記しない。

## 条項の全件対応と依存関係

| C147の条項 | 操作 | 残す理由、削除する責務と影響 |
| --- | --- | --- |
| `SPEC` | 逐語保持 | 成果と方法を分け、未指定成果を現在値や候補から補う経路を閉じる。操作ごとの結果・制約の範囲を保つ |
| `PRODUCER` | 逐語保持 | `SPEC`と`TERMINAL`が参照する実行者を定義し、結果の帰属を保つ |
| `TERMINAL` | 逐語保持 | 必要な実行者の確定結果がそろうまで、推測や進捗報告で完了を補えない |
| `CONTEXT` | 削除 | 入力パケットの項目列挙、継承量の指定を外す。引き継ぐ情報量が増える可能性は評価で確認する |
| `EVIDENCE_GATE` | 逐語保持 | 全段階の探索許可、全変更・関係の実装確定、再探索の限定、結果失効の局所性を残す |
| `OWNER_ROLE` | 削除 | 起動時名称と返却者の詳細照合、固有の状態付与を外す。実行者指定と結果必要性は前記3条項が担う |
| `ROOT` | 削除 | rootの作業範囲の独立した再記述を外す。同一判断の再割当ては禁止されたままとする |
| `INDEPENDENCE` | 削除 | 先行成果に対する別操作の独立条項を外す。操作ごとの条件・実行者は`SPEC`と`PRODUCER`で定める |
| `DECISION_BOUNDARY` | 削除 | 影響する操作クラスの分類と同じmodel stepでの発行義務を外す。独立操作の待機が増える可能性がある |
| `VALIDATION_CLOSURE` | 削除 | 一回の外側実行、個別呼び出し、返却単位の指定を外す。必須検証を省略する許可は与えない |
| `VALIDATION_PLAN` | 限定保持 | 最初の2文と完了後の追加tool禁止文を逐語保持し、検証の判断条件・順序・合格条件・停止条件の固定を明記する。一括実行後の一回判断、cell ID待機専用化は削除する |
| `METHOD` | 逐語保持 | 許可内の方法選択を残し、方法未定を不要探索・誤停止へ変えない |
| `RECOVERY` | 削除 | 環境復旧の組とカウンタ消費の追加定義を外す。TaskSpecに指定された復旧上限・禁止は保持する |

最終本文は6条項とする。新しいラベル・例外・参照ファイルは追加しない。検証条件の固定文は削除する`VALIDATION_CLOSURE`の条件部分を日本語で移すもので、新しい制御ではない。

`SPEC`だけでは不要探索を閉じず、`EVIDENCE_GATE`だけでは何が要求成果か決められない。さらに実行者と確定結果の定義を全部消すと、両条項が使う参照が未定義になる。検証の実行票も探索を閉じた後に正常終了するため必要である。このため6条項を依存関係込みの一単位として残す。削除群はこの中心制御から実行管理を切り離す一つの再構成差分であり、個々の削除の効果を独立に実証したとは扱わない。

## 評価計画と停止条件

評価は未実行。既存の`the-caption-standard14-r1`、Rating v14を変更しない。最初はA01 r2・A02 r2・F01 r3・F02 r1・F04 r2・F07 dependency r1を各N=5とし、期待分布はScore 4が30件、Score 3以下が0件。これにより推測禁止、正本への到達、必須検証、複数変更・単一変更・依存関係を確認する。次にStandard14 N=5の残りを評価し、委任、読み取りのみ、復旧への影響を含め70件すべての品質を確認する。合格後の安定性確認は同条件でN=20、N=100へ進める計画とするが、本依頼では発行しない。

比較するC147 N=5の一次結果は[C147 N=100結果のWave表](../evaluations/results/candidate147-result-effect-scope-v14-medium-standard14-atomic-reuse-n100-cli0146_2026-08-02.md)に記載された`f7baeadc5bd44399ac13cc0e0a8aff48`とし、対象ケースの保存runを選択する。比較単位は同一ケース・同一N。基準のmodel、reasoning、CLI、Python、Layer 1、fixture、TaskSpec、rating、permission、実行挙動、token accounting、集計方法を再利用し、prompt identity以外の一致を実行前receiptで証明する。未確認・不一致なら一件も発行しない。

品質を維持し、同一単位の全エージェント`total_tokens`と`elapsed_seconds`の中央値がC147よりともに減少した場合だけコスト改善とする。許容増加幅は0。片方でも増加すればコスト退行、同値なら改善未確認とし、拡張を停止する。invalid、採点不能、互換条件不一致、Score 3以下でも停止する。探索再入、実行順、委任方法、読み取り数は原因診断に使い、独立した第4のKPIにしない。必要成果の欠落を示すときは品質判定へ反映する。

SolとAstraを同一の互換条件とは扱わない。モデル間の差の縮小を再確認する場合は、各モデル内でC147対本Candidateを比較し、モデル別の固定条件と基準resultを先に確定する別の実行準備が必要である。本設計はその結果を先取りしない。
