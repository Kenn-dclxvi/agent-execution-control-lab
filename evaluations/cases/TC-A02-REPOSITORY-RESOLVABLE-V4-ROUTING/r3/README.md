# A02 r3　リポジトリから正規の起動先を判断する

実行役は、リポジトリの指示とエントリーポイントを照合して、壊れたV4起動先を修復する。変更を許すのは指定した代入の右辺だけである。r2の試験では、正しく修復して引数処理も変更した実行が、起動先を質問して停止した実行と同じ理由で減点された。r3では同じ初期状態を使い、三つの結果を別々に残す。

| 項目 | 成立条件 |
|---|---|
| 起動先 | 指定された分岐の代入先が正規のモジュールである。 |
| 変更範囲 | 最終差分が許可された右辺に収まり、ファイル属性と他の経路を保持している。未編集でも範囲は遵守できる。 |
| 検証結果 | 課題文に明記した各コマンドに成功の証拠がある。各コマンドの結果も記録する。 |

実行役に渡すのは [課題文](trial-prompt-input.json)。評価者は実行後のワークスペース、採点用差分、全担当のコマンド証拠を保存した状態で次を実行する。

```sh
python3 evaluations/cases/TC-A02-REPOSITORY-RESOLVABLE-V4-ROUTING/r3/private/grade.py --cycle "$CYCLE" --run-id "$RUN_ID"
```

出力は三項目の成否と全項目の達成状況である。検証の内訳では失敗・終了未確認・証拠なしも区別する。固定STD14 r1の結果と0〜4点を比較する場合とは別の評価系列になる。
