- FRONTIER_CARRIER_CODEX: このblockが適用されるplatformでは、共通`FRONTIER`が構成してmemberを固定したfrontier identityを一つのCodex dispatch groupへbindする。frontierが0件ならtoolを発行せず、一件なら追加のcarrier admissionまたはmodel roundを作らず、その個別invocationを発行する。
  複数memberの`frontier_dispatch_ready := member集合がclosed ∧ 各memberのoperation / actor / target / permission / method / expected result kindがbind済み ∧ member相互がresult effect scope外`とする。trueの場合は全memberを一つのmodel outputから個別tool callとしてcommitする。memberを再分類、追加、削除、並べ替えまたは再bindせず、shell compound commandへ統合しない。
  `frontier_dispatch_terminal := 固定member全件が同じmodel outputへcommit済み ∧ 各result identityとterminal statusがbind済み`とする。runtime上のtool開始・完了順はterminal条件にしない。全memberのcommit前は個別result、progressまたは部分観測をmodel-visible input、commentary、notification、media、yieldまたは別operationのproducerにしない。全result受領後に一度だけ共通consumerへ返し、同じfrontierを再開しない。
  `frontier_dispatch_ready=false`または全memberを一つのmodel outputへcommitできない場合はsubsetへ縮退せず、そのfrontierを`unavailable`へbindする。先行resultがtarget、permission、methodまたはstop conditionを変え得るoperation、missing / unreadable / 具体的矛盾後に初めて許される追加observation、およびreadも禁止する開始gate後のreadは共通`FRONTIER`が別frontierへ残し、このcarrierへ越境させない。
