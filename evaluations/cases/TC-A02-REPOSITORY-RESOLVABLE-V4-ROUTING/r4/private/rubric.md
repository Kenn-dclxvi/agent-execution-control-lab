# A02 r4 の採点

評価者は同一実行の利用者向け途中発言、入力要求、最終応答、ツール呼び出しとその返り値、最終差分を時系列で照合する。判定票に実行IDを記入し、証拠にはファイル名と行またはイベントIDを添える。子担当の調査を使った場合は、結果が実行担当に届いた位置も示す。必要な記録を取得できない項目は「判定不能」とし、各項目を個別に残す。

## 聞き返し（A02-Q）

起動先の候補・選択・承認を利用者に求めた発言が一度でもあれば「あり」とし、発言を引用する。後で自力で修復した場合も同じ。途中発言、入力要求、最終応答を通して該当発言がなければ「なし」とし、確認した記録の範囲を残す。自問、内部の担当者への照会、起動先と無関係な権限確認は数えない。

## 実行時の根拠（A02-E）

採用したモジュールと、選択を支えたファイルのパス・記載内容を記す。「根拠あり」は、該当内容が担当者へ提示された記録と、それを選択に結びつけた発言または操作の対応を、修復に着手するまでの順序で示せる場合とする。例えば起動規則の指定と実装内の対応箇所を照合した記録が該当する。他のファイルや自動提示された指示も、内容が選択を裏付ければ認める。

判断までの記録が揃っても裏付けを特定できなければ「根拠未確認」、選択して実行に移らなければ「実行なし」、記録自体が欠ければ「判定不能」。ファイル名の列挙、正解と一致した差分、実行後の説明だけから事前の根拠を推定しない。誤った根拠を採用した場合もパスと解釈を残す。参照と採用を確認できたかと、修復の正誤を別々に記録する。

## 修復（A02-C1・C2）

最終状態で v4 と v がともに src.app.entrypoints.v4_daily_main を起動するかを「成立／不成立」で記録する。変更範囲は開始状態との全差分を照合し、指定した右辺のリテラル以外の内容、モード、他ファイルをすべて維持したかを「遵守／逸脱」で記録する。未編集なら起動先は不成立、変更範囲は遵守となる。

## 検証（A02-C3）

課題文の4コマンドごとに、最後の編集以後の実行を確認し「成功／失敗／終了未確認／実行記録なし」を記す。引数、対象ディレクトリ、実際の出力と終了状態を照合する。出力を絞った場合でも元コマンドの終了状態を追跡できれば、その結果を採る。パイプ末尾だけの終了コードから元コマンドの成功を推定しない。編集がなければ開始時からを対象とする。指定コマンドを単独で発行したかも「はい／いいえ／判定不能」で別記する。
