# C280・C282の分割経路を切り分ける追加比較計画

2026-10-07、発行前に固定。必要な成果は、C282の追加文が分割経路を増やすという説明と、同一プロンプト内の実装選択のばらつきという説明を、無作為化した同時期比較で切り分けること。対象は既存Standard14のF04・F08だけ。実施担当はrootとし、計画、照合、実行、採点、履歴診断と判定を一度ずつ行う。元の本文、ケース、条件、履歴を維持する。

## 比較対象と不足枠

C280 result `794d02abe894456686eea22e9b6f0fed`、C282 result `b9555c4df4584e988c5e1837c2e251d9`の各ケース5件は保持する。各条件・各ケースに不足15件を追加し、累積20件とする。新規60件だけを発行する。これ以上の自動追加はしない。

主判定は新規15件ずつの無作為化比較を使い、先の5件と新規15件を混ぜて因果を判断しない。累積20件の頻度と3 KPIは別に示す。全14ケースN=20とは呼ばない。Layer 1は元のStandard14全14ケースを不変で再利用する。今回は2ケースの対象診断であり、全14ケースN=20の登録条件を満たさないため全体resultとして登録しない。各runのatomic登録と対象case selectionの集計は行う。

## 固定条件と割付

GPT-6.1 Sol Low、CLI 0.159.0、Python 3.14.5、Rating v14、個人指示隔離、全エージェントトークン、並列上限24、executor parameter、fixture、TaskSpecを保存済み比較と一致させる。変数はC280とC282のprompt identityのみ。今回の実行順はprovenanceとして記録し、同じケース・同じ追加反復番号のC280とC282を一組とする。組の順序と組内の先行条件を独立に無作為化して保存し、同じグローバル待ち行列へ流す。反復番号を共通乱数seedとは扱わない。

各条件のatomic preflightを通した後、共通待ち行列の実行順とhashを保存して発行する。並列上限24は変更しない。既存のcampaign runnerの実行処理は再利用し、controllerで発行順だけを変更する。executor、adapter、runtime、TaskSpec、採点、prompt本文を変更しない。

## 発行前に固定する診断

主診断はroot persisted rolloutの外側ツール呼び出し件数。response_itemのcustom_tool_callとfunction_callを数え、思考やモデル処理回数と同一視しない。先の実測で増加した経路を、F08は8回以上、F04は11回以上と固定する。この閾値は診断のためだけでありquality scoreや採用条件にしない。

補助診断として、外側呼び出しの全分布、プロセス結果待ちを含む外側呼び出し数、F08の変更後の差分・status確認を返す境界、F04のnpm検証を返す境界を記録する。同期が必要な待機を不要な待機と数えない。

## 判定方法

新規割付の各ケース15組で、分割経路頻度のC282−C280差を求める。組内の一致・不一致を保持し、両側の正確McNemar検定を使う。2ケースについてHolm法で調整したp値0.05未満かつ差が正なら「追加文による増加を支持」とする。逆方向なら減少を支持する。検定だけで不変を証明しない。

独立二項のWilson区間からNewcombe法の95%頻度差区間も示す。これは組内対応を利用しない補助区間である。F08の先の増加幅40ポイントを、この区間の上限が下回る場合は、その大きさの安定した増加という説明は今回支持されないとする。統計的同等性は主張しない。

有意な増加がなく、同じ条件の中で短い経路と長い経路が混在する場合は、観測した増加は追加文の安定した効果というより実装選択のばらつきに整合すると報告する。ただし小さな効果までゼロと断定しない。3 KPIと経路診断を分け、追加文がどちらの経路を選ぶ確率へ効くかと、長い経路がトークンを増やすかも分ける。

## 停止と保存

不一致・未確認のpreflightは一件も発行せず停止。外部失敗のみ同じ枠を最大3回まで再試行する。有効な失点は保存し、条件を変えて救済しない。60件の予定枠が終わったら判断して終了し、未確定というだけでN=50へ進めない。採点と観測を固定後、証拠を保存してworkspaceを削除し、atomic登録後に最終圧縮する。採用、release、本体反映、新Candidateは対象外。
