# STD14の開始状態の比較契約案と局所照合 第1版

全14ケース・Low／Medium／High各N2の84組について、保存された開始記録を契約案へ照合した。開始記録と起動入力の識別子は対応したが、旧側の容量2項目欠落は84組すべてで検出した。今回の成果はSol Mediumによる契約案の実装と局所検証であり、Astra Highに予定された対応の最終確認は行っていない。追加モデル実行は0件である。

## 元の計画における担当

[元の実施計画](standard14-dedicated-evaluation-plan-r1.md)は、実装・局所検証をGPT-6.1 Sol Medium、対応の最終確認をGPT-6 Astra Highに分けている。[今回の方針](standard14-dedicated-stage7-execution-plan-r1.md)もその責任範囲を保持した。[今回の作業設定](../evaluations/targets/standard14-dedicated-control/registrations/stage7-work-model-binding-r1.json)はセッションの実際の記録へ結んだ。契約案の最終受入、履歴の意味対応、難しさや代替可能性の認定は未実施である。

## 契約案で分けた条件

[開始状態の契約案](../evaluations/targets/standard14-dedicated-control/registrations/stage7-start-state-contract-r1.json)は、記録の項目・型、実物への結び付け、モデルが取得可能な履歴の対応を別々の条件とする。形式上の項目不足がなくなっても、残りの条件を自動的に満たした扱いにはしない。

| 対象 | 照合する内容 |
|---|---|
| 開始記録 | 両側で同じ11項目と型。宣言だけでは成立としない |
| 正本・実行器 | 内容と固定先が一致すること |
| ケースと実行ID | 固定済みの元ケースと専用ケースの対応、推論設定、iterationへ結ぶ |
| 素材とコミット | 各側の実際の識別子を保持し、base・seed・開始の祖先関係と変更内容を照合する |
| Git容量 | 同じ意味と測り方で記録する。素材軸の測定値なので値の等しさは要求しない |
| 判断材料 | seedから開始までの内容差分、親関係、コミット説明の役割を事前に対応づける |

モデルへ開始許可の文言や成功手順を追加する案は含めていない。開始状態の正しさは評価側が実物から確認し、評価を解くモデルへ追加判断を要求しない。旧新は素材移植の別インスタンスであり、同一fixtureのプロンプト比較や同じatomic poolとは扱わない。

## 保存証拠への局所照合

[84組の照合記録](../evaluations/targets/standard14-dedicated-control/registrations/stage7-start-state-audit-r1.json)では、全組のケース・実行ID・配送TaskSpecの開始記録と起動記録の結び付け、baseからseed、seedから開始コミットへの祖先関係を確認した。正本と実行器の結び付けは旧新で一致した。一方、旧側は全組で `git_objects_logical_bytes` と `git_objects_allocated_bytes` が欠け、旧発行前記録3設定の項目一致という宣言は実物と矛盾していた。

旧側ではseedから開始までroot指示58行の削除がある。専用側では同区間に内容差分がなく、空のコミットも一つ多い。これは保存証拠の構造として確認した差であり、どちらか一方を難しさの唯一の原因とする証拠ではない。履歴の差を維持すべき判断材料とするか、許容できる素材投影とするかは、最終確認へ残した。

検出器は、容量2項目の欠落、構築用情報の余分な追加、整数欄への真偽値、正本の内容差を拒否することを検証した。同じ型の容量値の差は、形式の不一致や固定条件の差へ誤分類しないことも確認した。

保存された実行後の作業領域がcleanかどうかを、開始時点の証明にしていない。今回の読み取り専用照合は、発行前の完全な入力・環境・履歴対応の照合を置き換えず、過去の事前ゲートを成立させる効力も持たない。
