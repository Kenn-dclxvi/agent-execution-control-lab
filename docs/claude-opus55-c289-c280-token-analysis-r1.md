# Opus 5.5でC289がC280より多くのトークンを使った理由

2026-10-08。Claude Code Opus 5.5 medium・Standard14 N=5のC280（2026-10-06）とC289（2026-10-08）について、保存済みの登録結果とroot transcriptを、APIリクエスト単位の使用量まで分解した。両条件は同じ互換キーを持ち、各70件が有効である。新しいモデル実行や採点はしていない。

## 結論

C289の全エージェントトークン中央値は1,274,147で、C280の1,058,318より215,829（+20.39%）多い（[計測記録](../evaluations/results/claude-opus55-c289-standard14-n5-cli2288_2026-10-08.md)）。中央値は足し算で分けられないため、以下は1反復（14ケース合計）あたりの平均差+232,358を分解した値である。

増加のおよそ3分の2は、指示ファイルの本文が毎回のリクエストに載る量の増加で説明できる。一つは、自動で読み込まれるルートの指示ファイルが大きくなったこと。もう一つは、開始時にその指示ファイルをコマンドで読み直し、同じ本文を文脈へ重ねて取り込んだことである。リクエストの回数はむしろわずかに減っている。

経過時間は減ったが、トークンが増えたため、C280比のトークン増加はコストの退行として扱う。品質中央値は両条件とも100だが、C289ではA02の2件が3点であり、この低い得点を中央値で相殺しない。この記録は3 KPIの判定を変えるものではなく、トークン差の原因の診断である。

## 分解

Claude Codeでは、各リクエストが会話全体をもう一度文脈として送る。そのため、全エージェントトークンは「最初のリクエストの文脈×リクエスト数」「途中で増えた文脈が以後のリクエストへ持ち越された量」「出力」の和になる。全140件で、この和が登録結果のトークンと一致した。

| 要因 | 1反復あたりの差 | 割合 |
| --- | ---: | ---: |
| 最初のリクエストの文脈の増加（指示ファイルの大きさ） | +88,965 | 38% |
| 最初の二つの応答の結果で増えた文脈の持ち越し | +163,627 | 70% |
| それ以降に増えた文脈の持ち越し | −14,023 | −6% |
| リクエスト数（72回→71回） | −13,314 | −6% |
| 出力 | +7,113 | 3% |
| 合計 | +232,358 | 100% |

### 自動で読み込まれる指示ファイル

ルートの`AGENTS.md`（評価環境ではbundleの`CLAUDE.md`から参照され、Claude Codeが自動で読み込む）は、C280の1,470バイトからC289の5,372バイトになった。最初のリクエストの文脈の中央値は9,430.5から10,691.5トークンへ増え、全14ケースで約1,260トークンずつ増えた。この増加が、1反復あたり約71回のリクエストすべてに載る。

### 開始時の読み取りと持ち越し

最初の二つの応答の結果として文脈へ入った量は、1反復あたり48,011から81,126トークンへ増えた。序盤に入った内容は、その後のリクエストで繰り返し送られる。C289ではこの持ち越しの倍率が平均約4.7倍で、33,115トークンの増加が163,627トークンの増加になった。一方、それ以降に入った量は51,070から44,886トークンへ減っている。

序盤に増えた中身の多くは、指示ファイルの本文だった。各指示ファイルに特有の行がツール結果に現れた回数を数えると、次のとおりである（70件の合計）。

| 指示ファイル | C280 | C289 |
| --- | ---: | ---: |
| ルートの`AGENTS.md` | 10 | 50 |
| `src/AGENTS.md` | 14 | 50 |
| `tests/AGENTS.md` | 0 | 31 |
| `docs/AGENTS.md` | 4 | 5 |

ルートの`AGENTS.md`をコマンドで読んだrunは、C280の10件からC289の48件へ増えた。この本文はすでに最初のリクエストに含まれているため、コマンドで読んだ分は重複である。ツール結果に含まれた指示ファイル本文の推定量は、1反復あたり7,664バイトから71,602バイトへ増えた。ツール結果全体の増加は62,674バイトであり、指示ファイル以外の取得量は全体としてほぼ変わっていない。

ルートの指示ファイルの差（3,902バイトで約1,260トークン）から換算すると、増えた指示本文は約2万トークンにあたり、持ち越しを含めて約10万トークンになる。この換算は推定であり、文字の種類によって比率は変わる。

## ケース別

各行は5件の平均のC289−C280である。全14ケースの値と各runの識別子は[機械可読の分析](../evaluations/results/claude-opus55-c289-c280-token-decomposition_2026-10-08.json)に保存した。

| ケース | トークン差 | リクエスト数（C280→C289） |
| --- | ---: | ---: |
| F02 履歴日付 | +56,847 | 8.4→8.4 |
| F06 空スナップショット | +44,825 | 5.2→7.0 |
| F04 Web監査列 | +30,058 | 7.6→7.6 |
| F01 重複資産キー | +27,982 | 6.2→7.0 |

| F10 月次形式レビュー | −10,652 | 6.0→4.2 |

A01とF05の三つのケースは、どちらの条件もリクエストが2回で、約2,600〜2,800トークン増えた。これはほぼ指示ファイルの大きさの分だけである。F06はリクエスト数も増えた。F10の二つのレビューケースは、序盤の読み取りでリクエスト数が減り、C280より少なくなった。

## 限界

- C289は、C280からC284、C285、C288、C289の順に変更を重ねた条件である（C286とC287はC285から分かれた別の枝で、C289の祖先ではない）。Opus 5.5ではC284、C285、C288を測っていないため、どの段階で増えたかは実測では分けられない。本文の上では、ルートの指示ファイルはC284とC285でも大きくなっている。また、「対象のディレクトリからリポジトリのルートまでにある適用される指示ファイル」を開始時の読み取りに含め、全文を読むとする文は、この系譜ではC288で入った。別の枝のC286にも同じ趣旨の文があり、C286のOpus 5.5計測でもトークンはC280より増えていた。
- 指示ファイルの読み取りの数は、各ファイルに特有の行がツール結果に現れた回数であり、本文全体を取得した証明ではない。バイト数からトークンへの換算も推定である。
- この記録は、どの文がどの読み取りを生んだかの因果効果を示すものではない。次の制御案は導いていない。
- A02の2件の減点（試験証拠の不足）は、トークン増加とは別の問題である。
