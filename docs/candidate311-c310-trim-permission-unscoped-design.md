# Candidate311 C310の、出力を絞ってよいとする一文から範囲の修飾を外す

2026-10-12。C310（C309の「TaskSpec」を「依頼や適用中の指示」に置き換えたもの）のSonnet lowで、確認コマンドの出力を絞る実行が減ったため、Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9に対応させた。計測と記録は[計測と記録の基準r2](shared-instruction-evaluation-criteria-r2.md)に従う。この記録ではbundleを作成しない。

## 目的と役割

- 系列：実行環境を切り離し、負荷を見て次のrunを始める発行の条件（CPU使用率70%以下、間隔1秒）で測る系列。プールは実効互換の規則（`effective-v1`）で作る。
- ベースと直接の親：C310（`the-caption-3ce91a4-final-check-unit-output-trim-generic-r1`）。比較の基準は、同じ条件のC309とC310のSonnet low。
- 計測の順序：Sonnet lowで確かめてから、Sol Lowを測る。
- 評価は計測であり、達成目標を置かない（r2）。
- 変更対象：C310のroot `AGENTS.md`のうち、出力を絞ってよいとする一文の範囲の修飾（「依頼や適用中の指示が求める」）だけを外す。他の項目と他の18対象はC310とバイト一致を保つ。

## 1. 比較の基準と、正常な最短経路

[C309の設計記録](candidate309-c307-final-check-unit-design.md)の項目1のとおり。

## 2. 保存traceで確認した問題

| 項目 | C309 | C310 |
| --- | ---: | ---: |
| `main_verify.sh`を出力そのままで実行 | 3 / 21 | 11 / 21 |
| 出力が退避された回数（読んだ回数） | 3（3） | 11（9） |
| 15,000字を超えるツールの結果 | 0 | 3 |
| 費用（USD） | 0.6637 | 0.6988 |

C309の一文「TaskSpecが求める確認のコマンドは、出力を絞って実行してよい。」は、課題文の「以下のTaskSpecに従って作業してください」と同じ言葉で、課題文の確認コマンドに直接結びついていた。C310の「依頼や適用中の指示が求める確認のコマンドは」では、この結びつきが弱くなったと読める。状態の確認の置き場所の文（遵守28/31）と、完了条件の確認（省略0件）は、C310でも保たれた。

## 3. 開いている記述

出力を絞ってよいとする一文は、許可を与える文で、何かを閉じる文ではない（[C307の設計記録](candidate307-c306-validation-output-trim-design.md)の項目5）。許可の範囲を限定する必要はなく、限定の言葉が、許可の当てはまる場面をモデルに判断させている。

## 4. 追加・変更する条件の全件

C310の一文を、次に置き換える。

> - 確認のコマンドは、出力を絞って実行してよい。確かめる終了コードは、そのコマンド自身のものとする。

状態の確認の置き場所の文（「依頼や適用中の指示が求める確認のうち最後に実行するもの」）は、C310のまま変えない。

## 5. 禁止行動、開放経路、閉じる境界、反証

C307の設計記録の項目5のとおり。許可の範囲が「確認のコマンド」全体に広がるが、絞らずに実行しても違反にならない点、確かめる終了コードはコマンド自身のものとする点は変わらない。

## 6. 維持する正常経路

C307の設計記録の項目6のとおり。

## 7. 新しく増える判断と、変更対象外への影響

- 新しい判断はない。許可の当てはまる場面の判断（求められた確認かどうか）がなくなる。
- 危険：依頼が求めていない確認（モデルが自分で選んだ確認）も出力を絞るようになる。終了コードを確かめる点は変わらないので、品質への影響は小さいと見込む。
- 固定分：一文が短くなる。

## 8. 評価ケース、比較単位、比較条件、記録する項目

- セル：Sonnet low、続けてSol Low。各Standard14の全14ケースN=5の計70件。
- 比較条件：C310の同じセルのプロファイルと同じで、prompt identityだけを変える。
- 記録する項目（r2）：品質、処理の適切さ、費用、経過時間、生のトークン（参考）。
- 機序の診断（合否にしない）：`main_verify.sh`を出力そのままで実行した件数、出力が退避された回数と読んだ回数、状態の確認の置き場所の遵守率、状態を確かめずに報告したrun、確認の後の応答、F06とF07の`git diff --check`の成功件数。
