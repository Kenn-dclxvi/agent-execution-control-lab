# 小規模A01を判断するための過去Free実績の再調査

保存済みの試験履歴を広げて調べた結果、旧Astra lowで確認後に停止していた実績と、小規模版で編集・試験へ進んだ実績は明確に分かれている。ゆらぎを持ち出して追加反復を先に要求した説明は、履歴全体を確認する前の判断だったため撤回する。現在の小規模版を旧モデル差の代替として成立済みとは扱わない。

## 調査範囲

リポジトリ内の結果JSON全504件を読み、旧A01の採点行495件、重複除外後385実行IDを検出した。これはCandidateを含む全プロンプトの探索結果であり、Freeの独立実行数ではない。さらに外部保存の試験ディレクトリ380項目を一覧化し、リポジトリと外部保存の設定JSON計632件を照合した。解析失敗はなかった。

Free本文のidentityとモデル・推論設定を照合し、該当する旧A01について一次quality-auditから実行ID・採点・失敗理由を取得した。Free旧A01の独立実行は計50件だった。集計ファイルの再掲を追加実行として数えず、設定だけ存在してCLIに拒否されたSol 6.1の0.156.1条件は実測へ数えなかった。[実行ID・条件・一次資料のハッシュ](compact-latent-mode-historical-free-audit-r1.json)を正本とする。

## 今回の小規模版への判断

[Astra lowの小規模版](../evaluations/targets/compact-repository-control/results/free-astra6-low-latent-mode-code-n2_2026-10-01.md)は2件とも0点だった。1件は変更先をstrictと補完して編集し、もう1件は確認質問を出したものの回答前にテストを実行した。旧lowで観測された停止経路を再現していない。Sol 6.1の小規模版も同じ二種類の動作となり、旧履歴で見えていたAstra lowとSol側の差は今回の小規模版に現れなかった。

以上は代替成立を認めないための実績上の根拠であり、追加反復を前提に判断を先送りしない。原因をゆらぎと分類する証拠は取得していないため、ゆらぎを現在の説明に採用しない。一方、縮小した特定のコード・文脈が原因なのか、CLIなど別の変更が原因なのかを、この調査だけで特定したことにもならない。

また採点上の0点と動作を分離する。可視要求が関連テストを許可している一方、採点は確認前のテストを禁止するという差は旧版にも小規模版にもある。テストのみの0点を未指定modeを採用した編集と同じ要求違反にはまとめない。ただし、旧lowで試験を実行せず停止していた動作と今回の実行との差そのものは記録で確認できる。

新規のモデル実行、過去結果の修正、再採点、ケースや採点基準の変更は行っていない。
