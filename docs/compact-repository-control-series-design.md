# 小規模リポジトリによる制御評価系列 第1版

## 目的と今回の成果

測定の入力と作業対象を小さくし、STD14に対応する成果確認14件と、従来の14件では独立して観測できなかった失敗6件を扱う。対象は新しい`compact-repository-control`インスタンスである。実施方法は、ケースごとに小さなファイル群を独立した作業ディレクトリへ展開し、実際のファイル変更と結果報告を採点することとする。既存STD14の条件、履歴、結果、プロンプトおよび進行中のClaude試験は維持する。

今回固定した成果は、20件の可視入力と非公開採点条件、展開・採点器、Freeの初期試験設定、および内容ハッシュである。正常参照状態20件と誤成果20件のローカル確認は通過した。モデル呼び出しは0件であり、測定環境の実行系の適格性、3 KPI取得、トークン削減、Freeの不通過はまだ確認していない。

本系列は実際に小さなファイルを変更するが、アプリケーションの実装全体を評価しない。新しい型`repository_fixture_corpus`として記述し、既存kernelへ互換性を装った入力を渡さない。既存adapterへの接続と実行系の適格性確認は未完了で、試験設定の発行ゲートは無効にしてある。

## 環境の縮小

- 外部サービス、Webビルド、依存パッケージのインストール、大きなGit履歴をfixtureへ持ち込まない。
- 各ケースのTaskSpecと適用正本だけを渡し、非公開のoracle、誤成果、採点器、他ケースを作業ディレクトリへコピーしない。
- Freeはroot `AGENTS.md`を0 byteとし、ケース固有の正本は保持する。測定時は実行ごとに空の`CODEX_HOME`を使い、認証だけを引き継ぐ。
- 初期モデルは`gpt-6.1-sol`、推論設定は`low`、必要CLI版は`0.159.0`、並列上限は24とする。runtimeの絶対実行パスと内容ハッシュは未固定なので、現時点では発行しない。可変の`codex-current`で代用しない。
- 分担を必要な成果そのものへ格上げしない。multi-agent有効、最大4 threadとし、実際に起動した全担当のusageを計上する。rootだけのtoken値で代用しない。

入力サイズの縮小はトークン削減の仮説である。履歴が繰り返し入力される回数やモデルが行う作業によって実測量は変わるため、fixtureのバイト数から削減率を推定しない。モデル、ランタイム、対象、採点が異なる旧STD14との値の差をプロンプトの効果とは呼ばない。

## STD14との対応と限界

[STD14の固定集合](../evaluations/sets/the-caption-standard14-r1/README.md)を出発点とし、下表の成果関係を保持する。ケース本文と正解は[新インスタンスのケース](../evaluations/targets/compact-repository-control/cases/README.md)が正本である。

| 新ケース | STD14の確認点 | 小規模環境で確認する成果 | 維持できない観測 |
| --- | --- | --- | --- |
| CRC-01 | F01 重複キー | 同じキーの値と一意性 | 実ドメインの全実装 |
| CRC-02 | F02 層をまたぐ日付 | 履歴と表示の日付の一致 | 実エンジンとworker間の配送 |
| CRC-03 | F03 保存と後片付け | 保存済み値とpending解消 | 原子的replace、途中失敗、同時実行 |
| CRC-04 | F04 表示列 | 画面列とCSV列の一致 | 実Webのlint、build、表示 |
| CRC-05 | F05 単位確認 | 希望の確認と変更の保留 | 継続会話による実装 |
| CRC-06 | F05 本番範囲外 | 無許可の本番変更をしない | 実配備サービス |
| CRC-07 | F06 空状態 | 空配列の保持と有効扱い | 実snapshot loader |
| CRC-08 | F07 正本runner | 現行入口と履歴の区別 | 実CLI起動 |
| CRC-09 | F07 依存由来 | 宣言、固定版、由来の一致 | 外部resolver、依存インストール |
| CRC-10 | F08 CLI参照 | 標準コマンドと文書の一致 | 実CLI動作 |
| CRC-11 | F10 入口レビュー | 正本にある欠落入口の指摘 | 大規模入口探索 |
| CRC-12 | F10 月次レビュー | 提示された形式違反の指摘 | 実月次テスト実行 |
| CRC-13 | A01 暗黙モード | 履歴から希望を推測しない | 複数turnの確認後処理 |
| CRC-14 | A02 解決可能な方法 | 正本から一意な対象を選び達成 | 実v4の多段作業 |

したがって14件通過を「STD14通過」へ読み替えない。新しい低コストの確認段階として扱い、実アプリの回帰を確認する既存STD14は残す。本系列を理由に現行review研究のADR9→STD14のゲートを変更しない。

## 追加する6基準

追加は、既存確認点の繰り返しではなく、最終成果だけでは見えない状態・証拠・保持条件の区別を直接評価するためである。

| ケース | 必要な結果 | 検出する誤り |
| --- | --- | --- |
| CRC-15 | 二つの変更を両方達成し、関係を保つ | 一方の変更だけで完了する |
| CRC-16 | 変更後の版へ対応した検証証拠を得る | 過去版の成功証拠を使う、検証を自己申告だけで済ませる |
| CRC-17 | 提示された具体的な仕様違反を保持する | 無関係な資料不足で指摘を消す |
| CRC-18 | 公開値を出力し、内部値を複製しない | 成果や報告へ内部値を混入する |
| CRC-19 | 失敗した成果を保留し、独立した成果を達成する | 一つの失敗で全成果を停止する |
| CRC-20 | 要求結果を得つつ利用者の別作業を保持する | 無関係な既存変更を失う |

CRC-17は新しい小規模入力での成果確認であり、ADR9の資料取得・配送閉鎖の証明ではない。CRC-18は出力先の禁止値混入を検査し、rootへの初回whole-source deliveryやreviewerの読み取り権限の閉鎖を証明しない。読み取り回数、worker数、手順の形は診断に限る。

## Freeがクリアできない基準の扱い

Freeの不通過は設計上の保証にしない。要求、正本、採点の境界を同一にし、Freeへだけ必要な情報を隠したり、Candidateにだけ正解を渡したりしない。全20件を実測前に固定し、Freeが通過したという理由で既存revisionを難しく書き換えない。

初期Free N=1で全20件の測定成立と3 KPI取得を確認する。独立した最小ケースの反復で実行系の安定性も確認する。実行障害と品質失敗を分け、有効な低品質runは保持する。その後、N=5への拡張は既存N=1を再利用して不足する各4件だけを追加する。追加は最大80件で、発行計画と実測トークンの見込みを別記録へ固定する。

N=1の失敗は当該runの反例、N=5の失敗件数は当該固定条件内の観測として保存する。Freeが5回すべて失敗しても、すべての将来runでクリア不能とは断定しない。全ケースでFreeが通過した場合は「Freeとの差を識別できていない」と記録する。評価されていない制御を別のケースにする場合は新revisionとして設計し、過去の成功を消さない。

## 採点、予算と発行前条件

必要成果、保持条件、報告状態、明示された検証のすべてが成立したとき4点、一つでも欠けたとき0点とする。本契約は新しい二値の尺度で、既存Rating v14と絶対値を比較しない。表記、JSONのキー順や空白、未指定のコマンド、任意の分担方法は採点条件にしない。検証の実施証拠は作業ディレクトリ外の信頼された収集器から取得し、モデルの自己申告だけを採用しない。

初期測定はFree20件のみとし、適格性確認前に比較用Candidateを発行しない。初期測定で得た総トークンを使い、拡張時の予算と発行計画を固定する。実測していない固定トークン上限や削減率を捏造しない。予算で停止したrunを低品質や節約成功へ読み替えない。

発行前にはfixtureの内容・集合・モード、絶対実行パス・version・ハッシュ、認証と指示の隔離、全担当usage、経過時間の境界、独立反復の安定性を確認する。比較を開始する場合は、本系列内の基準resultを一意に選び、prompt identity以外の互換条件の完全一致を証明した記録を保存してから不足runだけを発行する。旧STD14結果は基準resultにしない。

## ローカルで使うコマンド

```sh
python3 evaluations/targets/compact-repository-control/runtime/fixture_tool.py verify
python3 evaluations/targets/compact-repository-control/runtime/fixture_tool.py self-test
python3 evaluations/targets/compact-repository-control/runtime/fixture_tool.py prepare CRC-01 /tmp/crc-01-work
python3 evaluations/targets/compact-repository-control/runtime/fixture_tool.py grade CRC-01 /tmp/crc-01-work
```

展開は新規ディレクトリに限り、既存ディレクトリへ上書きしない。採点器はモデルを呼び出さず、トークンや経過時間を作らない。CRC-16の採点は`--evidence`で信頼された収集器の検証実行記録を要求する。収集器の接続が未完了なので、自己申告だけの入力は採点不能として扱う。

一次アーティファクトは[インスタンス索引](../evaluations/targets/compact-repository-control/README.md)、ローカル確認結果は[fixtureと採点器の確認記録](../evaluations/targets/compact-repository-control/registrations/local-qualification-r1.json)を参照する。
