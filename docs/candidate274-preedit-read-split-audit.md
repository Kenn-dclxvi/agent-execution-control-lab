# C274編集前の読み取り分割の再監査

前の時間比較で残った「初回にまとめて取得できる情報が、なぜ追加取得へ回るのか」を、F02・F04・F07依存関係の3ケースについて、C147 Sol・C147 Astra・C274 Astra各N=5、計45runで確認した。新規評価、Candidate作成、既存resultの再採点は行っていない。

結論は、分割には情報不足を自ら作る取得方法と、適用ルール取得の後回しが混在していた、ということである。単に独立した呼び出しの同時発行を忘れたという説明では足りない。また同じ形がC147 Astraにも存在するため、C274で削除した4条項が発生原因とはいえない。

## F02で確認した具体的な連鎖

Astraは初回に複数ファイルの全文を連結して出力した。初回の外側出力は途中を省略され、日付選択関数`_resolve_market_end_date`の定義と修正対象の`self._fetch_market_history(asset)`が、C147 Astra・C274 Astraとも全5runで欠落した。後続の限定した読み取りでは、両条件とも全5runで関数定義を取得できた。

代表例`6ab914d5099a48308f89e3f9aac3af85`では、コマンドが返した生出力61,163文字には関数定義が存在し、省略表示もなかった。しかしモデルへ渡された外側の結果は16,846トークン相当から6,846トークンが省略され、関数定義が欠けていた。コマンドを発行したことと、必要な本文をモデルが受領したことは一致していない。

| 条件 | 初回に日付選択関数の定義を受領 | 編集前の外側呼び出し |
| --- | ---: | --- |
| C147 Sol | 5 / 5 | 1回が4件、2回が1件 |
| C147 Astra | 0 / 5 | 2回が5件 |
| C274 Astra | 0 / 5 | 2回が5件 |

Solの初回結果にも全5runで省略表示があるため、省略の有無だけでは説明できない。Solは対象ごとの部分取得を行い、今回の修正に必要な関数が初回の受領内容に残っていた。重要なのは欠けた内容である。Solの1runは必要関数が届いていても追加取得しており、初回受領だけで必ず一度に終わるという因果は証明していない。

## 適用ルールは必ず後から読む必要があったか

F02のTaskSpecは対象4ファイルを開始時から明示し、既存authorityの必要範囲の読み取りを許可している。開始identityの確認は編集・必須検証の前提であり、読み取りを禁止する条件ではない。

C274の1runは初回から対象パス上の`AGENTS.md`を列挙・取得していたが、それでも本文の省略により2回目が必要になった。残る4runは後続で適用ルールを取得している。C147 Astraにも初回から適用ルールを取得した例があり、対象パスから候補を列挙して存在する指示を読む処理は初回に実施可能だった。ルール取得のためのモデル往復が常に不可欠だったとはいえない。

一方、適用ルールの本文によって読み取り許可や対象が変わる場合は真の判断境界となる。今回の「初回に取得可能」という観測を、あらゆる指示・sourceを無条件で同時取得してよいという一般則へ拡張しない。

## F04・F07では同じ説明がどこまで成立するか

F04ではAstra両条件とも全5runで初回出力が省略され、`colSpan`を含む表の構造は初回に届かず、後続取得で届いた。Solは初回が部分取得のため同じ箇所を後から読むが、初回に省略表示はない。外側呼び出しはSolが2回4件・3回1件、C147 Astraが2回5件、C274 Astraが2回4件・3回1件である。このケースの時間差を往復回数だけでは説明できない。

F07依存関係では初回出力の省略は全条件0件。Solは全5runが一度の取得、Astra両条件は各4runが一度、1runが二度だった。Astraは依存ファイル全文とルールの探索・取得を広く行うが、このケースの時間差をF02の省略・再取得だけで説明することはできない。

## 制御文との対応

[Candidate原文](../prompts/candidates/the-caption-3ce91a4-execution-boundary-core-r1/files/AGENTS.md.txt)の`DECISION_BOUNDARY`は、既知の相互非依存invocationを同じmodel stepへまとめる規則である。初回取得が不十分だった後の追加取得や、先に所在探索を選んだ結果として生じる本文取得まで、自動的に消すものではない。

`EVIDENCE_GATE`は必要な情報の欠落・読み取り不能などを追加証拠の理由として認める。今回、初回を一度に発行しても、結果のまとめ方で必要本文が届かず、取得を完了できない状態を作っていた。従って、後続取得を一律禁止すると必要情報を失う。後続のすべての呼び出しが同条項へ厳密に準拠したという判定は、本監査では行っていない。

以前の検証では、結果が揃う前のモデル再入が問題だった。今回は、初回発行済みでも必要な情報が受領できていないため、再取得が必要になる経路が具体的に確認された。「一度にやらせる」だけではこの違いを扱えない。ここまでを原因診断として固定し、解決案・新Candidateの機序成立は主張しない。
