# C284の経過時間増加の分解

2026-10-07。[C284のSol Low・Standard14 N=5](../evaluations/results/c284-sol61-low-standard14-n5_2026-10-07.md)では、C280比でトークンが-25.79%減った一方、経過時間は+7.93%増えた。この増加がどこで生じたかを、C280・C283・C284の保存rolloutから分解した。新しいモデル実行と再採点は行っていない。

## 結論

増加はモデルの応答区間だけで生じており、プロンプトが作業を増やした証拠は見つからなかった。C284はC280より応答回数、出力トークン、入力トークンが少ない。一方、応答1回あたりの待ちは、測定した時間帯が遅いほど長かった。C280は同日で最も応答が速い時間帯に測定されていた。

判定規則上、経過時間の増加は退行として記録したまま変えない。この分解は原因の診断であり、3 KPIの判定を置き換えない。

## 区間ごとの内訳

C284のツール実行は、変更以後の区間で増え、変更前の区間で減った。合計はC280の73.6秒に対し69.0秒である。C280では長い試験の実行中にモデルが待機呼び出しを出すため、試験時間の一部がモデル区間に含まれていた。C284では試験時間がすべて一つの呼び出しの中に入るため、区間の付け替えが起きている。

入力やツール出力を受け取ってから、次のモデル出力が最初に記録されるまでの待ちの中央値は次のとおり。いずれもGPT-6.1 Sol Lowで、時刻は日本時間。

C284の三項が適用されない変更なしの5ケース（A01、F05の2ケース、F10の2ケース）でも、出力トークンはほぼ同じまま、モデル区間の中央値の合計がC280の65.7秒からC284の85.5秒へ増えた。プロンプトの差では説明できない増加が、ここにも同じ向きで現れている。

## 対処の方向

- 応答速度はリポジトリの外の要因であり、プロンプトでは制御しない。経過時間の差を判定するには、基準と候補を同じ時間帯に測る必要がある。これは評価方法の変更にあたるため、実施する場合は別作業として設計する。
- プロンプトで減らせるのは、モデルの応答回数である。最初の変更以後の応答回数は、C284がC147（9月30日のSol Low）と同じ水準まで減った。残る差は変更前の区間にあり、変更を伴わない経路も含めた全70件で、最初の変更までの応答はC284が243回、C147が203回だった。この区間を対象に、C147の開始側の境界を移植する設計へ進む。

## 判断の限界

区間の境界はrolloutの記録時刻による。モデル区間には通信や待機も含まれ、純粋な推論時間ではない。変更なしケースの比率で補正した値は推定にとどまり、判定には使わない。時間帯による差は、同じ時間帯での比較を行うまで確定しない。
