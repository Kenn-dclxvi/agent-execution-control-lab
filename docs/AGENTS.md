# docs instructions

`docs/`の指示は、文書の正本、現在解釈、研究frontier、固定済み成果、履歴、参照整合を扱う。ルートの`AGENTS.md`の共通規則に加えて、この領域規則を適用する。

## 正本と索引

- リポジトリ契約の正本は`docs/repository-contract.md`とする。
- 評価基盤のレイヤーと境界は`docs/prompt-comparison-workflow.md`を正本とする。
- 評価実行方法は`docs/evaluation-loop-manual.md`を正本とする。
- プロンプト制御の設計原則は`docs/prompt-control-design-principles.md`を正本とする。
- `docs/README.md`は`docs/`配下文書の現在の分類・配置・読む順序を示す索引とする。分類の意味と更新規則はこの`AGENTS.md`を正本とする。
- 新規文書の追加、文書の役割変更、研究状態の遷移があった場合は、必要に応じて`docs/README.md`の所属と説明を同じ変更で追従させる。

## 文書分類

`docs/README.md`では文書を次の8分類で扱う。分類は文書の内容だけでなく、現在の役割とライフサイクルで決める。分類名（`現行frontier`、`historical／superseded`など）は`docs/README.md`の見出しと対応する固有ラベルのため、表記規則の対象外とする。

- **正本（canonical）**: 他文書がauthorityとして参照する契約・原則。要約文書や研究成果で置き換えない。
- **現在地・研究全体像**: 研究全体の入口、系譜、横断知見、未完了項目、長期方向を示す文書。読む順序は原則として「全体像 → 系譜 → 横断知見 → バックログ → ロードマップ」とする。
- **現行frontier**: 現在進行中で、次の設計・測定・判定を直接拘束する研究軸。別の研究軸を一つの時系列へ混ぜず、因果系列ごとに分けて並べる。
- **研究成果・統合知見**: 固定版の技術報告、総説、横断分析、統合知見。現在有効な成果であっても、進行中という理由だけで`現行frontier`へ置かない。
- **実務者向け解説**: 研究成果を実務向けに翻訳した読み物。研究アーティファクト、一次資料、正本の代替authorityとして扱わない。
- **評価・運用基盤**: 評価インフラ、実行環境、ストレージ、運用仕様など、測定・運用を成立させる文書。研究上の知見やfrontierと混ぜない。
- **完了済み研究記録**: 特定Candidate、比較、診断、段階判断などの完了済み成果アーティファクト。当時のresult・score・statusを保持する。
- **historical／superseded**: root-only履歴、完了済みの引き継ぎ文書、旧設計入力、後続成果で置換された解釈。現行設計・現行値として読ませず、文書内の位置づけを明示する。

## ライフサイクルと現在解釈

- `現在有効`と`現在進行中`を同義にしない。固定済みの技術報告や統合知見は`研究成果・統合知見`、次の観測や判断が未完了の系列だけを`現行frontier`とする。
- frontierの研究軸が完了した場合、文書本文を完了後の状態へ遡及改変して合わせず、索引上の所属を`研究成果・統合知見`または`完了済み研究記録`へ移す。必要な現在解釈は注記、新しいリビジョン、または別文書として追加する。
- 固定版を宣言した技術報告はその場で後続測定を取り込まない。内容が変わる場合は新しい版として追加し、旧版は当時の固定成果として保持する。
- 現在状態、当時の評価、後続の再解釈を同一の事実として混ぜない。
- 過去の判定、score、result、statusを削除しない。
- 過去resultを、後続のrating contractで再採点したように記述しない。
- 評価と採用、releaseとprojectionを別の状態として記述する。
- 未決事項を確定仕様として記述しない。

## 証拠と参照整合

- 数値、件数、status、commit、識別子は一次アーティファクトで確認する。
- 研究成果・総説・実務者向け解説は、一次アーティファクトや正本より強いauthorityを持つように記述しない。
- 同じ説明を複数文書へ全文複製せず、正本または対応する一次アーティファクトへのリンクを優先する。
- 文書移動時は、移動先基準で相対リンクを確認する。
- 見出し、用語、限定列挙、`docs/README.md`の分類番号を変更する場合は、文書全体の追従漏れを確認する。
