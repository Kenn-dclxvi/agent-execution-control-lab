# C325 r2で確定済みの条件を引き継ぐ

C324を直接の親とし、ルートの見出しにはC325初版と同じ番号を置く。第一項の最初の文の直後に、利用者と合意した次の一文を加える。

> その対象と作業に適用される条件は、今回の依頼で繰り返されていなくても求める結果に含め、今回指定された追加・変更・解除を反映する。

引き継ぐ対象は先行する要求・適用中の指示・正本がその対象と作業について定めた条件である。新しい依頼で言及が省かれただけで要件が失効するという解釈を退ける。追加文は結果の決め方を定める。先行条件の適用範囲や今回の変更内容を読み取る判断は残る。要求が確定していれば実施方法を選び、不足があれば指定の事前確認を経て不足点だけを質問する。

初版のA01は5件中2件で、変更後の値を尋ねる前に現行コードを検索した。A02は5件ともテストディレクトリの指示を読み、テスト全体を実行した。課題文だけでは、質問前に現行実装まで読むか、どこまでのテストを選ぶかは一意に決まらない。r2ではC324の未確定時の調査制限と消去法による推測の制限を採用し、初版の毎回の規則確認の指示を外す。変更はルートの見出しと第一項に限る。[初版の診断](../evaluations/results/c325-astra62-low-a01-a02-n5_2026-11-20.md)

初版と同じ固定Standard14 r1のA01 r2・A02 r2をGPT-6.2 Astra Low、Codex CLI 0.169.1、採点契約v14で各5回診断する。実行前照合の不一致で発行を止め、無効・採点不能な実行を有効件数に含めない。ケース別の得点分布、A01の質問前の操作、A02の修復・検証、同じ単価表での費用、時間と実測トークンをC324・初版の保存結果と比較する。得点低下があれば品質維持と判定しない。これらは単発の課題であり、依頼をまたいだ条件継承の効果はこの試験の観測範囲外とする。
