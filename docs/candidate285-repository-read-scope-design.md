## 作成前の確認事項

1. **比較基準と正常な最短経路。** 基準はC284。正常経路は、依頼で指定された開始時の確認と、依頼が名指ししたファイルや適用される指示の読み取りから方針を固め、変更し、検証と確認を一つの呼び出しで終えることである。
2. **保存traceで確認した問題経路。** リポジトリの外を読んだrunは、C280が12 / 70件、C284が9 / 70件、C147が0 / 70件。すべてF06、F07の正規runner、F08で、`*identity*`や`*gate*`のファイル検索に続けて親ディレクトリを一覧し、試験基盤の`../case.json`を読んでいた（例：C284 F08 `9daebfe428e4499c8f765af897d4835b`、C280 F08 `694346e9c773454fa2aa1dd4b3d0f560`）。得た内容は依頼と同じTaskSpecで、2〜3回の外側呼び出しと応答が増えただけだった。C284の変更前の外側呼び出しのうち18回がこれに当たる。
3. **既存の記述やTaskSpecでは防げない理由。** C280第1項（C284でも同じ）の「利用可能な情報や環境を確認し、自分で決めて進める」が、確認してよい範囲を限定していない。TaskSpecの「runnerのstart-identity gateがfailedなら停止」は、その判定結果がどこにあるかを示さないため、探索の動機になる。TaskSpecは評価条件として固定されており、変更しない。
4. **追加する条件の全件。** 上記の一項だけである。既存の文は変更しない。担当、ラベル、新しい判断項目は追加しない。
5. **禁止行動、開放経路、閉じる境界と反証。** 禁止行動は、rootが作業対象のリポジトリの外のファイルやディレクトリを読むことである。開放経路は、確認範囲を限定しないC280第1項の文である。追加文は、確認してよい情報源を依頼、適用中の指示、リポジトリへ限定する。範囲はパスで決まり、必要性や目的の判定を介さない。「必要だから」「安全のため」と位置づけても、リポジトリの外を読めば違反になる。順序や呼び出しの分け方を変えても同じである。
6. **維持する正常経路。**
   - 依頼が名指ししたファイル、適用中の指示ファイル、リポジトリ内の`.venv`や`node_modules`を含む作業ディレクトリの中は、これまでどおり読める。リポジトリ内の`.agents`や`.codex`の確認も制限しない（C147でも12件あった）。
   - コマンドの実行は読み取りと区別し、制限しない。`npm ci`、`pytest`、`node --version`などが外部のツールやパッケージを使うことは、この文の対象外である。
   - 依頼が外部の判定に触れている場合でも、依頼で指定された確認（`git status --short`が空であることなど）だけで判断する。C147はこの形で全70件が品質4だった。
   - 変更を伴わない経路（A01、F05の2ケース、F10の2ケース）にも適用されるが、これらの経路でリポジトリの外を読んだrunはC280・C284とも0件だった。
7. **新しく増える判断と対象外への影響。** 新しい判断は、読み取る対象がリポジトリの中かどうかだけで、パスから機械的に決まる。依頼が外部の判定に触れるケースで、その判定を探さずに進むことが、停止すべき場面を見落とす危険を生まないかを確認した。F06、F07、F08の依頼は、未コミットの変更を同時に停止条件としており、`git status --short`で判定できる。試験基盤は開始前にstart-identityを検証済みである。
8. **評価ケースと比較条件。** C284のprofile（`c284-sol61-low-standard14-n5-cli0159-isolated-20261007-r1`）からprompt identityとprofile IDだけを変える。GPT-6.1 Sol Low、Standard14全14ケース各N=5の計70件、Rating v14、CLI 0.159.0、Python 3.14.5、固定Layer 1、fixture、TaskSpec、個人指示の隔離、M24、固定executor、全エージェントのトークン計上を再利用する。主比較はC284。品質、全エージェントトークン、経過時間の3 KPIで判定する。原因の診断として、[経路分析の記録](../evaluations/results/c284-start-side-route-analysis_2026-10-07.json)と同じ方法で、リポジトリの外の読み取りを含むrun、変更前の外側呼び出し、モデルの応答回数を集計する。経過時間は[経過時間の分解](c284-elapsed-time-decomposition-r1.md)と同じ方法で区間に分け、応答1回あたりの待ちの中央値も記録する。
9. **停止条件。** 互換条件の不一致や未確認があれば、一件目の発行前に停止する。外部失敗だけ同じ枠で固定上限内に再試行し、有効な失点は保存する。70件を完了して判断し、自動で追加反復しない。品質を維持し、トークンと経過時間がともに減った場合だけコスト改善の方向とする。片方でも増えた場合は、その指標の退行として記録する。リポジトリの外の読み取りの件数は診断値とし、独立した合否条件にしない。採用、本体反映、方式の修正による再試験は行わない。
