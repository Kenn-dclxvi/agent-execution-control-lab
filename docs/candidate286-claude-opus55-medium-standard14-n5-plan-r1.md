## Claude Codeでの見込みと注意点

Claude CodeとCodexでは、ツールの形とコストの生じ方が違う。結果を読む前に、次の点を固定しておく。

- **モデルの再開の単位**：Claude Codeは、一つの応答の中で複数のツール呼び出し（たとえば複数のファイルの`Read`）を並べて発行できる。コストの主な原因であるモデルの再開は、ツール呼び出しの数ではなく、モデルの応答（assistantのメッセージ）の数で生じる。C286の「一つの外側のツール呼び出し」を、並べた`Read`の代わりに一回の`Bash`で`cat`する形で守ると、応答の数は減らずに形だけが変わる可能性がある。
- **ツールの使い分け**：Claude Codeの既定の指示は、ファイルの読み取りに`cat`ではなく`Read`を使うよう求めている。リポジトリの指示とこの既定の指示がぶつかった場合の振る舞いは、観測して記録する。
- **長いコマンド**：変更後の検証を一回の`Bash`で実行すると、F04の`npm ci`などで`Bash`の時間上限に近づく可能性がある。背景実行や待機の操作が増えた場合も記録する。
- **測定時刻**：比較相手のC280は2026-10-06に測っている。Sol Lowで確認した時間帯による応答速度の差（[経過時間の分解](c284-elapsed-time-decomposition-r1.md)）がOpus 5.5にもあり得るため、経過時間の差はプロンプトだけの効果と断定しない。

## 判定

品質、全エージェントトークン、経過時間の3 KPIで判定する。品質を維持し、トークンと経過時間がともに減った場合だけコスト改善の方向とする。片方でも増えた場合は、その指標の退行として記録する。有効な4点未満は削除、相殺、再実行しない。

## 診断

診断は独立した合否条件にしない。Claude Codeのtranscriptから、次の値をrootとsubagentごとに集計する。

| 診断 | Claude Codeでの数え方 |
| --- | --- |
| 変更の有無 | `Edit`、`Write`、`MultiEdit`の使用、または`Bash`による許可パスへの書き込み |
| 変更後の検証の一括実行 | 最後の変更以後、検証と確認のコマンドを実行した`Bash`の呼び出し数と、それを含むモデルの応答の数。背景実行と待機の操作も数える |
| 名指しされたファイルの読み取り | 名指しされたファイルを最初に読んだツール呼び出しの順番と、そのときのモデルの応答の順番の両方。`Read`、`Bash`の`cat`など、Pythonによる読み取りを含める |
| リポジトリの外の読み取り | `Read`、`Glob`、`Grep`、`Bash`の対象パスが作業ディレクトリの外にあるもの |
| 応答と時間 | モデルの応答の数、変更前の応答の数、経過時間の区間（[経過時間の分解](c284-elapsed-time-decomposition-r1.md)に準じる）、応答1回あたりの最初の出力までの待ち、実行時間帯 |
| 副作用 | Sol Lowで見えた、A02の最初の読み取り量の増加と、F05範囲外ケースの`README.md`読み取りの頻度 |

ツール呼び出しの数で見た遵守と、モデルの応答の数で見たコストの経路は、分けて記録する。比較相手のC280についても、保存済みtranscriptから同じ診断を集計し、差の原因を調べる材料にする。
