# 保存済み試験結果の比較手順

保存された結果を並べ、観測された差を示す。環境、実行状況、課題、件数、単価表の一致を比較の許可条件にしない。差の原因、プロンプトの効果、優劣は数値だけから断定しない。

## 表示するもの

- 対象のプロンプト、課題、ケース、件数と、元の結果への参照。
- 保存された点数、費用、時間、トークン数、反復ごとの値と集計値。
- 採点基準、単価表、計測範囲、実行条件など、記録から分かる数値の意味と条件の違い。
- 情報がない項目は不明とし、推定で埋めない。条件が違う結果も一覧へ載せる。

点数の尺度や時間の計測範囲など、意味が対応する項目だけ差分を出す。対応が不明な項目は元の数値を並べる。反復番号や件数を合わせるために結果を捨てたり、測り直したりしない。

費用は記録された金額をそのまま示し、単価表の違いを併記する。共通の単価表での再計算は依頼された場合だけ行い、元の金額と区別する。環境や実行日時が異なることを理由に比較を停止しない。

## 通常の比較コマンド

```bash
python3 scripts/atomic_run_registry.py compare-observations \
  --input /path/to/first-analysis.json \
  --input /path/to/second-analysis.json \
  --output /new/path/observed-comparison.json
```

保存済みのatomic analysisまたは内容ハッシュ付きresultを2件以上指定する。入力記録をそのまま結果へ保持し、条件の違い・不明を別欄へ出す。上の例は一覧のみで、数値の意味を確認した項目に`--difference-metric cost_usd`などを追加すると、先頭の結果を引く側として差分を計算する。点数、費用、時間、トークン数を個別に指定できる。指定した数値が欠けていれば差分は不明として残す。

内容ハッシュの検証は、入力の改変を検出するために行う。環境や互換キーの一致を要求するものではない。入力と既存出力は上書きしない。各入力の件数、元の集計値、反復の記録は保持し、異なる条件の結果を一つの試験として再集計しない。

## 既存の厳密な比較機能

`compare`、`compare-effective`、`compare-analyses`は、互換キーなどの一致を検査する既存機能として残す。通常の結果比較の必須経路にはしない。それらが条件不一致で拒否しても、保存済み結果を並べることはできる。

既存のプール所属規則、採点、結果登録、計測条件の記録は変更しない。厳密な互換判定の実装は`scripts/comparison_identity.py`と各コマンドに残す。過去の結果・互換キー・比較成果物も書き換えない。

## 不足と追加試験

対象や数値が欠けている場合は、分かる範囲の比較と不足を示す。比較のために新しいモデル試験を自動発行しない。追加試験を依頼された場合は、モデル・内容・件数を提示して利用者の確認を得る。
