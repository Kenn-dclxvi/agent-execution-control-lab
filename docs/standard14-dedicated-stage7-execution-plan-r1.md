# STD14の開始状態の比較契約案を実装・検証する方針 第1版

必要な成果は、全14ケースの要求・維持条件・難しさを保持した低コストな評価代替に向け、開始記録の形式、実際の開始状態、判断材料の対応を別々に判定できる契約と、その保存証拠への照合結果である。対象は既存の工程2作業領域と、工程6が参照した旧第2版・専用版の各84件である。このチャットが一人で担当し、作業設定はセッションで確認した `gpt-6.1-sol / medium` を新しい記録へ結ぶ。

方法は、開始記録の必須項目・型・意味と一致を要求する境界を固定し、実行ID・ケース対応・起動入力・固定コミットの関係を保存証拠で機械照合する。容量値の差、素材の識別子の差、履歴に残る内容差分を一つの「不一致」へまとめない。全84組を照合し、旧証跡の宣言と実物が異なる場合に拒否できることを検証する。

元の実施計画では、実装・局所検証は `gpt-6.1-sol / medium`、対応の最終確認は `gpt-6-astra / high` に分かれている。今回は前者の範囲に限る。契約案と局所照合を保存するが、契約の最終受入、履歴の意味対応、全14件の同等性を最終判定しない。後者は実際のAstra Highの設定を確認してから別の判定として行う。

素材、TaskSpec、42条件、採点、モデル結果、既存の発行前記録は変更しない。過去の記録へ項目を追加しない。追加モデル実行、N拡張、実行器・CLI・外部補助機構の変更、代理担当、commit・push・PR・mergeを行わない。新しい契約は今回の読み取り専用診断と、将来の実行前の必要条件を表す。保存済みの発行前ゲートを成立させる効力を持たない。

開始履歴の差の役割が未確定なら、形式だけを修正した再測定案は採用しない。正常動作を誘導する開始許可の文言、正解の説明、成功した操作順を測定対象へ追加しない。契約の確定と、契約を満たす素材版の作成、難しさの実証、低コスト認定は別の成果として保持する。
