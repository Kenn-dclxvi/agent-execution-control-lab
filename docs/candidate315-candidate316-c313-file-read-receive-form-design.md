# Candidate315・Candidate316 C313から担当の項目を外し、ファイルの本文を判断に必要な範囲だけ受け取る形で読む

2026-10-12。利用者の判断（C313をベースにする。担当を分ける項目は外す。外した状態で、Solの長いファイルの全文取得をC312の書き方で設計し直す）を受けて、Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9と「処理方法を指定できる条件」に対応させた。計測と記録は[計測と記録の基準r2](shared-instruction-evaluation-criteria-r2.md)に従う。この記録ではbundleを作成しない。

## 目的と役割

- 系列：実行環境を切り離し、負荷を見て次のrunを始める発行の条件（CPU使用率70%以下、間隔1秒）で測る系列。プールは実効互換の規則（`effective-v1`）で作る。
- ベース：C313（`the-caption-3ce91a4-receive-form-without-plan-item-r1`）。
- 計測の順序：Sonnet lowで確かめてから、Sol Lowを測る。
- 評価は計測であり、達成目標を置かない（r2）。

| Candidate | 親 | 変更 |
| --- | --- | --- |
| C315 | C313 | 担当を分ける項目（「独立した作業を分ける場合は、開始前に担当 / 判定対象 / 必要な結果を対応づける。…」）を外す |
| C316 | C315 | 末尾に一項目を加える（項目4） |

## C315：担当を分ける項目を外す理由

Standard14では、C312でもFreeでも、両セルともサブエージェントの起動が0件で、この項目の効果も害も試験で測れない。実際の使い方での必要性から、利用者が外すと判断した。C315の計測は、C316の比較の基準を作るためのもので、この項目の効果を確かめるものではない。

## C316：この一文で何をさせたいか

ファイルの本文を、判断（変更する箇所を決める、内容を確かめる）に必要な範囲だけ受け取ること。長いファイルの全体を一度に受け取らないこと。

## 1. 比較の基準と、正常な最短経路

基準はC315。正常な最短経路は[C309の設計記録](candidate309-c307-final-check-unit-design.md)の項目1のとおり。読み取りでは、変更する箇所と、その判断に必要な定義や参照先を取得する。C313のSonnet lowは、長いファイルを、検索で位置を確かめてから範囲を指定して読んでいた（300行を超えるファイルの全文取得は0件、範囲を指定した読み取りは40回）。

## 2. 保存traceで確認した問題経路

C313のSol Low（70件）で、300行を超えるファイルの本文を、範囲を指定せずに全体で受け取った件数（行数は作業開始時点のファイル）：

| ケース | ファイル（行数） | 件数 |
| --- | --- | ---: |
| F08 | `docs/reference/system.md`（636行） | 5 / 5 |
| F04 | `App.tsx`（1,097行） | 5 / 5 |
| F02 | `v4_engine.py`（351行）、`collection_history_updater.py`（309行）、`test_v4_engine.py`（388行） | 各2 |

計16回、12run、1反復あたり約109KB（Codexは出力の上限を指定するため、実際に文脈へ入った量はこれより少ない）。[Sol Lowの費用の分析](sol-cost-element-decomposition-r1.md)で、プロンプトで減らせる最大の要素とした経路が、C313でも残っている。

## 3. 開いている記述と、TaskSpec・正本で防げない理由

C313の「事前調査は、対象と実施方法を一つに決めるために不足している情報だけに絞る」は、読む対象を絞るが、名指しされたファイルを一度に全部受け取ることを禁じない。名指しされたファイルを読むことは正常な処理なので、TaskSpecやリポジトリの正本からは、全体を受け取る経路を閉じられない。

[C304](candidate304-c301-file-read-line-cap-design.md)は「1回のツール呼び出しで、一つのファイルの本文を300行を超えて受け取らない」という行数の上限で閉じようとしたが、Sonnet lowで、300行以内の小さいファイルまで範囲を指定して分けて読む、やりすぎた適用が出た（範囲を指定した`Read`が9件から20件、同じファイルを2回以上読んだrunが3件から8件）。

## 4. 追加する条件の全件

C315の末尾に、次の一項目を加える。

> - ファイルの本文は、判断に必要な範囲だけを受け取る形で読む。

- [C312](candidate312-c311-validation-receive-form-design.md)の確認コマンドの文と同じく、禁止や許可ではなく、させたい形を書く処理方法の指定である。
- 行数の上限を置かない。C304の、小さいファイルまで分けて読むやりすぎた適用を避けるためである。判断に全体が必要な小さいファイルは、全体を読んでよい。
- 「長いファイルは、検索で位置を確かめてから範囲を読む」のような、検索の発行を求める文は加えない。発行を求める文は操作を増やす（C297）。範囲を決める方法（検索、行番号、見出し）は、モデルが選ぶ実装方法とする。

## 5. 禁止行動、開放経路、閉じる境界、反証

| 項目 | 内容 |
| --- | --- |
| 閉じる経路 | rootが、判断に必要な範囲を超えて、長いファイルの本文全体を一度に受け取る |
| 現在の開放経路 | 読み取りの量の定めがなく、名指しされた長いファイルを`cat`などで一度に受け取れる |
| 閉じる境界 | 結果の受け取り。保存traceでは、範囲を指定しない取得のうち、作業開始時点で300行を超えるファイルに対するものを数えて観測する（300行は観測の物差しで、指示には書かない） |
| 正常な処理の保持 | 変更する箇所や定義の範囲を読める。判断に全体が必要な場合は全体を読める |
| 反証する構成 | 「全体が判断に必要」と位置づけて長いファイル全体を読む構成は、文の上では違反と判定できない。この一文は判断に頼る部分を含むため、閉じた経路とは主張しない。効果は、長いファイルの全文取得の件数で観測する |

## 処理方法を指定できる条件との対応

| 条件 | 満たし方 |
| --- | --- |
| 1. 無条件である | ファイルの本文の読み取りすべてに当てはまる。ただし「判断に必要な範囲」はモデルが決める |
| 2. 遵守を観測できる | 範囲を指定した読み取りか、全体の読み取りかを、コマンドとツールの引数から判定できる。長いファイルの全体の読み取りの件数で観測する |
| 3. 遵守率を実証している | 未確認。この計測で最初に確かめる |
| 4. 正常経路を保持する | 項目5のとおり |
| 5. 汎用の形で書く | 個別のファイル名、行数、ケースを書いていない |

条件1のうち「判断に必要な範囲」はモデルの判断を含む。C312の確認コマンドの文（「判断に必要な部分の出力（末尾など）」）も同じ形で、Sonnet lowで遵守率79/81を示した。この一文も、遵守率を計測で示すまでは、高い確度の制御として扱わない。

## 6. 維持する正常経路

- 変更する箇所の取得：長いファイルは、検索や行番号で範囲を決めて読む。C313のSonnet lowが全件4点で行っていた経路である。
- 小さいファイル：判断に全体が必要なら、全体を読める。
- 指示ファイル（`AGENTS.md`）：短く、全体が判断に必要である。

## 7. 新しく増える判断と、変更対象外への影響

- 新しい判断：どの範囲が判断に必要か。
- 危険1：Sonnet lowで、小さいファイルまで範囲を指定して分けて読み、読み取りの回数が増える（C304で起きた）。範囲を指定した読み取りの数と、同じファイルを2回以上読んだrunの数で観測する。
- 危険2：Sol Lowで、範囲の取得が複数の呼び出しに分かれ、呼び出しが増える。変更前の呼び出しの数で観測する。
- 危険3：必要な箇所を読み落とし、品質が下がる。品質で観測する。
- 固定分：C315は担当の項目（257バイト）が減る。C316は一項目（89バイト）が加わる。

## 8. 評価ケース、比較単位、比較条件、記録する項目

- セル：Sonnet low、続けてSol Low。各Standard14の全14ケースN=5の計70件。C315とC316の両方を測る。
- 比較条件：C313の同じセルのプロファイルと同じで、prompt identityだけを変える。C316はC315と比べる。
- 記録する項目（r2）：品質、処理の適切さ、費用、経過時間、生のトークン（参考）。
- 機序の診断（合否にしない）：300行を超えるファイルの全文取得の件数とバイト数（項目2と同じ数え方）、範囲を指定した読み取りの数、同じファイルを2回以上読んだrunの数、変更前の呼び出し・応答の数、C312で確かめた機序（状態の確認の置き場所、確認コマンドの受け取り方、待機）が保たれているか。

## 9. 停止条件

C302の設計記録の項目9のとおり。

## 判断の限界

- 項目2の観測は、C313のN=5の一系列による。
- 見込みの大きさは、上限側で費用の約4%で、基準の揺れと同じ程度である（[C304の設計記録](candidate304-c301-file-read-line-cap-design.md)の項目7）。
