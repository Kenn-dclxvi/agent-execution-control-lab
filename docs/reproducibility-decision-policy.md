# 再現性の判断と反復の打ち切り基準

この文書は、過去のチャットで合意した反復数・追加試験の停止判断と、2026年10月1日の利用者指示を統合した共通の判断基準である。再現性を調べる際は、保存済みの実績を先に調べ、ケース・モデル・推論設定・実行条件が一致する有効な独立実行の累積Nで判断する。未観測の可能性だけを理由に、反復の追加や判断の保留を続けない。

## 共通の判断基準

測定前に、何の再現を確認するかを一つに定める。期待する正常動作の再現、特定の失敗の再現、モデル間の動作差の再現を混同しない。

| 累積有効N | 再現対象が一度も観測されなかった場合の判断 | 追加実行の扱い |
| --- | --- | --- |
| 5 | 対象条件で再現性なしと判断する。単発の可能性を理由に結論を保留しない | 自動延長しない。実際に確認済みの低頻度経路、条件差の切り分け、または利用者が求める追加確認がある場合だけ20までの計画を固定する |
| 20 | 再現する可能性は低いと判断し、通常の確認を打ち切る | さらに確認する具体的な理由がある場合だけ、次の累積上限を50へ固定する。判断が変わる成果と理由を実行前に記録する |
| 50 | それ以上の同条件反復でも再現しないものとして扱い、再現確認を終了する | 可能性への一般的な懸念で50を超えて延長しない。別条件の調査や、利用者が明示した別の目的の試験とは分ける |

ここでいう「再現性なし」「再現する可能性は低い」「それ以上でも再現しない」は、研究と実務を進めるための運用上の判断である。未観測の確率が数学的にゼロである証明を求めて、上記判断を留保してはならない。

期待する動作を全件保持することが目的なら、有効な一件の反例でその条件の全件保持を否定できる。特定の失敗が実際に起きたかを調べる場合も、一件の観測で発生の事実は確定する。その事実を「ゆらぎかもしれない」と未確認へ戻さず、頻度の確認と原因の切り分けを別の課題として扱う。反復数の不足を理由に、すでに観測した不成立の判断を延期しない。

## Nの数え方と実行前の固定

- Nは一つのケース・一つの条件についての、有効な独立実行の累積件数とする。N=5から20は不足15件、20から50は不足30件だけを追加する。
- 保存済みの互換する実行を再利用する。同じ実行IDの再掲、別ケース、別モデル、別推論設定、別CLI、別fixture、別TaskSpec、別採点契約を合算しない。
- 実行環境の不備、除外された試行、採点不能を、有効な失敗や成功の件数へ混ぜない。有効な低得点は削除せず、自動再試行で置き換えない。
- 観測対象、開始時の累積N、追加理由、追加上限、判定条件、停止条件を発行前に固定する。N=5・20・50を必ず全て実行する計画ではない。
- 再現性について説明する前に、関係する保存結果・設定・実行IDを調べる。既存実績を確認せず、未観測のゆらぎや低頻度失敗を追加測定の理由にしない。
- この文書はモデル軸の別測定、互換条件の事前照合、ケース固有の品質gate、既存アーティファクトの履歴保持を変更しない。

## チャットで確認した合意

試験結果の回数だけでなく、利用者の直接の発言と、それに続く応答を確認した。[発言日時・話者・チャットID・原文の所在](reproducibility-decision-chat-evidence-r1.json)へ根拠を固定する。以下の日時は日本時間である。

| 会話日時 | 利用者の発言 | 合意の内容 |
| --- | --- | --- |
| 2026年7月15日21時台 | 「5回で進めて」 | 各ケースN=5で開始する提案への承認 |
| 2026年7月31日13:00 | 「今後は試験の試行回数はNで統一しよう。今回はN20ってことね。」 | B20という表記と100回相当の旧用法を区別し、その試験を累積N=20と固定 |
| 2026年8月3日19:57 | 「C145を実施して50まででいいよ。これから100との互換は50まで見て判断できるかを見極めたい。」 | 累積N=50までで判断し、N=100を自動的に要求しない |
| 2026年8月3日21:47 | 「C143→C147はすでに今の試験で判断されているのだからそれを覆す可能性があるもの以外はこれ以上の試験はしないよ。」 | 既に判断できた内容について、判断を変えない追加試験をしない |
| 2026年8月3日22:20 | 「じゃぁ試行回数を増やすのはここまでだね。」 | 応答でN=50終了・N=100へ進まないことを確認。22:22には追加整理も不要と訂正し、その論点を終了 |

したがって、「N=50で止める」「現在の判断を覆し得ない試験を追加しない」は、今回初めて作った方針ではなく、過去の会話で確認済みの合意である。この根拠を確認する前に、新しい方針としてだけ説明した点を訂正する。

なお、7月30日の応答には失敗率と信頼度から59・99・299件を提案した箇所もあるが、直後に利用者が「そういう話じゃない」と訂正している。この提案を承認済みの反復基準として採用しない。上記の各合意と、今回明示された5・20・50での未再現判断を区別したうえで、同じ運用方針へ統合する。

## 小規模A01への適用

[保存履歴全体の再調査](compact-latent-mode-historical-free-audit-r1.md)で、旧Free Astra lowのA01は有効N=5で、確認前の編集・試験は0件だった。その旧条件では、この誤経路に再現性なしと判断する。

[今回の小規模版](../evaluations/targets/compact-repository-control/results/free-astra6-low-latent-mode-code-n2_2026-10-01.md)では有効N=2で、確認前の編集・試験が2件観測された。旧条件の停止動作を保つ代替としては不成立であり、判断のために5回まで追加する必要はない。小規模化とCLI等の変更のどれが原因かは別の切り分け課題とし、ゆらぎを理由にこの観測差を留保しない。

採点上の0点と実際の動作は分ける。テストのみを行った実行を、未指定のmodeを推測して編集した実行と同じ要求違反にはまとめない。保存済み得点と履歴は変更しない。
