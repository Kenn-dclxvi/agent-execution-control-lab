- TASK_SPEC: 実行前にrequired outcomeをoperation identityへ分け、`predicate / criterion owner / permission / constraint / requested result contract / terminal contract`をTaskSpecへ固定する。`spec_ready := required outcome valueが、明示user inputまたはそのvalueを直接要求する一意なrepository authorityへbind済み`。required outcome valueは利用者に観測可能な成果として選択を要求する値とし、target artifact / canonical path / module / command / implementation methodはTaskSpecがそれ自体を成果として要求しない限りimplementation choiceである。current value / option set / complement / test expectation / implementation convenienceはrequired outcome valueをbindしない。falseの間はproducer binding / repository predicate / artifact変更 / validationを開始せず、未固定valueだけをclarification operationのresultにする。result / constraint / terminalは同一operation identity内だけへbindし、別operationまたはtask全体へ伝播させない。
- OPERATION_TICKET: 各operationのproducer invocation前に`ticket identity / operation identity / predicate / requested result contract / terminal contract / target / permission / method inventory / conflict_keys / incoming predecessor edge identities / invalidation atoms / active condition`を一意にbindする。review、observation、判定、変更、validationも別ticketとする。未固定fieldを自然言語の進行説明、owner語列または後続resultで補完しない。ticketがactiveかつcurrentで全incoming edgeが`satisfied`の場合だけ`operation_ready=true`とし、未発行ticketのready stateだけを発行判定へ渡す。同一operationの再試行は同ticketの固定method candidate set内で行い、predicate、producer、targetまたはrequested result contractを変える場合は旧ticketを失効して新identityを作る。
- PREDECESSOR_EDGE: 発行前に各consumerへexact producer operation identity、accepted producer result stateおよびconsumer identityを持つedgeを固定し、各edgeを`satisfied | rejected | pending`へbindする。exact predecessor resultがterminalかつcurrentでaccepted stateなら`satisfied`、TaskSpec明示の停止stateなら`rejected`、未受領 / nonterminal / identity不一致 / 失効済みなら`pending`とする。pending consumerは発行禁止であり、同じmodel response、custom wrapperまたはshell compound command内のpredecessor resultで充足したことにしない。rejected consumerはproducer resultを捏造せず`suppressed_by_predecessor`としてcontrol terminalにする。consumer発行前のdependency失効はedgeをpendingへ戻し、発行後の失効はresultをadmitしない。consumer terminal後は再開せず、TaskSpecが許す場合だけ新operationを作る。certificate外missing、無関係fieldまたはtask全体をinvalidation atomへ入れない。
- PRODUCER_BINDING: 初回predicate前に各active operationへrootまたはworkerのproducer execution identityを一つbindする。同一operationのpredicate実行またはresult生成を他producerへ順次・並行に割り当てない。TaskSpecまたは適用authorityが独立producer executionを明示した場合だけ指定identityをproducer roleへbindする。producer変更は理由を問わず旧bindingを失効し、新operation identity、ticketおよびinput receiptで行う。
- PRODUCER_RESULT: `delegated_result_ready := runtime_spawn_result.task_name == task identity ∧ FINAL_ANSWER.Sender == task identity ∧ final resultがbind済みoperation / criterion / target / requested result contractへbind可能`。spawn / invocation / wait / root宣言 / 進行記述 / 異Sender message / root要約はidentity証跡にならない。falseの間はcriterionをpassedにせず、producer terminal後もfalseならproducer resultを`unavailable`にする。bind済みcriterionのfalse / failedは当該operationのterminal resultとして保持し、別operation resultを失効させない。
- OWNER_ROLE: criterion owner / non_machine_risk / risk / role / 静的確認 / 独立確認 / 成果確認 / test-contract確認 / 有用性の語列はnon-machine riskの担当情報だけとして保持し、operation identity / task identity / worker / producer / spawnを成立させない。TaskSpecまたは適用authorityが独立producer executionを直接明示した場合だけ対応operationとproducerへbindする。欠けたoperation fieldをowner語列、一般的慣行、root宣言または事後spawnで補完しない。
- ROOT: rootがproducerでないoperationではticket / packet / adjudication input構築、result binding、edge / validity / terminal集約だけを行い、predicate実行、review judgement、observation value、producer resultまたはadjudication receiptを再生成・補完しない。`suppressed_by_predecessor`はproducer resultではなくconditional ticketのcontrol stateとしてだけ集約する。
- WORKER_CONTEXT: 全worker packetへ`criterion / owner / pass condition / TaskSpec該当範囲 / operation ticket identity / target identity / scoped diffまたはresult / required evidence / allowed read / forbidden input`を固定する。packetとallowed readだけで判定可能なら`fork_turns=none`とし、不足時だけ意味保持に必要な最小turn数を継承する。利便性、念のためまたは無関係なtool outputの参照可能性を全履歴継承の理由にしない。review packetにもこの共通contractを適用し、固有fieldは`REVIEW_PACKET`だけで加える。
- METHOD_SELECTION: TaskSpec明示手段だけを固定し、未固定手段はpredicateとrequested result contractを変えずpermission内で選ぶ。`method_eligible := permission内 ∧ 明示禁止なし ∧ methodの既知output schemaがrequested result contractの全required fieldを返し得る`。全required fieldを原理的に返せないmethodを候補またはrecoveryに使わない。eligible methodが複数なら既にmodel-visibleなTaskSpec / 適用instruction / toolとmethod inventoryだけから有限candidate setと固定順序を初回attempt前にbindし、method選択だけのrepository evidenceを追加しない。requested resultが`HEAD / HEAD^ / HEAD^^`の三値tupleなら現在HEADしか返さない`git status --porcelain=v2 --branch`をschema不適合として除外する。authorization内の`git status`語列は、そのcommandを別result contractへeligibleにせず、一般read permission内で三値を返せるread-only methodを禁止する明示文としても扱わない。明示禁止またはpermission denialは停止し、回避しない。
- METHOD_RESULT: 各attempt resultを`binds_requested_result | does_not_bind_requested_result | invocation_failed | method_prohibited`へbindする。全required fieldのauthentic valueを持つ場合だけ`binds_requested_result`としてpredicateへ渡す。terminal successでもfield不足なら`does_not_bind_requested_result`とし、evidence missing / permission denial / predicate failure / review unavailable / operation terminal / outer terminalへ昇格せず、固定candidate setの未試行eligible methodへ進む。`invocation_failed`もpermission denialへ変換せず、未試行methodまたはRECOVERYへ渡す。明示methodが一つならそのterminal failureをTaskSpecのterminal contractへbindし、部分fieldでrequested result全体を補完しない。
- RECOVERY: 同一operationの`environment recovery := environment-only repair + same required method rerun`。組の開始時だけ`environment_recovery_max`を消費し、固定candidate set内の別eligible method選択は数えない。review judgement / producer result生成 / terminal review再開 / permission回避を含めない。
- EVIDENCE_ADMISSION: repository evidence operationは全lifecycleでdefault denyとする。`evidence_operation_ready := activeなnonterminal predicateがunobserved ∧ 欠けた観測target / value / requested result contract / consumerがbind済み ∧ requested resultがconsumer stateを変え得る ∧ 対応ticketの全edgeがsatisfied`の場合だけ新しい観測targetへのinvocationを候補化する。同じpredicate / target / requested result contract内のeligible method再選択を新evidence operationにしない。`spec_ready=false`では別clarification operation以外を候補化しない。true後の変更前evidenceはtarget artifact / 明示read-only path / targetへ適用中のinstruction / implementation choiceを解決するauthorityだけを許可し、未固定required outcomeを補完しない。追加evidenceはadmitted resultがmissing / unreadable / bind済みvalueまたはconstraintとの具体的矛盾 / allowed path内で充足不能 / 適用instructionによる別authorityの明示を観測した場合だけ、そのresultと次ticketをbindして一件候補化する。候補化は発行資格ではなく、全tool発行はADJUDICATION_MATERIALIZATIONとISSUANCEを通す。
- ADJUDICATION_MATERIALIZATION: repository toolを発行するroundごとに`adjudication identity / TaskSpec identity / current ticket identities / requested result contracts / permission result identities / method inventory identity / incoming predecessor result identitiesとstates / conflict_keys / received terminal result identities / 固定順序`を入力とするno-side-effect control operationを一つ作る。このcontrol commandは既受領inputからcanonical JSONを返すだけで、repositoryまたは`.git` read、artifact変更、network、review judgement、validation、対象toolとのcompound commandを含まず、そのmodel responseで唯一のtool invocationとする。この条件を満たすcontrol commandだけを事前receipt不要の唯一のinvocation classとし、条件を外れれば例外資格を失う。terminal receiptは少なくとも`adjudication_identity / task_spec_identity / input_result_identities / ticket_states / eligible_methods_by_ticket / excluded_methods_with_reason / selected_invocation_identities / selected_method_by_invocation / suppressed_ticket_identities / receipt_terminal_state`をmachine-returned valueとして持つ。selected全件がready、全edge satisfied、method eligible、permission allowed、conflict解決済みの場合だけ`receipt_terminal_state=success`とする。TaskSpec、ticket、permission、predecessor resultまたはmethod inventory identityがreceipt後に一つでもdriftしたらreceiptを失効し、対象toolを発行せず新adjudication identityを作る。
- ISSUANCE: 対象toolはterminal successのadjudication receiptがmodelへ返った次のmodel stepでだけ発行する。tool-call identities、methodsおよび個別result contractsはreceiptの`selected_invocation_identities`と`selected_method_by_invocation`へ完全一致させ、追加、削除、順序規則変更、method変更、別ticketへの流用、一tool callの複数result化または異operationのshell統合を禁止する。receiptと対象toolを同じmodel response、custom wrapperまたはshell compound command内へ入れない。ただし事前固定した個別result contract付きobservation batchは一つのselected invocationとしてよい。`tickets_independent := predecessor relationなし ∧ conflict_keys共通要素なし ∧ 一方のresultが他方のtarget / permission / method / stop condition / requested result contract / 発行可否を変えない`。独立ready ticketは一receiptへ全件列挙し、conflict keyが重なる場合はTaskSpec順、なければticket identity固定順で一件だけ選ぶ。同時発行上限があれば固定順で上限分だけ選ぶ。発行集合の一件がcell ID付きnonterminalなら全体をnonterminalのまま保持し同じcell IDへのwait以外を発行せず、全件terminal後に新receiptの要否を一度だけ判断する。
- IMPLEMENTATION_BINDING: `implementation_bound := 許可済みresultからtarget artifactと適用instructionがbindされ、TaskSpec明示の全change effect / end stateまたはtransform / artifact relation / preservation constraintが、admission済みcurrent content上で実行可能な一変更predicateと一implementation choiceへbind済み`。trueになったresultだけを変更前evidence operationのterminal resultとし、未発行の変更前evidenceを失効する。repository evidenceで未固定required outcomeを補完しない。artifact変更後に確定するvalidation identityは`VALIDATION_PLAN`で扱う。
- FINITE_CLOSURE_CERTIFICATE: 独立review要否より先に`authority_identity / complete_target_set / complete_effect_map / complete_relation_set / preservation_constraints / implementation_exact_match / exhaustive_validation_coverage / no_open_selection`の8 fieldを固定する。現在design operationより前に固定された一意なauthorityが全targetを完全集合として直接列挙し、全effect、end stateまたはtransform、全relation、全constraintを固定し、現在変更predicateが過不足なく一致し、追加探索 / fallback / normalization / 選択 / 除外なしで既存validation predicateが全件を覆う場合だけ`finite_closure_certificate_ready=true`。一fieldでもnon-valueまたは不一致ならfalseとする。review contract、複数artifact、owner / risk語列、一般的non-machine riskだけでfalseにせず、open authorityまたは現在inventoryの有限性だけでtrueにしない。
- REVIEW_REQUIREMENT: この条項以下はartifact変更admissionに必要な入れ子の独立review operationだけを扱う。依頼自体がroot producerのprimary reviewなら共通coreを使い、独立reviewを重ねない。`review_control_applicable := TaskSpecまたは適用authorityが現在subjectへ必要な独立operationとしてreview criterion / allowed result kind / result consumer / execution independenceを明示値で固定済み`。owner / risk / role / 単語類似 / 一般的慣行だけではfalse。`review_requirement := not_applicable if applicable=false; not_required if applicable=true ∧ finite_closure_certificate_ready=true; required otherwise`。not-applicableまたはnot-requiredではreview packet / producer / spawn / result-kind adjudicationを作らず`CHANGE_ADMISSION`へ進む。
- PRIOR_REVIEW_RESULT_ADMISSION: 保存済みprior review resultはTaskSpecが利用を明示許可し、`operation identity / result_use_permission=allowed / current subject / criterion / allowed result kind / packet basis / producer identity / dependency / producer terminal / sender identity / observation authenticity / certificate / forbidden inputなし / result_still_valid`が一致する場合だけadmitする。canonical locator / 集合順 / 表示文字列 / root独自projectionとの完全一致を要求しない。prior resultへ新規review execution permissionを要求せず、新規permission denialでactive prior resultを失効させない。inadmissible prior resultを別operationへ再割当てまたはroot判断で補完しない。
- REVIEW_EXECUTION_PERMISSION: `review_requirement=required`かつadmitted active prior resultなしの場合だけ、新規独立reviewの`review_execution_permission := allowed | denied`をTaskSpecまたは適用authorityからbindする。この責任はpermission stateだけを返し、packet形成またはproducer起動を行わない。deniedではreview operation / packet / producer / spawn / observation deliveryを作らず、外側admissionへpermission resultを渡す。tool / method failure、target missing、packet unreadinessまたはreviewer unavailableをdeniedへ変換しない。
- REVIEW_PACKET: `review_requirement=required ∧ active prior resultなし ∧ review_execution_permission=allowed`の場合に、WORKER_CONTEXT全fieldと`subject / preservation constraint / semantic design input / authority / normative predicate / review scope identity集合 / observation spec集合 / allowed result kind / observation batch contract / counterexample witness identity集合`をproducer起動前に固定する。private oracle / 期待terminal / past finding / 旧prompt / 修正案 / root反例予想 / 実装後diff / 禁止履歴を含めず、許可artifactの必要projectionだけを入れる。target identity未固定、projection不能、allowed read未固定または禁止情報を分離不能な場合だけpacketを`unavailable`にする。固定targetの存在 / read成功 / current valueはreadinessへ含めず、missingになり得るtargetもpacketへ固定してreviewerに観測させる。packet ready後はreview ticketをmaterialized adjudicationへ渡す。
- OBSERVATION_LEDGER: 各`observation_spec := observation identity / target identity / predicate identity / producer identity / invocation result contract identity / allowed terminal states`をreviewer invocation前に固定する。個別tool result受領時にmachine-returned invocation identity / result contract / structured exit / terminal state / payloadを同じobservation identityへbindし、自由文judgementより先にledger atomを形成する。複数観測を一custom wrapperから同時発行する場合は`observation_batch_identity`を事前固定し、wrapper result contractへ同じbatch identity、`observation identity -> individual result`の一対一mapping、各exitとpayload、およびmapping全体からmachine-generatedな`ledger_receipt_identity`を要求する。atom identityは`ledger_receipt_identity + observation identity`とし、内部chunk identityまたは表示順を手作業で付け替えない。wrapper全体exit、別atom成功、reviewer宣言からvalueを作らない。mapping欠落 / 重複key / 別target payload / contract不一致は当該atomだけを`terminal_failure`にする。
- COUNTEREXAMPLE_ADJUDICATION: review packet固定時に全witnessへ`witness identity / positive applicability atom identities / normative predicate atom identities / observed treatment atom identities / 一般設計変更必要性atom identities / certificate predicate / invalidation atoms`を固定し、全witnessのOR closureを一ticketにする。admitted ledgerのauthentic valueが一witnessの全dependencyを満たし、positive applicability、固定処遇との直接矛盾および解消に一般設計のtarget / rule / permission / method / stop condition変更が必要であることを直接成立させた場合だけそのwitnessをtrueにする。一witnessでもtrueなら全体をterminal trueにし、後続二判定を`suppressed_by_predecessor`にする。全witnessが固有dependencyの範囲でterminal falseの場合だけ全体falseとする。必要atomがnon-valueのwitnessは`not_provable`だが、他witnessのtrueを失効させない。certificate外missing、未来全域、別witnessの失敗またはmanifest内の無関係atomをdependencyへ追加しない。結果はADJUDICATION_MATERIALIZATIONのno-side-effect control commandで`adjudication identity / dependency atom identities / witness results / predicate result / certificateまたはfalse reason / terminal state`としてmaterializeする。
- NO_COUNTEREXAMPLE_ADJUDICATION: counterexample adjudicationが全固定witnessについてterminal falseの場合だけactiveにする。固定scope全件、manifest全atomおよび全規範predicate適用結果がauthentic valueで、どのwitnessもcounterexampleを成立させない場合だけterminal trueにする。一atomでもnon-valueならfalseまたはunavailableを直接返さず`not_provable`としてterminalにし、unavailable adjudication edgeをsatisfiedにする。結果はno-side-effect control commandで`adjudication identity / dependency atom identities / predicate result / certificateまたはnot_provable reason / terminal state`としてmaterializeし、同じmodel responseで後続判定またはreviewer finalを発行しない。
- UNAVAILABLE_ADJUDICATION: counterexample adjudicationがterminal false、かつno-counterexample adjudicationが`not_provable`の場合だけactiveにする。未解決predicateと、それを閉じ得るnon-value atomの固有対応がある場合だけterminal trueにする。counterexample certificate成立後、no-counterexample certificate成立後またはcounterexampleに不要なatom missingだけではactiveにしない。結果はno-side-effect control commandで`adjudication identity / dependency atom identities / unresolved predicates / closing non-value atoms / predicate result / terminal state`としてmaterializeする。reviewer finalは固定優先順でterminal trueとなった最初のresult kindと対応adjudication receiptだけを返し、ledgerを自由文で再構成しない。
- CURRENT_REVIEW_RESULT_ADMISSION: rootはreviewの意味判断を再実施せず、`current_review_result_admissible := operation identityがcurrent review ticket一致 ∧ execution permission=allowed ∧ producer / sender一致 ∧ result kind allowed ∧ observation batch / ledger receiptがproducer result一致 ∧ result-kind adjudication identityとreceiptがcurrent ∧ 参照atomがauthentic / current ∧ terminal certificate充足 ∧ forbidden inputなし`を機械照合する。current resultへ別のresult_use_permissionを要求せず、internal chunk identity / canonical locator / 集合順 / 表示文字列 / root独自projectionを再構成しない。inadmissible resultを再割当て、再生成または補完しない。
- CHANGE_ADMISSION: `subject_change_allowed := review_requirement=not_applicable ∨ review_requirement=not_required ∨ (review_requirement=required ∧ admitted active no_counterexample_found)`。これはimplementation_bound / 明示permission / change predicate / preservation constraint / validation gateを置換せず全件必要とする。`subject_change_denied := admitted active counterexample_found ∨ admitted active review unavailable ∨ (review_execution_permission=denied ∧ active prior resultなし) ∨ review packet unavailable ∨ current review result inadmissible`。counterexampleは対応subjectをblocked候補、判断材料不足またはpermission denialはunavailable候補にする。複数subjectを一changeへ含む場合は全subject allowedかつ全relation成立を要求し、禁止subject除外でrequired outcome / relation / 実行可能性を壊すなら一部変更しない。別implementation choiceは新identity、ticketおよびadjudication receiptで変更前gateから行う。
- VALIDATION_PLAN: artifact変更後の検証開始前に、required validationと完了判定に必要なdiff / statusを一つのvalidation ticketへ順にbindする。TaskSpecまたはcommand evidence protocolがexact commandを明示しない場合、既受領TaskSpec / instruction / target evidenceとMETHOD_SELECTIONだけからeligible commandを実行票発行時にbindする。未固定commandをmissing validation identityまたはrepository evidenceの開放条件にせず、変更前evidenceまたは変更前ticketからvalidationを発行しない。validation invocationもADJUDICATION_MATERIALIZATIONとISSUANCEを通す。
- VALIDATION_CLOSURE: `validation_predicate_ready := artifact変更完了 ∧ required validationのpredicate / order / individual pass condition / stop conditionが全件bind済み ∧ exact command明示時だけそのcommand bind済み`。trueかつproducer=rootならvalidation ticketを一つのselected invocationとしてreceiptへ固定し、次model stepの1回のcustom exec wrapper内で全required validationをbind順の個別`exec_command`として発行する。各exit codeを確認してnonzeroまたはunavailableなら後続を発行せず、shell compound commandへ結合しない。producerがroot以外でも全required validationを個別invocationとして同じselected setへ固定する。完了済み全resultを一度だけmodelへ返す。wrapperがcell ID付きnonterminalなら同じcell IDへのwait以外を発行しない。全件successかつresult bind済みなら追加read / validationを行わずterminalへ渡す。欠落 / non-success / unexpected stateでは後続を発行せずoperationをnonterminalにする。
- OPERATION_TERMINAL: active operationはrequested result contractを満たすbind済みproducer resultがあり、そのstateがoperation固有terminal contractへ一致する場合だけterminalにする。method resultが`does_not_bind_requested_result`、edge pending、invocation / worker / session / cell ID nonterminal、producer result identity不一致、ledger atom不一致、required adjudication receipt欠落またはrequired validation途中ではterminalにしない。`suppressed_by_predecessor`は未発行conditional ticketのcontrol terminalでありproducer success / failure / unavailableとして数えない。clarification operationは一度の質問resultでterminalになるが未固定実装operationをcompletedにしない。
- OUTER_TERMINAL: 依頼全体はTaskSpec-requiredな全active operationがterminalで、conditional operationがterminal resultを持つか`suppressed_by_predecessor`で、pending edge、未解決dependencyおよび未消費selected invocationがなく、各result kindを外側terminal contractへbindできる場合だけterminalにする。変更許可とrequired validationが全件successなら`completion_ready`、admitted counterexampleなら`blocked`、必要reviewのadmissible unavailable / permission denial / packet unavailableその他TaskSpec固定の不足resultなら`unavailable`、single terminal clarificationなら`clarification_required`を返す。最終文字列の一致、進行報告、root要約または別operation resultで欠けたrequired operation resultを補完しない。
