# Candidate300 C298とC299の二項目をC280へ同時に加える

2026-10-09。利用者の依頼（C298とC299を組み合わせて測る）を受けて、Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9に対応させた。判定は[判定基準の記録](shared-instruction-evaluation-criteria-r1.md)に従う。各項目の設計の根拠は[C298の設計](candidate298-post-validation-success-command-closure-design.md)と[C299の設計](candidate299-no-short-wait-time-design.md)にあり、この記録はそれらを繰り返さず、統合で新しく生じる点だけを記す。この記録ではbundleを作成しない。

## 目的と役割

- 系列：汎用指示の改善系列。比較の基準かつ直接の親はC280（`the-caption-3ce91a4-execution-control-outcome-binding-r1`）。C298とC299は、加える文の原文の出所であり、親ではない。
- 位置づけ：設計原則は、一つのCandidateで一つの局所的な機序だけを扱うとし、個別に行動差を確かめた文は統合できるとする（C148〜C163の知見）。C298とC299は、それぞれ同じ比較条件で単独に測り、閉じる対象の応答の減少を確かめた。C300は、その二つを統合したときに、効果が足し合わされるか、互いに打ち消すかを確かめる。
- 主なセル：GPT-6.1 Sol LowとClaude Code Sonnet 5.5 low。
- 必要な効果：品質を保ち、両セルでC280よりトークンを増やさない。経過時間は保存済みC280との比較を参考として記録する。
- 変更対象：root `AGENTS.md`の末尾に、C298の一項目（132バイト）とC299の一項目（117バイト）を、この順で原文どおり加える。C280の本文と他の18対象はC280とバイト一致を保つ。全文は1,719バイト（C280は1,470）。

## 4. 追加する条件の全件

C280の末尾に、次の二項目をこの順で加える。

> * 必須の確認コマンドがすべて成功した結果を受け取った後は、コマンドを発行せずに報告する。
> * コマンドの実行とその終了待ちで、ツールの既定値より短い待機時間を指定しない。

どちらも既存の操作の発行またはパラメータを禁止・限定する文であり、新しい操作の発行を求めない。文言は単独の計測と同じにし、統合のために書き換えない。

## 5. 禁止行動、開放経路、閉じる境界、反証

各項目の対応は、C298とC299の設計記録の項目5のとおり。統合で新しく確かめる点は次のとおり。

- 二つの文は、別の経路（成功後のコマンドの発行と、終了待ちの待機時間）を閉じ、互いの禁止の範囲は重ならない。
- C299で待機時間を既定値以上にすると、Sol Lowでは必須の確認の結果が一度で返りやすくなる。成功の結果を受け取る時点が明確になるため、C298の禁止の適用を妨げないと見込む。
- 片方の文に従うために、もう片方の禁止する操作が必要になる構成はない。

## 7. 新しく増える判断と、変更対象外への影響

- 新しい判断：統合による新しい判断はない。
- 固定分：249バイト。Sonnet lowで1反復あたり約5.2千トークン（249×0.3247×64.6）、Sol Lowで約7.4千トークン（249×0.34×88.0）の見積もり。
- 見込み：効果が足し合わされる場合、Sol Lowでは、成功後のコマンドと待機の両方の応答が減る。ただし、C298単独のSol Lowでは、待機と状態確認を同じ応答に出す回数が増えており（1.6回→2.6回）、C299でその待機が消えれば、両方の削減は一部重なる。Sonnet lowでは、C298の効果（残った一部の応答）と、C299の固定分だけが加わる。
- 危険：二項目を並べることで、どちらかの文が目立ち、単独のときと違う受け取られ方をする。各項目の閉じる対象の応答の数を、単独の結果と並べて観測する。

## 8. 評価ケース、比較単位、比較条件

- セル：Sol LowとSonnet low、各Standard14の全14ケース各N=5の計70件。
- 基準：各セルの保存済みC280（Sol Low `794d02abe894456686eea22e9b6f0fed`、Sonnet low `c84fd22753d248e588e586cb8022ea1e`）。単独のC298とC299の結果は、診断の比較に使う。
- 比較条件：C293〜C299と同じ。変えるのはprompt identityだけ。発行前にpreflight receiptを保存し、不一致があれば一件も発行しない。
- 判定：品質を保ち、各セルで全エージェントトークン中央値がC280より減った場合を主な判定とする。経過時間は参考に扱う。セルの間で相殺しない。
- 診断（合否にしない）：必須の確認を含む最後の応答より後の応答の種類と数（C298と同じ方法）、待機だけの応答と待機時間の指定（C299と同じ方法）、応答数。

## 9. 停止条件

- 互換条件の不一致、未確認があれば、一件目の発行前に停止する。
- invalid、採点不能、品質の低下は、有効な改善として扱わない。外部失敗だけ、同じ枠で固定上限内に再試行する。有効な4点未満は削除、相殺、再実行しない。
- 各セル70件で判断し、自動で追加反復しない。結果に合わせてこの記録と案文を書き換えない。
