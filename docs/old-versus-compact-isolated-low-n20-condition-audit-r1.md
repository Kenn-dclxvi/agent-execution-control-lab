# 個人指示を除外した旧素材と小規模r4のLow N20条件監査

旧素材20件と新試験r4の20件を、実行ID・rollout・起動記録・固定素材で照合した。[証拠JSON](old-versus-compact-isolated-low-n20-condition-audit-r1.json)を正とする。追加モデル実行は0件。

## 結論

個人指示除外とCLIが同じであることをもって、旧素材と小規模版の比較条件が揃ったとはいえない。両者の現在環境N20では基本指示・起動引数・提供スキル文脈・権限・モデル・Low設定は一致していた。一方、TaskSpec、階層別repository authority、依存環境、対象実装とテスト、Gitの開始状態、実行群の構成には差があった。従って停止10件と3件の差を、素材の容量削減だけの影響へ帰属させない。

## 全40件で一致した条件

実行ごとのworkspace・home・終了文の保存先だけを置換した上で、CLI起動引数、developerメッセージ全文、初期environmentメッセージ全文が全件一致した。基本指示のSHA-256も全40件で同一。モデルはgpt-6-astra、推論low、summary=none、personality項目なし、workspace-write、approval never、network_access=falseで一致した。全40件で個人指示ブロックなし。固定モデル一覧の開始時ハッシュも同じだった。個人指示を戻す必要はない。

## 先の結果説明の訂正

「個人指示を除外しても動作差が残った」は両条件で観測した内訳の説明として保持する。しかし、それを「旧試験の判断条件を揃えて縮小版だけを測った結果」と読むことはできない。小規模r4内の既存2件と追加18件の互換照合は、旧素材との完全互換を証明していない。

今回の各N20の実行と得点は、その実効入力での記録として保持する。どの差が停止・試験先行・推測編集を変えたかは、差をまとめて変えた今回の測定では分離できない。素材縮小の因果を判断する前に、元TaskSpecの意味と配送形式、必要なauthority、対象Python環境を保持する境界を決める必要がある。個人指示の除外は引き続き維持する。新たな停止義務を追加したり、成功動作を手順へ転記したりしない。
