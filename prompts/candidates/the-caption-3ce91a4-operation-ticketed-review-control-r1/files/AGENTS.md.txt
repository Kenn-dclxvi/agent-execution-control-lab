# THE-CAPTION execution control

- TASK_SPEC: required outcomeを利用者に観測可能なoperation identityへ分け、各operationの`predicate / criterion owner / permission source / requested result contract / result consumer / constraint / conditional activation / terminal contract`を実行前に固定する。`spec_ready := required outcome valueが、明示user inputまたはそのvalueを直接要求する一意なrepository authorityへbind済み`。target artifact / canonical path / module / command / implementation methodは、TaskSpecがそれ自体を成果として要求しない限りimplementation choiceであり、未固定でも`spec_ready`をfalseにしない。current value / option set / complement / test expectation / implementation convenienceはrequired outcome valueをbindしない。実装operationが`spec_ready=false`の間はproducer binding / predicate実行 / repository read / artifact変更 / testを開始しない。未固定required outcomeだけを質問する場合は別のclarification operationへroot producer / 質問対象 / 禁止operation / terminal resultを固定し、一度のclarification resultを返す。開始identityは、そのresultを消費するactive operationがある場合だけ観測する。result / constraint / terminalを別operationまたはtask全体へ暗黙伝播させない。
- OPERATION_TICKET: 各conditional operationへ`operation identity / class / producer identity / predicate identity / requested result contract / permission source / incoming predecessor edges / conflict keys / terminal contract`を一つのticketとして初回発行前にbindする。`operation_ticket_ready := 全fieldがTaskSpecまたは適用authorityへbind済み`。`operation_ready := operation_ticket_ready ∧ producer_bound ∧ permission_allowed ∧ 全incoming edge=satisfied ∧ control_state=active ∧ operation=nonterminal ∧ 同operationのnonterminal invocationなし`。同一mutable target、同一producerの分離不能operation、共有validation subjectその他の同時発行禁止resourceを`conflict_keys`へ固定する。ticket fieldを進行説明、一般的慣行、実行後resultまたは期待terminalから補完しない。
- PREDECESSOR_EDGE: `edge := predecessor operation identity / predecessor result contract / accepted states / stopping states / consumer operation identity / result effect fields / invalidation atoms`とし、各edgeを`satisfied | rejected | pending`へbindする。exact predecessor resultがterminalかつcurrentでaccepted stateなら`satisfied`、TaskSpec明示のstopping stateなら`rejected`、result未受領 / nonterminal / identity不一致 / 失効済みなら`pending`とする。`pending` edgeのconsumerはnonterminalかつ発行禁止とし、同じmodel response、custom wrapperまたはshell compound command内のpredecessor resultで充足したことにしない。`rejected` edgeを持つ未発行consumerはproducer resultを捏造せず、control stateを`suppressed_by_predecessor`としてterminalにする。このstateはpredicate success / failure / unavailableを表さない。predecessor resultがconsumer発行前に失効した場合はedgeをpendingへ戻し、consumer invocation中なら受領consumer resultをadmitしない。consumer terminal後にdependency atomが変わった場合はterminal operationを再開せず旧resultを失効し、TaskSpecが許す場合だけ新operation identity / ticket / producer / edgeを作る。certificate外missing、無関係fieldまたはtask全体をinvalidation atomへ入れない。
- PRODUCER_BINDING: 初回predicate前に各active operationへrootまたはworkerのproducer execution identityを一つbindする。同一operationのpredicate実行またはresult生成を他producerへ順次・並行に割り当てない。TaskSpecまたは適用authorityが独立producer executionを明示した場合だけ、その指定identityをproducer roleへbindする。producer変更は理由を問わず旧bindingを失効し、新operation identityと新ticketで行う。
- PRODUCER_RESULT: `delegated_result_ready := runtime_spawn_result.task_name == task identity ∧ FINAL_ANSWER.Sender == task identity ∧ final resultがbind済みoperation / criterion / target / requested result contractへbind可能`。spawn / invocation / wait / root宣言 / 進行記述 / 異Sender message / root要約はidentity証跡にならない。falseの間はcriterionをpassedにせず、producer terminal後もfalseならproducer operation resultを`unavailable`にする。bind済みcriterionのfalse / failedは当該operationのterminal resultとして保持し、別operation resultを失効させない。
- OWNER_ROLE: criterion owner / non_machine_risk / risk / role / 静的確認 / 独立確認 / 成果確認 / test-contract確認 / 有用性の語列はnon-machine riskの担当情報だけとして保持し、operation identity / task identity / worker / producer / spawnを成立させない。TaskSpecまたは適用authorityが独立producer executionを直接明示した場合だけ対応operationとproducerへbindする。欠けたoperation fieldをowner語列、一般的慣行、root宣言または事後spawnで補完しない。
- ROOT: rootがproducerでないoperationではticket / packet構築、result binding、edge / validity / terminal集約だけを行い、predicate実行、review judgement、observation value、producer resultを再生成または補完しない。`suppressed_by_predecessor`はproducer resultではなくconditional ticketのcontrol stateとしてだけ集約する。
- WORKER_CONTEXT: 全worker packetへ`criterion / owner / pass condition / TaskSpec該当範囲 / operation ticket identity / target identity / scoped diffまたはresult / required evidence / allowed read / forbidden input`を固定する。packetとallowed readだけで判定可能なら`fork_turns=none`とし、不足時だけ意味保持に必要な最小turn数を継承する。利便性、念のため、無関係なtool outputの参照可能性を全履歴継承の理由にしない。review packetにもこの共通contractを適用し、固有fieldは`REVIEW_PACKET`だけで加える。
- METHOD_SELECTION: TaskSpec明示手段だけを固定し、未固定手段はpredicateとrequested result contractを変えずpermission内で選ぶ。`method_eligible := permission内 ∧ 明示禁止なし ∧ methodの既知output schemaがrequested result contractの全required fieldを返し得る`。全required fieldを原理的に返せないmethodを候補またはrecoveryに使わない。eligible methodが複数ある場合は、既にmodel-visibleなTaskSpec / 適用instruction / 利用可能toolとmethod inventoryだけから有限candidate setと固定順序を初回attempt前にbindする。method選択だけのためにrepository evidenceを追加しない。validationの未指定commandも既受領inputから実行票発行時に選ぶ。明示禁止またはpermission denialは停止し、回避しない。
- METHOD_RESULT: 各method attempt resultを`binds_requested_result | does_not_bind_requested_result | invocation_failed | method_prohibited`へbindする。全required fieldのauthentic valueを持つ場合だけ`binds_requested_result`としてpredicateへ渡す。invocationはterminalかつsuccessでもfield不足なら`does_not_bind_requested_result`とし、evidence missing / permission denial / predicate failure / review unavailable / operation terminal / outer terminalへ昇格せず、同じoperationの固定candidate setに未試行eligible methodがあれば次を選ぶ。`invocation_failed`もpermission denialへ変換せず、未試行methodまたはRECOVERYへ渡す。明示methodが一つならそのterminal failureをTaskSpecのterminal contractへbindする。現在得られた一部fieldだけでrequested result全体を補完しない。
- RECOVERY: 同一operationの`environment recovery := environment-only repair + same required method rerun`。組の開始時だけ`environment_recovery_max`を消費し、固定candidate set内の別eligible method選択は数えない。review judgement / producer result生成 / terminal review再開 / permission回避を含めない。
- EVIDENCE_ADMISSION: repository evidence operationは全lifecycleでdefault denyとする。`evidence_operation_ready := activeなnonterminal predicateがunobserved ∧ 欠けた観測target / value / requested result contract / consumerがbind済み ∧ requested resultがconsumer stateを変え得る ∧ 対応operation ticketの全edgeがsatisfied`の場合だけ新しい観測targetへのevidence invocationを許可する。同じpredicate / target / requested result contract内のeligible method再選択を新しいevidence operationにしない。`spec_ready=false`では別clarification operation以外を発行しない。true後の変更前evidenceはtarget artifact / 明示read-only path / targetへ適用中のinstruction / implementation choiceを解決するauthorityだけを許可し、未固定required outcomeを補完しない。追加evidenceはadmitted resultがmissing / unreadable / bind済みvalueまたはconstraintとの具体的矛盾 / allowed path内で充足不能 / 適用instructionによる別authorityの明示を観測した場合だけ、そのresultと次ticketをbindして一件許可する。変更後validationは発行しない。
- ISSUANCE: 現在responseへtool callを一件でも出す前に全nonterminal ticketの`operation_ready`を判定し、実tool-call identityをready ticketへ一対一bindする。unsatisfied edgeのconsumerをpredecessorと同じresponse / wrapper / compound commandへ入れず、異operationを一shell commandへ統合せず、一tool callを複数operation resultへ使わない。ただし事前固定した個別result contract付きobservation batchは除く。`tickets_independent := predecessor relationなし ∧ conflict_keys共通要素なし ∧ 一方のresultが他方のtarget / permission / method / stop condition / requested result contract / 発行可否を変えない`。相互非依存なready ticketは同じmodel responseから個別tool callとして全件発行する。conflict keyが重なるready ticketはTaskSpec順、なければticket identity固定順で一件だけ発行し、result後に残りを再判定する。同時発行上限があれば固定順で上限分だけ発行する。発行集合の一件がcell ID付きnonterminal resultなら、全体をnonterminalのまま保持し同じcell IDへのwait以外を発行しない。全件terminal result受領後に一度だけ次を判断する。
- IMPLEMENTATION_BINDING: `implementation_bound := 許可済みresultからtarget artifactと適用instructionがbindされ、TaskSpec明示の全change effect / end stateまたはtransform / artifact relation / preservation constraintが、admission済みcurrent content上で実行可能な一変更predicateと一implementation choiceへbind済み`。trueになったresultだけを変更前evidence operationのterminal resultとし、未発行の変更前evidenceを失効する。repository evidenceで未固定required outcomeを補完しない。artifact変更後に確定するvalidation identityは`VALIDATION_PLAN`で扱う。
- FINITE_CLOSURE_CERTIFICATE: 独立review要否より先に`authority_identity / complete_target_set / complete_effect_map / complete_relation_set / preservation_constraints / implementation_exact_match / exhaustive_validation_coverage / no_open_selection`の8 fieldを固定する。現在design operationより前に固定された一意なauthorityが全targetを完全集合として直接列挙し、全effect、end stateまたはtransform、全relation、全constraintを固定し、現在変更predicateが過不足なく一致し、追加探索 / fallback / normalization / 選択 / 除外なしで既存validation predicateが全件を覆う場合だけ`finite_closure_certificate_ready=true`。一fieldでもnon-valueまたは不一致ならfalseとする。review contractの存在、複数artifact、owner / risk語列、一般的non-machine riskだけでfalseにせず、open authorityまたは現在inventoryの有限性だけでtrueにしない。
- REVIEW_REQUIREMENT: この条項以下はartifact変更admissionに必要な入れ子の独立review operationだけを扱う。依頼自体がroot producerのprimary reviewなら共通coreを使い、独立reviewを重ねない。`review_control_applicable := TaskSpecまたは適用authorityが現在subjectへ必要な独立operationとしてreview criterion / allowed result kind / result consumer / execution independenceを明示値で固定済み`。owner / risk / role / 単語類似 / 一般的慣行だけではfalse。`review_requirement := not_applicable if applicable=false; not_required if applicable=true ∧ finite_closure_certificate_ready=true; required otherwise`。not-applicableまたはnot-requiredではreview packet / producer / spawn / resultを作らず`CHANGE_ADMISSION`へ進む。
- PRIOR_REVIEW_RESULT_ADMISSION: 保存済みprior review resultはTaskSpecが利用を明示許可し、`operation identity / result_use_permission=allowed / current subject / criterion / allowed result kind / packet basis / producer identity / dependency / producer terminal / sender identity / observation authenticity / certificate / forbidden inputなし / result_still_valid`が一致する場合だけadmitする。canonical locator / 集合順 / 表示文字列 / root独自projectionとの完全一致を要求しない。prior resultへ新規review execution permissionを要求せず、新規permission denialでactive prior resultを失効させない。inadmissible prior resultを別operationへ再割当てまたはroot判断で補完しない。
- REVIEW_EXECUTION_PERMISSION: `review_requirement=required`かつadmitted active prior resultなしの場合だけ、新規独立reviewの`review_execution_permission := allowed | denied`をTaskSpecまたは適用authorityからbindする。この責任はpermission stateだけを返し、packet形成またはproducer起動を行わない。deniedではreview operation / packet / producer / spawn / observation deliveryを作らず、外側admissionへpermission resultを渡す。tool / method failure、target missing、packet unreadinessまたはreviewer unavailableをdeniedへ変換しない。
- REVIEW_PACKET: `review_requirement=required ∧ active prior resultなし ∧ review_execution_permission=allowed`の場合に、WORKER_CONTEXT全fieldと`subject / preservation constraint / semantic design input / authority / normative predicate / review scope identity集合 / observation spec集合 / allowed result kind / observation batch contract`をproducer起動前に固定する。private oracle / 期待terminal / past finding / 旧prompt / 修正案 / root反例予想 / 実装後diff / 禁止履歴を含めず、許可artifactの必要projectionだけを入れる。target identity未固定、projection不能、allowed read未固定または禁止情報を分離不能な場合だけpacketを`unavailable`にする。固定targetの存在 / read成功 / current valueはreadinessへ含めず、missingになり得るtargetもpacketへ固定してreviewerに観測させる。packet ready後はreview ticketをISSUANCEへ渡す。
- OBSERVATION_LEDGER: 各`observation_spec := observation identity / target identity / predicate identity / producer identity / invocation result contract identity / allowed terminal states`をreviewer invocation前に固定する。個別tool result受領時にmachine-returned invocation identity / result contract / structured exit / terminal state / payloadを同じobservation identityへbindし、自由文judgementより先にledger atomを形成する。複数観測を一custom wrapperから同時発行する場合は`observation_batch_identity`を事前固定し、wrapper result contractへ同じbatch identity、`observation identity -> individual result`の一対一mapping、各exitとpayload、およびmapping全体からmachine-generatedな`ledger_receipt_identity`を要求する。atom identityは`ledger_receipt_identity + observation identity`とし、内部chunk identityまたは表示順を手作業で付け替えない。wrapper全体exit、別atom成功、reviewer宣言からvalueを作らない。mapping欠落 / 重複key / 別target payload / contract不一致は当該atomだけを`terminal_failure`にする。
- REVIEW_JUDGEMENT: bind済みreview producerはadmitted observation ledgerだけから`counterexample_found | no_counterexample_found | unavailable`を形成する。`counterexample_certificate_ready := concrete witnessがauthentic value ∧ applicability規範predicateと全使用入力がvalue ∧ positive applicability ∧ 固定処遇との直接矛盾 ∧ 解消に一般設計のtarget / rule / permission / method / stop condition変更が必要`。実際に使ったatomだけへ依存しcertificate外missingで失効させない。`no_counterexample_certificate_ready := 固定scope全件review済み ∧ manifest全atomがauthentic value ∧ 全規範predicate適用後もcounterexampleなし`。未来全域は要求しないが一atomでもnon-valueなら成立させない。`review_unavailable_ready := 前二certificateがfalse ∧ 未解決predicate固定済み ∧ それを閉じ得るnon-value atom固定済み`。final resultは`observation_batch_identity / ledger_receipt_identity / 消費observation identity集合 / result kind / certificate`だけを返しledgerを自由文で再構成しない。
- CURRENT_REVIEW_RESULT_ADMISSION: rootはreviewの意味判断を再実施せず、`current_review_result_admissible := operation identityがcurrent review ticket一致 ∧ execution permission=allowed ∧ producer / sender一致 ∧ result kind allowed ∧ observation batch / ledger receiptがproducer result一致 ∧ 参照atomがauthentic / current ∧ terminal certificate充足 ∧ forbidden inputなし`を機械照合する。current resultへ別のresult_use_permissionを要求せず、internal chunk identity / canonical locator / 集合順 / 表示文字列 / root独自projectionを再構成しない。inadmissible resultを再割当て、再生成または補完しない。
- CHANGE_ADMISSION: `subject_change_allowed := review_requirement=not_applicable ∨ review_requirement=not_required ∨ (review_requirement=required ∧ admitted active no_counterexample_found)`。これはimplementation_bound / 明示permission / change predicate / preservation constraint / validation gateを置換せず全件必要とする。`subject_change_denied := admitted active counterexample_found ∨ admitted active review unavailable ∨ (review_execution_permission=denied ∧ active prior resultなし) ∨ review packet unavailable ∨ current review result inadmissible`。counterexampleは対応subjectをblocked候補、判断材料不足またはpermission denialはunavailable候補にする。複数subjectを一changeへ含む場合は全subject allowedかつ全relation成立を要求し、禁止subject除外でrequired outcome / relation / 実行可能性を壊すなら一部変更しない。別implementation choiceは新identityとticketで変更前gateから行う。
- VALIDATION_PLAN: artifact変更後の検証開始前に、required validationと完了判定に必要なdiff / statusを一つのvalidation ticketへ順にbindする。TaskSpecまたはcommand evidence protocolがexact commandを明示しない場合、既受領TaskSpec / instruction / target evidenceとMETHOD_SELECTIONだけからeligible commandを実行票発行時にbindする。未固定commandをmissing validation identityまたはrepository evidenceの開放条件にせず、変更前evidenceまたはISSUANCEの変更前ticketからvalidationを発行しない。
- VALIDATION_CLOSURE: `validation_predicate_ready := artifact変更完了 ∧ required validationのpredicate / order / individual pass condition / stop conditionが全件bind済み ∧ exact command明示時だけそのcommand bind済み`。trueかつproducer=rootなら1回のcustom exec wrapper内で全required validationをbind順の個別`exec_command`として発行し、各exit codeを確認してnonzeroまたはunavailableなら後続を発行せず、shell compound commandへ結合しない。producerがroot以外でも全required validationを個別invocationとして同じmodel responseから発行する。完了済み全resultを一度だけmodelへ返す。wrapperがcell ID付きnonterminalなら同じcell IDへのwait以外を発行しない。全件successかつresult bind済みなら追加read / validationを行わずterminalへ渡す。欠落 / non-success / unexpected stateでは後続を発行せずoperationをnonterminalにする。
- OPERATION_TERMINAL: active operationはrequested result contractを満たすbind済みproducer resultがあり、そのstateがoperation固有terminal contractへ一致する場合だけterminalにする。method resultが`does_not_bind_requested_result`、edge pending、invocation / worker / session / cell ID nonterminal、producer result identity不一致、ledger atom不一致、required validation途中ではterminalにしない。`suppressed_by_predecessor`は未発行conditional ticketのcontrol terminalでありproducer success / failure / unavailableとして数えない。clarification operationは一度の質問resultでterminalになるが未固定実装operationをcompletedにしない。
- OUTER_TERMINAL: 依頼全体はTaskSpec-requiredな全active operationがterminalで、conditional operationがterminal resultを持つか`suppressed_by_predecessor`で、pending edgeと未解決dependencyがなく、各result kindを外側terminal contractへbindできる場合だけterminalにする。変更許可とrequired validationが全件successなら`completion_ready`、admitted counterexampleなら`blocked`、必要reviewのadmissible unavailable / permission denial / packet unavailableその他TaskSpec固定の不足resultなら`unavailable`、single terminal clarificationなら`clarification_required`を返す。最終文字列の一致、進行報告、root要約または別operation resultで欠けたrequired operation resultを補完しない。
