# C325 r3で先行する依頼の効力を明確にする

C324を直接の親とし、C325の見出しを用いる。第一項の冒頭を次の二文に差し替え、同じ一行に続ける。

> ユーザーが求める結果（作業後にどうなっているべきか）は、ユーザーが今回示した内容、以前に示した内容のうち今回の対象と作業にも効力があるもの、およびそれらが従うよう求めている指示や正本が直接定めている内容だけで決まる。以前の条件には、今回指定された追加・変更・解除を反映する。

「装備選びの方法を要約」では、今後使う基準を決めた直後に指輪固定を追加すると、回答はほかの部位を現状に固定し、左右の比較で終了した。r3は、今回の依頼で再掲されなかったことだけを理由に、明示済みの要求を完了条件から外す解釈を閉じる。先行する依頼とその指定先から結果を決め、変更後も効力を持つ条件の充足を既存の完了判断へ渡す。個々の条件が今回の対象に及ぶかという意味上の判断は残る。

変更するのは結果を決める根拠の時間的範囲である。依頼や指定先から決まらない結果については、C324が定めた事前確認を経て、不足点を尋ねて終了する。結果が決まっていれば、要求の範囲で実施と検証を終える。過去の実装例、任意の文書、検索で見つけた候補をユーザーの要求へ加える許可や、先行条件を探す操作は追加しない。r2のA01反復2では結果未確定時に対象コードを検索し、A02反復2ではテスト全体を実行した。前者はC324の制限違反、後者は許容された検証範囲の広がりとして扱う。[r2の保存結果](../evaluations/results/c325r2-astra62-low-a01-a02-n5_2026-11-20.md)

固定Standard14 r1のA01 r2・A02 r2を、GPT-6.2 Astra Low、Codex CLI 0.169.1、採点契約v14で各5回計測する。事前照合後に発行し、無効・採点不能を有効件数に含めない。C324・C325初版・r2の同条件の保存結果と得点分布、全エージェントのトークン、時間、費用を比較する。A01で質問前に調査したか、A02で修復と検証を完了し、どの既存テストを実行したかを確認する。得点低下があれば品質維持と判定しない。継続依頼での条件継承は両課題で直接観測できないため、両課題の満点を継承成功として扱わない。
