# 【API料金40%減】プロンプトを増やしたら、なぜか請求が安くなりました

いきなり結論です。

**AIへの指示を0バイトから10,772バイトに増やしたら、API料金換算が39.95%下がりました。**

「いやいや、プロンプトを増やしたら、そのぶん料金も上がるでしょ？」

普通はそう思いますよね。でも、実際に測ったら逆でした。

同じAIに、同じ14個の課題を、同じ条件でやらせています。違うのは、いちばん上に置く静的プロンプトだけです。指示が0バイトのFree版を100%として、147通り試した末の最新版と比べました。

結果がこちらです。

|  | 0バイト（Free・基準） | 最新版 | Free比 |
| --- | ---: | ---: | ---: |
| **API料金換算** | **$5.08** | **$3.05** | **60.05%（39.95%減）** |
| 1,000セットの換算額 | $5,083 | **$3,052** | **約$2,031節約** |
| 実行トークン | 3,488,611 | **1,447,626** | **41.50%（58.50%減）** |
| 静的プロンプト | 0 B | **10,772 B** | **約1万バイト増** |
| 最高評価だった実行 | 65 / 70件 | **70 / 70件** | **全件満点** |

どうでしょう。

**料金は約4割減。トークンは約6割減。品質は65勝から70戦全勝です。**

プロンプトを約1万バイト増やしたのに、むしろ安くなっています。1,000セット回すと、換算額は約`$5,083`から`$3,052`へ。差額は約`$2,031`です。

## なんで安くなったの？

ポイントは、AIがお金を使うのは、最初にプロンプトを読むときだけじゃないということです。

本当にお金がかかるのは、指示が曖昧なせいでAIが迷走するときです。

- 「どのファイルを見ればいいんだ？」と探し回る
- 「念のため」と余計な調査を始める
- 誰が作業するのかを何度も考え直す
- 終わっているのに確認や検証を繰り返す

こういうことをするたびに、トークンが使われます。つまり、**AIが迷っているあいだも、料金メーターは回り続けるんです。**

最新版では、「どこを見るか」「誰がやるか」「いつ終わるか」を先に決めました。読む文章は増えます。でも、実行中に迷ったり、探し回ったり、やり直したりする量が減ります。

その結果、静的プロンプトは約1万バイト増えたのに、実行中のトークンは58.50%減りました。

## これだけ覚えてください

**プロンプトをケチると、AIが勝手に残業します。**

削るべきなのは文字数じゃありません。AIが迷う余地です。

良いプロンプトは、長いから安いわけではありません。AIの無駄足を止めるから安いんです。今回の条件では、その差が**API料金約40%減**になりました。

では、実際に何を書けばいいのか。続きは[「AIの無駄足を止める4つの判断ルール」](how-to-write-prompts-that-cut-api-cost.md)にまとめています。

なお、金額は保存済みの通常入力・キャッシュ入力・出力トークンにGPT-5.6 SolのAPI単価を掛けた換算値で、実際の請求額ではありません。数値は各課題を5回ずつ実行した中央値です。別のリポジトリやモデルでも同じ削減率になるとは限りません。
