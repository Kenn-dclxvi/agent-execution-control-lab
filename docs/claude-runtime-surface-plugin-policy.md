# Claude Code評価の起動時照合：プラグインとプランの扱い

2026-10-08。Claude Codeのアダプター（`scripts/run_claude_evaluation.py`）は、各runの起動時に、モデル、権限、MCP、スラッシュコマンド、skill、プラグイン、ツール、エージェント、版、出力形式を、プロファイルの条件と照らし合わせている。一致しないrunは`claude_runtime_surface_mismatch`として除外する。この文書は、そのうちプラグインとプランの扱いを定める。

## 経緯

C291のOpus 5.5 medium計測の途中で、利用上限のためにアカウントをTeamから個人のプランへ切り替えた。切り替え後は、起動時のプラグイン一覧から`cc-plugin-sec-default@builtin`が消えた。それ以外の項目はすべて一致し、モデルの作業も正常に終わっていたが、222回が除外された（[計測記録](../evaluations/results/claude-opus55-c291-standard14-n5-cli2288_2026-10-08.md)）。

このプラグインは、実行ファイルの説明によると、TeamとEnterpriseの組織で一番外側に置かれ、組織のフック、プロンプト、設定、ツールの方針を、利用者が入れたプラグインから守る。自分では方針を加えない。C289のOpus 70件の記録でも、起動時の一覧以外に現れた箇所はなく、フックが動いた記録もなかった。`cc-plugin-telemetry@builtin`は利用状況の送信を担い、モデルが受け取る指示やツールを変えない。

照合で確かめるべきなのは、エージェントの動きを変えるものが条件どおりかどうかである。動きを変えない組み込みの補助プラグインの有無まで一致を求めると、作業内容が同じrunを、アカウントの違いだけで除外することになる。

## 方針

- プラグインの照合は、動きを変えうるプラグインだけを対象にする。`cc-plugin-telemetry@builtin`と`cc-plugin-sec-default@builtin`は、観測と条件の両方から除いて比べる。それ以外のプラグインが1つでも増減すれば、従来どおり除外する。
- 除いた2つも、各runの`runtime-surface.json`には観測値として残す。
- 除外の対象は`source`で判定する。同じ名前でも`@builtin`以外から入ったものは、動きを変えうるプラグインとして扱う。
- 契約プラン（`subscription_type`）は、アダプターも事前照合も必須にしない。新しいプロファイルでは条件へ入れず、プラン名で計測を識別しない。認証の条件は、ログイン方式とAPIキーの有無だけとする。
- 計測用の設定フォルダのログイン情報は、`.credentials.json`に置く必要がある。計測は画面のない実行環境で動き、キーチェーンを読めない。アカウントを切り替えるときは、計測側からログインを実行する。

## 既存の結果と互換性

- 既存のプロファイルと結果は書き換えない。C291 medium以前のプロファイルには、`cc-plugin-sec-default`を含む一覧と`subscription_type`が残っている。
- アダプターのコードのSHA-256は、比較条件（`time_recording.code_sha256`）に入っている。この変更以降に作るプロファイルは、変更前の系列とは別の互換キーになる。変更前の系列と比べたい場合は、比較の前に、コードの違いを条件の差として扱うかを決める。
- 新しいプロファイルのプラグイン一覧は、動きを変えうるプラグインだけを書けばよい。通常は空の一覧になる。
