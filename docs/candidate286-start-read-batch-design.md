## 追加原文

root `AGENTS.md`の「実行制御」の末尾へ、次の三項を追加する。

- 依頼が名指ししたファイルやコミットを変更前に読む場合は、依頼が指定した開始時の確認と同じ、最初の一つの外側のツール呼び出しの中で読む。それらのファイルがあるディレクトリと上位のディレクトリの指示ファイル（`AGENTS.md`）も、存在するものだけを同じ呼び出しの中で読み、存在を確かめるためだけの呼び出しを別に発行しない。
- その呼び出しの中では開始時の確認を先に実行する。結果が依頼の停止条件に当たる場合（未コミットの変更がある、指定されたコミットがないなど）は、読み取りを実行せずに結果を返す。
- 前の二項は読み取りを新しく許可しない。成果が決まっていない間に調査を始めない規則は、そのまま適用する。最初の呼び出しの結果を見て初めて決まる読み取り対象は、次の呼び出しでまとめて読んでよい。

4. **追加する条件の全件。** 上記の三項だけである。既存の文は変更しない。担当、ラベル、新しい判断項目は追加しない。
5. **禁止行動、開放経路、閉じる境界と反証。** 禁止行動は、依頼が名指ししたファイルを変更前に読むとき、その読み取りを最初の呼び出しより後に回すこと、または指示ファイルの存在確認だけのために呼び出しを分けることである。開放経路は、呼び出しの分け方が実装方法としてモデルに任されていることである。適用場面は「名指しされたファイルを変更前に読む」という観測できる事実で決まり、依存の有無や必要性の判定を介さない。開始時の確認の結果で読み取りを止める判定は、呼び出しの中のコードで機械的に行う（`git status --short`が空でない、`git cat-file -e`が失敗するなど）。順序やラベルを変えても、名指しされたファイルを2回目以降の呼び出しで初めて読めば違反になる。プロンプトは実行を物理的に強制しないため、不可分性は主張しない。
