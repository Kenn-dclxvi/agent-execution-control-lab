# THE-CAPTION execution control

- OPERATION_SPEC: 実行前にrequired outcomeをoperation identityへ分け、`predicate / criterion owner / permission source / required result kind / result consumer / constraint / dependency / terminal condition`をTaskSpecへ固定する。`spec_ready := required outcome valueが、明示user inputまたはそのvalueを直接要求する一意なrepository authorityへbind済み`。required outcome valueはTaskSpecが利用者に観測可能な成果として選択を要求する値とし、target artifact / canonical path / module / command / implementation methodはTaskSpecがそれ自体を成果として要求しない限りimplementation choiceとする。current value / option set / complement / test expectation / implementation convenienceはrequired outcome valueをbindしない。実装operationが`spec_ready=false`の間は、そのoperationのproducer binding / predicate実行 / repository read / artifact変更 / testを開始しない。未固定required outcomeだけを質問する場合は、実装operationと別のclarification operation identityへroot producer / 質問対象 / 禁止operation / terminal resultを固定し、一度のclarification resultを返す。開始identityは、そのresultを消費する未発行operationがある場合だけ観測する。外側admission / review / 観測 / 変更 / validationは別operation identityとし、result / constraint / terminalを別operationまたはtask全体へ伝播させない。
- PRODUCER_BINDING: 初回predicate前に各operationへrootまたはworkerのproducer execution identityを一つbindし、同一operationのpredicate実行またはresult生成を他producerへ順次・並行に割り当てない。TaskSpecが独立producer executionを明示した場合だけ、その指定identityをproducer role identityへbindする。producer変更は理由を問わず旧bindingを失効し、新operation identityと新TaskSpecで行う。先行resultまたはartifactを対象とする別operationには固有predicate / owner / producerを実行前に固定する。
- PRODUCER_RESULT: `delegated_result_ready := runtime_spawn_result.task_name == task identity ∧ FINAL_ANSWER.Sender == task identity ∧ final resultをbind済みcriterionとtargetまたはproposed response identityへbind可能`。`wait` / root宣言 / 進行記述 / 異Sender message / root要約はidentity証跡にならない。falseの間はcriterionをpassedにせず、producer terminal後もfalseならそのoperation resultを`unavailable`にする。bind済みcriterionの`false / failed`はそのoperationのterminal resultとして保持し、別operation resultを失効させない。
- OWNER_ROLE: criterion owner / non_machine_risk / risk / role / 静的確認 / 独立確認 / 成果確認 / test-contract確認 / 有用性の語列はnon-machine riskの担当情報だけとして保持し、operation identity / task identity / worker / producer / spawnを成立させない。TaskSpecまたは適用authorityが独立producer executionを直接明示した場合だけ、そのidentityを対応operationとproducerへbindする。欠けたoperation fieldをowner語列、一般的慣行、root宣言または事後spawnで補完しない。
- ROOT: rootがproducerでないoperationではpacket構築 / result binding / dependency集約 / terminal集約だけを行い、predicate実行 / review judgement / result再生成をしない。
- WORKER_CONTEXT: 全worker packetへ`criterion / owner / pass condition / TaskSpec該当範囲 / target identity / scoped diffまたはresult / required evidence / allowed read / forbidden input`を固定する。packetとallowed readだけで判定可能なら`fork_turns=none`とし、不足時だけ意味保持に必要な最小turn数を継承する。利便性、念のため、無関係なtool outputの参照可能性を全履歴継承の理由にしない。review packetにもこの共通contractを適用し、固有fieldは`REVIEW_PACKET`だけで加える。
- RESULT_DEPENDENCY: `result_dependency(result, next_operation) := resultがnext_operationのtarget / permission / method / stop condition / requested result contract / 発行可否 / terminal conditionのいずれかを変え得る`。trueの場合だけnext operationへresultをdependencyとしてbindする。dependencyは実際に消費するobservation atomとsubjectへ限定し、certificate外missing / 無関係field / task全体を含めない。`result_still_valid := dependency内identityまたはvalueを変えた新resultなし`。artifact変更 / 追加観測 / failed resultは入力atomを変えたresultだけを失効でき、別subjectまたは別operationのresultを一括失効させない。terminal operationのresultが失効しても同operationを再開せず、TaskSpecが許す場合だけ新operation / packet / producer / result identityを作る。
- METHOD: TaskSpec明示手段だけを固定する。未固定手段はpredicateを変えずpermission内で選び、validationでは既に受領したTaskSpec / 適用instruction / target evidenceから実行票発行時にcommandへbindする。exact command選択だけを理由にrepository evidenceを追加しない。invocation failed / unavailableをpermission denialまたはterminalにせず、未固定手段があれば同じpredicateへ継続する。tool failure / target missing / review unavailable / permission denialを相互変換しない。明示禁止またはpermission denialは停止し、回避しない。
- RECOVERY: 同一operationの`environment recovery := environment-only repair + same required command rerun`。組の開始時だけ`environment_recovery_max`を消費し、未固定手段の選択は数えない。review judgement / review result生成 / 失効result再利用 / terminal review再開を含めない。
- EVIDENCE_ADMISSION: repository evidence invocationは全lifecycleでdefault denyとする。`required_predicate_state := satisfied | unsatisfied | unobserved`、`evidence_consumer_ready := required predicateがnonterminal ∧ state=unobserved ∧ 現在欠けた観測値がbind済み ∧ requested resultがそのstateをbind可能 ∧ そのresultを消費する未発行operationがある`とし、target探索 / 変更前evidence / review observationのいずれもtrueの場合だけ発行する。TaskSpecがvalidation predicateを固定済みならcommand / locator / symbol / 慣行が未固定なだけで`unobserved`へ戻さず、method選択用evidenceを追加しない。consumer terminal後は未発行evidenceを失効する。`spec_ready=false`ではOPERATION_SPECが固定したclarification以外を発行しない。true後の変更前evidenceは`target artifact / 明示read-only path / targetへ適用中のrepository instruction / implementation choiceを解決するrepository authority`だけを許可し、未固定required outcomeを事後補完しない。追加evidenceは許可resultが`missing / unreadable / bind済みvalueまたはconstraintとの具体的矛盾 / allowed path内で充足不能 / 適用instructionによる別authorityの明示`を観測した場合だけ、そのresult identityと次evidence identityをbindして一件許可する。permission / allowed read / available tool / 一般的安全確認は開放条件にしない。変更後required validationは`VALIDATION_PLAN`と`VALIDATION_CLOSURE`だけが発行する。
- DECISION_BOUNDARY: 開始identity / repository read / 変更前evidence / review observation / その他の変更前invocationについて、発行前に`requested result / consumer / operation class / target / permission / method / stop condition`を固定する。consumerがなければ発行しない。TaskSpecの限定停止は名前を挙げた未発行operation classだけへ効かせ、無限定停止は全未発行operation classへ効かせる。先行resultが次invocationのtarget / permission / method / stop condition / requested result contract / 発行可否を変え得る場合だけ受領を待つ。相互非依存でreadyなinvocationは同じmodel responseから個別tool callとして全件発行し、発行集合とtool-call identity集合を一対一にする。明示された同時発行上限を超える場合だけ、固定順序と上限で現在集合を発行前に分割し、result受領後に便宜的に選び直さない。一部だけを発行して残りを次responseへ送らず、shell compound commandまたはaggregate resultで個別identityを代用しない。発行済み集合の一件がcell ID付きnonterminal resultを返した場合、その集合をnonterminalのまま保持し、同じcell IDへのwait以外を追加発行しない。全件のterminal result受領後に一度だけ次を判断する。独立review producerの実発行もこの責任が所有し、`review_requirement=required ∧ active prior resultなし ∧ review_execution_permission=allowed ∧ review_packet_ready`の場合だけ起動する。変更後required validationは所有しない。
- IMPLEMENTATION_BINDING: `implementation_bound := 許可済みresultからtarget artifactとtargetへ適用中のrepository instructionがbindされ、TaskSpecがrequired outcomeに明示した全change effectとartifact間relationが、admission済みcurrent content上で実行可能な一変更predicateと保持constraintを持つ一つのimplementation choiceへbind済み`。trueになったresultだけを変更前evidence operationのterminal resultとし、未発行の変更前evidenceを失効する。repository evidenceはimplementation choiceをbindできるが、未固定required outcomeを補完しない。artifact変更後に確定可能なvalidation identityは変更前evidence operationを再開せず`VALIDATION_PLAN`で扱う。
- REVIEW_REQUIREMENT: この条項以下のreview controlは、artifact変更admissionに必要な入れ子の独立review operationだけを扱う。依頼自体がroot producerのreviewである場合はprimary operationとして共通coreを使い、独立reviewを重ねない。`subject := implementation_bound=trueの一変更predicate`、`explicit_review_operation_fixed := TaskSpecまたは適用authorityがreviewを現在subjectへ必要な独立operationとして直接名指しし、review criterion / allowed result kind / result consumer / execution independenceを明示値で固定済み`、`review_control_applicable := explicit_review_operation_fixed`。owner / risk / role / 静的確認 / 独立確認 / 成果確認だけではfalseとし、欠けたfieldを推論しない。`finite_direct_match := 先行する一意なTaskSpecまたはauthorityが全target / effect / end stateまたはtransform / 保持constraint / artifact間relation / 集合全件性を直接固定 ∧ 既存machine-bound resultだけで変更predicateとの過不足ない一致を判定可能 ∧ 追加選択 / 除外 / 探索 / fallback / normalization / non-machine完全性判断なし`。`review_requirement := not_applicable if review_control_applicable=false; not_required if applicable ∧ finite_direct_match; required otherwise`。not-applicableでは独立review一式を作らず共通coreを使い、not-requiredではreview一式を作らず`CHANGE_ADMISSION`へ進む。
- PRIOR_REVIEW_RESULT_ADMISSION: 保存済みprior review resultは、TaskSpecが利用を明示許可し、`operation identity / result_use_permission=allowed / current subject / criterion / allowed result kind / packet basis / producer identity / dependency / producer terminal / sender identity / observation authenticity / certificate / forbidden inputなし`が一致し、`result_still_valid=true`の場合だけadmitする。canonical locator / 集合順 / 表示文字列 / root独自projectionとの完全一致を要求しない。prior resultへ新規review execution permissionを要求せず、新規permission denialでactive prior resultを失効させない。inadmissible prior resultを別operationへ再割当てまたはroot判断で補完しない。
- REVIEW_EXECUTION_PERMISSION: `review_requirement=required`かつadmitted active prior resultがない場合だけ、新規独立reviewの`review_execution_permission := allowed | denied`をTaskSpecまたは適用authorityからbindする。この責任はpermission stateだけを返し、packet形成またはproducer起動を行わない。deniedではreview operation / packet / producer / spawn / observation deliveryを作らず、外側admissionを`unavailable`候補にする。tool / method failure、target missing、packet unreadinessまたはreviewer unavailableをdeniedへ変換しない。
- REVIEW_PACKET: `review_requirement=required ∧ active prior resultなし ∧ review_execution_permission=allowed`の場合に、`review_packet_ready := WORKER_CONTEXT全field ∧ subject / 保持constraint / semantic design input / authority / 規範predicate / review scope identity集合 / 各observation identity・target・allowed read・success condition / allowed result kindが固定済み`をproducer起動前に判定する。private oracle / 期待terminal / 過去finding / 旧prompt / 修正案 / rootの反例予想 / 実装後diff / 禁止履歴を含めず、許可artifactの必要projectionだけを入れる。target identity未固定、projection不能、allowed read未固定または禁止情報を分離不能な場合だけpacketを`unavailable`にする。固定targetの存在 / read成功 / 現在valueはreadinessへ含めず、missingになり得るtargetもpacketへ固定してreviewerに観測させる。packet ready後の起動は`DECISION_BOUNDARY`へ委ねる。
- OBSERVATION_RESULT: `observation_atom := observation identity + target identity + predicate identity + producer identity + invocation result identity + invocation result contract identity + terminal state`、`terminal state := value | missing | unreadable | terminal_failure`。正常観測した不存在だけをmissing、resultを返せないinvocationをterminal-failureとし、permission deniedをatom stateにしない。root推測 / reviewer宣言 / 別fieldまたは別atom成功 / aggregate exitからvalueを作らない。aggregate non-success下のper-item valueは、適用中invocation result contractがそのvalueの真正性を明示する場合だけadmitし、未固定なら別invocationを要求する。実invocationなしのsuccess receiptをadmitしない。
- REVIEW_JUDGEMENT: bind済みreview producerはreview packetとadmitted observationだけから`counterexample_found | no_counterexample_found | unavailable`を形成する。`counterexample_certificate_ready := concrete witnessがvalue ∧ applicabilityの規範predicateと全入力がvalue ∧ positive applicability ∧ 固定処遇との直接矛盾 ∧ 解消に一般設計のtarget / rule / permission / method / stop condition変更が必要`。実際に使ったatomだけへ依存し、certificate外missingで失効させない。`no_counterexample_certificate_ready := 固定review scope全件review済み ∧ manifest全atomがauthenticなvalue ∧ 全規範predicate適用後もcounterexampleなし`。未来全域は要求しないが一atomでもnon-valueなら成立させない。`review_unavailable_ready := 前二certificateがfalse ∧ 未解決predicate固定済み ∧ それを閉じ得るnon-value atom固定済み`。一般的不確実性だけでunavailableにしない。counterexample成立時は無関係な未発行observationを失効し、それ以外の場合だけ全scopeを判定する。
- CURRENT_REVIEW_RESULT_ADMISSION: rootはreviewの意味判断を再実施せず、`current_review_result_admissible := operation identityがcurrent bound review operation identityと一致 ∧ review_execution_permission=allowed ∧ producerとsenderがbinding一致 ∧ result kindがallowed ∧ 参照observationが実在・authentic・current ∧ terminal certificate充足 ∧ forbidden inputなし`を機械照合する。current resultへ別の`result_use_permission`を追加要求せず、canonical locator / 集合順 / 表示文字列 / root独自projectionとの完全一致を要求しない。inadmissible resultを再割当て、再生成または補完しない。
- CHANGE_ADMISSION: `subject_change_allowed := review_requirement=not_applicable ∨ review_requirement=not_required ∨ (review_requirement=required ∧ admitted active no_counterexample_found)`。これは`implementation_bound / 明示permission / change predicate / 保持constraint / validation gate`を置換せず全件必要とする。`subject_change_denied := admitted active counterexample_found ∨ admitted active review unavailable ∨ (review_execution_permission=denied ∧ active prior resultなし) ∨ review packet unavailable`。counterexampleは対応subjectを`blocked`、判断材料不足またはpermission denialは`unavailable`にする。複数subjectを一invocationへ含む場合は全subject allowedかつ全relation成立を要求し、禁止subjectの除外でrequired outcome / relation / 実行可能性を壊すなら一部変更しない。別implementation choiceは新identityで変更前gateから行う。
- VALIDATION_PLAN: artifact変更後の検証開始前に、required validationと完了判定に必要と確定しているdiff / status等を一つの実行票へ順にbindする。TaskSpecまたはcommand evidence protocolがexact commandを明示しない場合、その未固定commandをmissing validation identityまたはrepository evidenceの開放条件にせず、既に受領したTaskSpec / 適用instruction / target evidenceの範囲から`METHOD`として選び、実行票発行時にcommandへbindする。変更前evidenceまたは`DECISION_BOUNDARY`からvalidationを発行しない。
- VALIDATION_CLOSURE: `validation_predicate_ready := artifact変更完了 ∧ TaskSpec-required validationのpredicate / order / individual pass condition / stop conditionが全件bind済み ∧ TaskSpecまたはcommand evidence protocolがexact commandを明示したvalidationだけそのcommandがbind済み`。trueかつproducer=rootの場合、TaskSpecまたはcommand evidence protocolの「順に」「1 commandずつ個別」は、1回のcustom exec wrapper内で全required validationをbind順の個別`exec_command`として発行することを意味し、resultをmodelへ返して次commandを別custom tool callで発行することを意味しない。各exit codeをwrapper内で確認し、nonzeroまたはunavailableなら後続を発行せず、shell compound commandへ結合しない。producerがroot以外の場合も全required validationを個別invocationとして同一model stepから発行する。完了済みの全resultを一度だけmodelへ返す。wrapperがcell ID付きnonterminal resultを返した場合、その返却を完了判定へ使わず、実行票全体がterminalになるまで同じcell IDへのwaitだけを発行し、commentary / 判断 / 別toolを先に発行しない。全件successかつ全result bind済みなら、TaskSpec追加要求またはresult失効がない限りread / validationを追加しない。欠落 / non-success / unexpected stateでは後続を発行せずoperationをnonterminalにする。
- OPERATION_TERMINAL: 一operationは、そのpredicateに必要な全producer resultがterminalで、bind済みresultが当該operationのterminal conditionを満たした場合だけterminalにする。invocation / worker / session / 発行集合がnonterminal、producer result identity不一致、またはrequired result欠落ならoperationもnonterminalとし、別operationのsuccess / failureを伝播させない。clarification operationは一度の質問resultでterminalになるが、未固定の実装operationをcompletedにしない。
- OUTER_TERMINAL: 依頼全体は、全required operationがterminalで、未解決dependencyがなく、TaskSpecの最終状態を説明できる場合だけterminalにする。TaskSpecがclarificationをsingle terminal outcomeとする場合は、terminal clarification operationと未発行実装operationから`clarification_required`を返す。変更許可とrequired validationが全件successなら`completion_ready`、admitted counterexampleなら`blocked`、必要result不足 / packet unavailable / permission denialなら`unavailable`として原因と一緒に集約する。進行報告 / 集約結果 / final responseで欠落resultを補完せず、未検証成果を成功、完了、採用可能として報告しない。
