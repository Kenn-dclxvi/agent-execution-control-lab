# Candidate283 検証結果の採用と追加操作の許可境界

2026-10-07。Candidate作成前に固定する設計と計測条件。

## 目的と実施方針

利用者の指示に従い、C280から[再判定r2](c280-c147-control-group-transfer-reassessment-r2.md)の方式を指定しない検証側の三項を追加したC283を作成し、C282と同条件のGPT-6.1 Sol Low・Standard14全14ケースN=5、計70件を測定する。C280は直接親と主比較相手、C282は条件照合と補助比較の相手。C147は境界の参考資料であり、直接親にしない。実行担当はroot。root以外の18対象とC280既存本文をバイト一致で維持する。既存の設計方針見直しの未コミット変更を保持する。

今回の三項は利用者が依頼した再設計案の試験として固定する。保存traceで三種類の違反すべてを観測したため追加する試験とは扱わない。分割経路を禁止行動へ昇格させず、呼び出し数、同期方法、ツール順を指定しない。

## 追加原文

- 検証の成功結果は、対応する検証条件を満たした証拠としてだけ採用する。その結果だけを根拠に、要求された検証や完了条件を追加・削除・置換したり、入力が変わっていない他の確認結果を失効させたりしてはならない。
- 必要な検証と確認の終了結果がそろっていない状態を完了としてはならない。進行報告、結果の欠落、未終了の返却、別担当の結果についての推測を、成功結果の代わりに採用してはならない。
- 必要な結果がそろった後は、新しい要求または判断の根拠入力の変更がない限り、満たした判断の再確認を目的とする読み取り・検証・レビューを追加してはならない。

## 作成前の確認事項

1. 比較基準はC280。正常経路は、要求成果を固定し、必要情報から変更を行い、要求された全検証・確認の結果を受領して終了すること。未確定成果を探索で補う許可は戻さない。
2. [保存済み140件の診断](c280-c282-result-effect-scope-trace-analysis.md)と[無作為化比較](../evaluations/results/c280-c282-sol61-low-f08-randomized-n50_2026-10-07.md)が観測したのは検証・最終確認の分割であり、要求の勝手な置換や未終了の成功補完を示すものではない。例としてC280 F04 `1f521853730e4282bf3f3d03369cf34d`は3種類のNode検証と最後の差分・状態確認を実行した。必要な別呼び出しはこの案でも合法である。今回の三項の発行根拠は利用者による文案の作成・試験指示であり、未観測違反を観測済みのように補わない。
3. C280の成果固定、担当対応、事前調査限定は維持するが、検証成功の証拠としての用途、欠落結果の採用禁止、全件成功後の追加操作の発行境界を直接定めていない。今回の三項は検証結果から完了までの結果採用と操作許可を一つの再構成対象にする。
4. 変更はrootへ上記三項を追記するだけ。C282の結果待ちの文、C147の単一wrapper・同一model step・特定wait・委任packetの指定は追加しない。既存4項と非rootの18対象を保持し、ラベルは追加しない。
5. 第1項は途中成功を要求変更や無関係な結果失効の根拠として採用する辺、第2項は欠落・未終了・推測を成功へ昇格する辺、第3項は満たした判断を追加要求や入力変化なしに再開する辺を閉じる。ツール順・呼び出し・ラベルを変えてもこれらの操作は規則違反になる。逆に分割して固定済み検証を続ける操作は閉じない。
6. 必要結果は依頼、適用指示、対象、指定した担当の終了結果から届く。途中結果の受領、同期、指定順の次検証、要求された最終差分確認、必要な独立確認、許可された失敗修正と入力変化後の再検証を維持する。F04 r2の一時出力削除は試験基盤の担当でありmodelへ移さない。
7. 新しい判断は結果を採用する用途、全結果の充足、追加操作を開く要求・入力変化との対応だけ。担当・手順・コマンド・出力形式は新設しない。既存成果固定との一部の意味的重複はあるが、検証結果が届く時点の局所境界として配置する。三項の独立効果を一度の試験で分離したとは扱わない。
8. C282 result `b9555c4df4584e988c5e1837c2e251d9`を発行前の条件照合先、C280 result `794d02abe894456686eea22e9b6f0fed`を主比較基準とする。C282のprofileからprompt identityとprofile IDだけを変え、同じLayer 1、全fixture、TaskSpec、Rating v14、CLI 0.159.0、Python 3.14.5、固定実行コード、個人指示隔離、M24、executor parameter、全エージェントトークン計上を再利用する。新規はC283の70件だけ。採点分布と個別runの3 KPI、反復ごとの14ケース合算の中央値、ケース別差を保存する。分割・tool数は診断に限定し、削減を先に主張しない。
9. 不一致・未確認は一件目の発行前に停止する。外部失敗のみ同じ枠で固定上限内再試行し、有効な失点は保存する。70件を完了して判断し、自動追加反復しない。品質低下を相殺せず、品質を維持しトークンと経過時間がともに減る場合だけコスト改善方向とする。片方の増加も退行として記録する。採用・本体反映・新方式への修正再試験は行わない。

三項を一単位とする理由は、結果の許される用途、完了への採用、採用後の追加操作の許可を連続した境界として扱うためである。作成・測定の結果は独立した評価記録に保存し、この固定設計を結果に合わせて改訂しない。
