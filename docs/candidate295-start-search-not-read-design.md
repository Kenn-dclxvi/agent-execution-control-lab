# Candidate295 開始時の義務を「名指しした対象の読み取り」から「位置を特定する検索」へ置き換える

2026-10-09。Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9に対応させた。目的、ターゲット、機序と保護の対応、評価の枠組みは[C293の設計記録](candidate293-shared-mechanism-carrier-design.md)と同じで、この記録はC294からの変更点と、その根拠を固定する。

## 目的と役割

- 系列と目的はC293・C294と同じ。比較の基準かつ直接の親はC280。主なターゲットはGPT-6.1 Sol LowとClaude Code Sonnet 5.5 low。
- C294は文面の供給源で、Sonnetで開始時の読み取りを前倒しした反例である。C294の開始時の項目（R1）だけを置き換え、他の文と書式はC294とバイト一致とする。
- 方針：判定表のANDの原則に従い、Sonnetで成立していない機序（開始時のまとめ読みによる変更前の要求の減少）のために、Sonnetに副作用だけを課す文を外す。Solで成立している機序（位置だけの検索を返さない、検索と本文を同じ呼び出しで返す）は保つ。
- 変更対象：root `AGENTS.md`のR1だけ。全文は4,894バイト（C294は4,858）。

## 1. 比較の基準と、正常な最短経路

C293と同じ。開始時の正常経路は、最初の応答で、開始時の確認、名指しされた対象の位置の検索（その定義・節の本文を同じ呼び出しで受け取る）、ルート以外の指示ファイルの取得を発行することである。

## 2. 保存traceで確認した問題経路

Sonnet lowの最初の応答で、範囲の指定なしの`Read`（指示ファイルを除く）の回数と結果の量を、段階ごとに数えた（各70件、1反復あたり）。

| 段階 | 最初の応答の全文`Read` | 結果の量 |
| --- | ---: | ---: |
| C280 | 7回 | 13.1KB |
| C284 | 4回 | 7.0KB |
| C288 | 41回 | 42.8KB |
| C289 | 25回 | 24.7KB |
| C291 | 36回 | 32.9KB |
| C293 | 40回 | 41.9KB |
| C294 | 34回 | 47.0KB |

- 増加はC288で起きた。C288は、「開始時の確認と、依頼が名指しした対象の読み取りは、最初の応答でまとめて発行する」を入れた段階である。
- C294の34回のうち26回は、依頼で名指しされたファイルだった（F10の`monthly_main.py`など、F06の試験ファイル、F07の`run.sh`）。
- C288〜C291には「ファイル名の指定だけでは全文を取得しない」の文があったが、全文`Read`は減っていない。この文は、この経路を閉じていなかった。
- C294のSonnet lowで最初の応答のツール結果は105.9KB（C280は42.3KB）で、Claude Codeでは以後のすべてのリクエストへ持ち越される。変更前の要求は1.62回で、C280の1.56回から減っていない。Opus mediumのC286で観測された、名指しされたファイルを開始時にまとめて読み、読み取り量が増えた型と同じである（[C287の設計](candidate287-start-read-response-design.md)）。

## 3. 開いている記述と、TaskSpec・正本で防げない理由

C294のR1は「依頼が名指しした対象の読み取り」を最初の応答の義務にしている。Claude Codeの`Read`は、範囲を指定しなければファイル全体を返す。R2は本文を範囲に限るが、R1の義務が「対象の読み取り」を求めるため、範囲を決める前に、名指しされたファイルを読む操作が最初の応答で発行される。C280には開始時の義務がなく、Sonnetは最初の応答で検索を発行していた（位置のみの検索27回）。

## 4. 追加・変更・削除する条件の全件

C294のR1を、次の文に置き換える。他の文はC294とバイト一致とする。

> - 開始時の確認、依頼が名指しした対象の位置を特定する検索、および対象のディレクトリからリポジトリのルートまでにある指示ファイルのうちルート以外のものの取得は、最初にツールを呼び出す応答で発行する。同じ応答の中で、ツール呼び出しは分けてよい。名指しされた対象も、ファイルを指定しただけで全文を読まず、次項の範囲で取得する。ルートの指示ファイル（この文書。`CLAUDE.md`は同じ本文を指す）は作業開始時に渡されているため、ツールで取得しない。依頼が確認前の読み取りを禁じている場合は、一つの呼び出しの中で確認を先に実行し、停止条件に当たれば読み取らずに結果を返す。この指定は、成果が決まっていない間の調査を許可しない。

| C294のR1 | C295のR1 | 理由 |
| --- | --- | --- |
| 依頼が名指しした対象の読み取りを、最初の応答で発行する | 名指しした対象の位置を特定する検索を、最初の応答で発行する | 義務の対象を、範囲を決める操作（検索）に変える。検索はR2により、定義・節の本文を同じ呼び出しで返す |
| 読み取りには、本文の取得範囲を特定する検索とその範囲の本文を含める | 削る（上の検索とR2が担う） | 同じ内容を、範囲の限定を先に置く形で書き直した |
| （C293で削った）ファイル名の指定だけでは全文を取得しない | 名指しされた対象も、ファイルを指定しただけで全文を読まず、次項の範囲で取得する | 名指しの義務を外した後に、名指しされた対象にも範囲の限定が及ぶことを明記する。単独では経路を閉じなかった文なので、閉じる境界としては主張しない |

## 5. 禁止行動、開放経路、閉じる境界、反証

| 禁止する行動 | 現在の開放経路（C294） | 閉じる境界 | 適用を決める事実 |
| --- | --- | --- | --- |
| 名指しされたファイルを、範囲を決める前に、最初の応答で全文読む | R1が「名指しした対象の読み取り」を最初の応答の義務にしている | 義務を「位置を特定する検索」に置き換える。名指しされた対象にもR2の範囲を適用する | 依頼がファイルを名指ししたという事実 |

反証：最初の応答で名指しされたファイルを範囲指定なしの`Read`や`cat`で読む構成は、R1の「ファイルを指定しただけで全文を読まず」とR2に違反し、保存traceの`Read`の引数と`cat`のコマンドで観測できる。定義・節の範囲がファイル全体と一致する場合の全文取得は、R2の範囲として許される。この区別は保存traceだけでは判定できないため、診断では全文`Read`の回数と量を数え、違反の件数とは呼ばない。

## 6. 維持する正常経路

- Sol：最初の応答で、検索と定義・節の本文を同じ呼び出しで取得できる（C289以降のSolの経路）。
- Sonnet：最初の応答で、検索、範囲を指定した`Read`、ルート以外の指示ファイルの取得を発行できる。
- 依頼が全文の取得を指定した資料、ルート以外の指示ファイルは全文を読める。

## 7. 新しく増える判断と、変更対象外への影響

新しい判断はない。適用は、依頼がファイルを名指ししたという事実で決まる。Solでは、名指しされたファイルの読み取りが検索に置き換わるため、変更前の呼び出しが増える可能性がある（C294の1.68回）。固定コストはC294より36バイト増える。

## 8. 評価ケース、比較単位、比較条件

C293と同じ（Sol LowとSonnet low、各Standard14 N=5の計70件、主比較は各セルの保存済みC280、参考はC289・C291・C293・C294）。診断はC294と同じ指標に、最初の応答の全文`Read`の回数と量、最初の応答のツール結果の量（Sonnet）を含める。

## 9. 停止条件

C293と同じ。結果に合わせてこの記録と案文を書き換えない。

## 判断の限界

- C288で全文`Read`が増えた原因を、開始時の義務と特定したのは、段階の対応と保存traceのファイル名による。C288は複数の文を同時に入れた段階であり、文単独の効果は分けていない。
- この記録は採用、release、本体反映を決めない。
