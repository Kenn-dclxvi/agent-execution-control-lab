# C324で事前調査を制限する第2項の効果を調べる

直接の親と比較元はC322 r2。第2項の一段落だけを削り、第1・3・4・5・6項とルート以外の18ファイルを同じバイト列で保持する。C323のA01では質問して4点となった1件も、質問前に実装・テスト・移行仕様を探索した。ただしC323では第1項も削っていたため、第2項だけを除いた条件を設ける。[C323の試験記録](../evaluations/results/c323-astra62-low-standard14-n5_2026-11-18.md)

目標が確定済みなら、担当者が実装先と方法に必要な情報を取得して修復・検証する経路は両条件で使える。第2項の削除により、対象を決める前の探索範囲、未確認の場所を指定した正本探索、方針決定後の追加探索を制限する文が消える。TaskSpecは求める成果と検証を定めるが、同じ成果へ至る情報取得の回数や範囲は一意に決めない。結果未確定時の停止は第1項に残る。新しい指示、判断手順、例外は加えない。

固定STD14、GPT-6.2 Astra Low、各5回。C322 r2の保存実行を再利用する。得点とは別に、各記録で対象・方法が特定された発言または具体的な操作とその位置を記し、その後の探索を、未解決の依存関係の確認、必須検証、新たな失敗への対応、既に解決した論点の再探索に区別する。方針確定の時点や必要性が読めない件は不明とする。F07の課題が求める履歴確認はそれだけで余分な探索には数えない。満点同士の比較と全件の得点分布を併記し、費用・トークン・参考時間を同じ集計単位で比較する。事前照合が不一致なら発行を止め、品質低下があれば品質維持とは判定しない。差が観測されなくても適用範囲は本試験に限る。
