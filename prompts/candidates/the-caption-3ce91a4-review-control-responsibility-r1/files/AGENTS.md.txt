# THE-CAPTION execution control

- OPERATION_SPEC: 実行前にrequired outcomeをoperation identityへ分け、各operationへ`predicate / criterion owner / permission source / required result kind / result consumer / constraint / dependency`を固定する。`spec_ready := required outcome valueが、明示user inputまたはそのvalueを直接要求する一意なrepository authorityへbind済み`。required outcome valueはTaskSpecが利用者に観測可能な成果として選択を要求する値とし、target artifact / canonical path / module / command / implementation methodはTaskSpecがそれ自体を成果として要求しない限りimplementation choiceとする。current value / option set / complement / test expectation / implementation convenienceはrequired outcome valueをbindしない。`spec_ready=false`の間はproducer binding / predicate実行 / artifact変更 / testを開始せず、`TaskSpec本文 / TaskSpec明示の開始状態の直接観測`だけを許可し、未固定のrequired outcome valueだけをclarification resultにする。外側admission、独立review、観測、artifact変更およびvalidationは別operation identityとし、`result / constraint / terminal`を別operationまたはtask全体へ伝播させない。
- PRODUCER_BINDING: 初回predicate前に各operationへrootまたはworkerのproducer execution identityを一つbindし、同一operationのpredicate実行 / result生成を他producerへ順次・並行に割り当てない。criterion owner語列はnon-machine riskの担当情報でありproducerを選ばない。TaskSpecが独立したproducer executionを明示した場合だけ、起動前にそのexecution identityをtask identityとしてproducerへbindし、対応workerを起動する。`delegated_result_ready := runtime_spawn_result.task_name == task identity ∧ FINAL_ANSWER.Sender == task identity ∧ final resultをcriterion / target artifactまたはproposed response identityへbind可能`。`wait`は同期専用でidentity証跡にしない。producer変更は旧bindingを失効させ、新identityのTaskSpecで行う。rootがproducerでないoperationではpacket構築 / result admission / terminal集約だけを行い、predicate実行 / result再生成 / terminal補完をしない。
- REVIEW_REQUIREMENT: C147から継承した`implementation_bound=true`の一変更predicateを一`subject`とし、target数、field数、artifact数、open classまたはreview都合から再分解しない。`review_control_applicable(subject) := TaskSpecまたは適用中repository authorityが、現在subjectへ独立review criterion / allowed result kind / result consumer / 必要なexecution independenceを直接固定済み`。`finite_direct_match(subject) := 現在設計より前に固定された一意なTaskSpecまたは適用中authorityが、subjectの全target identity / 全effect / 各end stateまたはtransform / 全保持constraint / 全artifact間relation / 集合の全件性を直接固定 ∧ 既存のmachine-bound resultだけから変更predicateが同じidentityと値へ過不足なく一致すると判定可能 ∧ 追加の選択 / 除外 / 探索 / fallback / normalization / 完全性判断がない`。`review_requirement := not_applicable if review_control_applicable=false; not_required if review_control_applicable=true ∧ finite_direct_match=true; required otherwise`。review契約がない通常変更へrisk、owner語列、open boundaryまたは`finite_direct_match=false`だけを理由にreviewを新設しない。`not_applicable`ではreview permission / packet / reviewerを作らずC147由来の変更前evidence、変更、validationおよびterminal経路へ委譲する。`not_required`でもreview一式を作らず変更許可判定へ進む。
- REVIEW_EXECUTION_PERMISSION: `review_requirement=required`では、新規review permissionより先に現在subjectへbind済みの保存review resultを`RESULT_ADMISSION`と`RESULT_EFFECT`で照合する。admittedかつactiveで`result_use_permission=allowed`ならそのresultを使い、新reviewを作らない。該当resultがない場合だけTaskSpecまたは適用中authorityから`review_execution_permission := allowed | denied`を現在subjectへbindする。`review_operation_ready := review_requirement=required ∧ activeなadmitted prior resultなし ∧ review_execution_permission=allowed ∧ review operation identity固定済み ∧ 独立producer bind済み ∧ packet_ready`。permission deniedではreview operation / packet / producer binding / spawn / deliveryを作らず、activeなadmitted prior resultもなければroot producerの外側admissionを`unavailable`にする。新規review permissionは保存resultの利用permissionを兼ねず、permission deniedはactive resultを失効させない。tool起動失敗、producer method失敗、観測missingまたはreviewerの`unavailable`をpermission deniedへ読み替えない。
- PACKET_FORMATION: `packet_ready(subject) := TaskSpec該当範囲 / subject / 保持constraint / semantic design input / 適用authority / 規範predicate / review scope identity集合 / 各observation identity・target・allowed read・success condition / forbidden input / allowed result kindが固定済み`。packetは評価case、private oracle、期待terminal、過去finding、旧Candidate、修正案、実装後diffまたは禁止履歴を含めず、許可artifactの一部だけがsemantic inputならそのprojectionだけを入れる。observation targetの存在、read成功または全atomの`value`はpacket readinessに含めない。identity自体が未固定、semantic projectionを作れない、permission内のallowed readを固定できない、または禁止情報を分離できない場合だけpacketを`unavailable`にし、reviewer resultを捏造せず外側admissionを`unavailable`にする。packetとallowed readで判定可能なら`fork_turns=none`とし、不足時だけ意味保持に必要な最小turn数を継承する。
- OBSERVATION_RESULT: repository evidence invocationは全lifecycleでdefault denyとする。`required_predicate_state := satisfied | unsatisfied | unobserved`、`evidence_consumer_ready := required predicateがnonterminal ∧ state=unobserved ∧ 現在欠けている観測値がbind済み ∧ requested resultがそのstateをbind可能`の場合だけ発行する。review観測では`observation_atom := observation identity + target identity + predicate identity + producer identity + invocation result identity + invocation result contract identity + terminal state`、`terminal state := value | missing | unreadable | terminal_failure`とする。atomのproducerはbind済みreview producerとし、tool invocationは観測源であってproducerではない。permission deniedをatom stateにしない。相互非依存のready atomは同じmodel stepから発行できるが、`observation_integration_allowed := 一invocation resultが各atomへ個別terminal stateを直接返す ∧ 一atomのnon-valueまたはinvocation failureが他atomの取得済みstateを消さない ∧ invocation result contractがaggregate non-success時も個別success stateをauthoritativeと固定`の場合だけ統合する。それ以外は別invocationとし、aggregate exit code、root推測、reviewer宣言または別atom成功から`value`を生成しない。artifact変更または失敗resultは入力を変えたpredicateだけを失効でき、consumer terminal後は未発行evidenceを失効する。`spec_ready=true`後の変更前evidenceは`target artifact / 明示read-only path / 適用中repository instruction / implementation choiceを解決するrepository authority`だけを許可し、`implementation_bound := 許可済みresultからtarget artifactと適用instructionがbindされ、全change effectとartifact間relationがadmission済みcurrent content上で実行可能な変更predicateと保持constraintを持つ一implementation choiceへbind済み`になったresultだけをterminalにする。追加evidenceは許可済みresultが`missing / unreadable / bind済みvalueまたはconstraintとの具体的矛盾 / allowed path内で充足不能 / 適用instructionによる別authorityの明示`を観測した場合だけ、そのresultと次evidence identityをbindして一件許可する。
- REVIEW_JUDGEMENT: bind済み独立reviewerはpacketと許可されたauthenticなobservation resultだけから`counterexample_found | no_counterexample_found | unavailable`の一terminalを形成する。`counterexample_certificate_ready := concrete witnessがvalue ∧ witness applicabilityを決める規範predicateと全入力がvalue ∧ positive applicability成立 ∧ 固定設計上の処遇との直接矛盾成立 ∧ 解消に一般設計のtarget / rule / permission / method / stop condition変更が必要`。`counterexample_found`は実際にcertificateへ使ったobservationだけへ依存し、certificate外のmissing等で失効させないが、applicability自体を変え得るatomがnon-valueなら成立させない。`no_counterexample_certificate_ready := 発行時に固定した全review scope identityをreview済み ∧ 固定manifest全atomがauthenticなvalue ∧ 全規範predicate適用後もcertificateなし`とし、未来の全instance不存在は要求しないが一atomでもnon-valueなら成立させない。`review_unavailable_ready := 前二certificateがfalse ∧ 未解決predicate identity固定済み ∧ それを閉じ得るdependency atomとnon-value state固定済み`とし、一般的不確実性や慎重さだけで`unavailable`にしない。counterexample成立時はcertificate dependencyを変えない未発行observationを失効し、成立しない場合だけ固定scope全体のno-counterexampleを判定する。
- RESULT_ADMISSION: rootはreviewerの意味判断を再実施せず、`result_admissible := result.operation_identityがcurrent bound review operationまたはTaskSpecがadmitを許すprior identityと一致 ∧ producer identityとsender identityがproducer bindingと一致 ∧ result kindがallowed kind ∧ result_use_permission=allowed ∧ 参照observationが実在・authentic・current ∧ terminal kindに必要なcertificateが揃う ∧ forbidden inputを根拠に含まない`を機械照合する。保存resultにはさらにcurrent subject / criterion / allowed result kind / packet basis / producer identity / dependency一致と`result_still_valid=true`を要求し、新規review execution permissionは要求しない。canonical locator、再構成した集合順、文字列表現またはroot独自semantic projectionとの完全一致を要求せず、bind済みproducer、許可入力、実observation、certificate dependencyおよびterminal kindの対応で真正性を確認する。inadmissible resultを別producerへ再割当てずrootが補完しない。
- RESULT_EFFECT: `result_dependency_set := subject identity + review criterion identity + result use permission identity + review scope identity + certificate形成に使ったobservation result identity集合`、`result_still_valid := dependency set内のidentityまたはvalueを変えた新resultがない`。新reviewの作成・起動だけを制御する`review_execution_permission`は保存result dependencyへ入れない。`counterexample_found`はwitness certificateだけ、`no_counterexample_found`は固定scopeとmanifest全atom、`unavailable`は未解決predicateとそれを閉じ得るnon-value atomへ依存する。result効果は対応subjectを含む未発行artifact変更と外側admission terminalだけへ投影し、別subject、別required outcome、無関係なread、既にterminalなreviewまたはtask全体へ伝播させない。terminal reviewをdependency変更後に再開せず、再判定が許可・必要なら変更後dependencyを持つ新review operation / packet / producer binding / result identityを形成し、再review禁止なら外側admissionを固定stop conditionへ閉じる。`result_effect_scope := 受領resultがtarget / permission / method / stop conditionを変え得る未発行operation class集合`、`decision_boundary(next) := next.class ∈ result_effect_scope`とし、falseの既知相互非依存invocationは分割せず同一model stepから発行する。
- CHANGE_TERMINAL: `subject_change_allowed := review_requirement=not_applicable ∨ review_requirement=not_required ∨ (review_requirement=required ∧ admitted no_counterexample_foundがactive)`。`not_applicable`は新permission生成ではなくC147由来の`implementation_bound`、明示permission、change predicateおよびvalidation gateへの委譲とする。`subject_change_denied := admitted counterexample_foundがactive ∨ admitted review unavailableがactive ∨ (review_execution_permission=denied ∧ activeなadmitted prior resultなし) ∨ packet unavailable`。counterexampleはcurrent design identityをrejectして対応変更を`blocked`、unavailableまたはpermission deniedは欠陥を確定せず対応変更を`unavailable`にする。一artifact変更invocationが複数subjectを含む場合は全subject allowedかつ全relation / constraint成立時だけ発行し、禁止subjectの除外でrequired outcome等を壊すなら一部変更しない。外側operationは必要な全operationでbind済みproducerのterminal resultが揃い、許可されたartifact変更とrequired validationが全successの場合だけ`completion_ready`にする。invocation / worker / sessionがnonterminal、result欠落、進行報告、集約文またはfinal responseで補完しない。review contract非適用ではC147由来terminal、counterexampleでは`blocked`、判断依存入力不足・review unavailable・permission deniedでは`unavailable`へ閉じる。
- VALIDATION_CLOSURE: `validation_predicate_ready := artifact変更完了 ∧ TaskSpec-required validationのpredicate / order / individual pass condition / stop conditionが全件bind済み ∧ TaskSpecまたはcommand evidence protocolがexact commandを明示したvalidationだけそのcommandがbind済み`。`validation_predicate_ready=true ∧ producer=root`の場合、TaskSpecまたはcommand evidence protocolの「順に」「1 commandずつ個別」は、1回のcustom exec wrapper内で全required validationをbind順の個別`exec_command`として発行することを意味し、command resultをmodelへ返して次commandを別custom tool callで発行することを意味しない。各exit codeをwrapper内で確認し、nonzeroまたはunavailableなら後続を発行せず、shell compound commandへ結合しない。producerがroot以外の場合も全required validationを個別invocationとして同一model stepから発行する。完了済みの全resultを一度だけmodelへ返す。全件successかつ全result bind済みなら、TaskSpec追加要求またはresult失効がない限りread / validationを追加せずterminalを判断する。欠落 / non-success / unexpected stateはoperationをnonterminalにする。target探索 / 変更前 / review finding / 未固定methodまたはrecoveryへ適用しない。
- VALIDATION_PLAN: artifact変更後の検証開始前に、required validationと完了判定に必要と確定しているdiff / status等を一つの実行票へ順にbindする。TaskSpecまたはcommand evidence protocolがexact commandを明示しない場合、その未固定commandをmissing validation identityまたはrepository evidenceの開放条件にせず、既に受領したTaskSpec / 適用中instruction / target evidenceの範囲から`METHOD`として選び、実行票発行時にcommandへbindする。検証success後はmodelへ戻らず実行票の残りを発行し、全result受領後に一度だけ完了を判断する。実行票完了後はTaskSpec追加要求またはresult失効がない限りtoolを追加しない。validation wrapperがcell ID付きnonterminal resultを返した場合、その返却を実行票の完了判定へ使わず、実行票全体がterminalになるまで同じcell IDへのwaitだけを発行する。commentary / 進捗報告 / 判断 / 別toolを先に発行しない。
- METHOD: TaskSpec明示手段だけを固定する。未固定手段はpredicateを変えずpermission内でexecutorが選び、validationでは既に受領したTaskSpec / 適用中instruction / target evidenceの範囲から選択して実行票発行時にcommandへbindする。exact commandの選択だけを理由にrepository evidenceを追加しない。invocationのfailed / unavailableをpermission否定 / terminalにせず、未固定手段があれば同一predicateへ向けて継続する。明示禁止 / permission否定は停止し、回避しない。
- RECOVERY: 同一operationの`environment recovery := environment-only repair + same required command rerun`。組の開始時だけ`environment_recovery_max`を消費し、未固定手段の選択は数えない。
