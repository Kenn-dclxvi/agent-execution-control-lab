# C280の指示文を短くする案の検討（r1）

2026-10-09。C281以降の機序を足すのではなく、C280自体の文を短くして、GPT-6.1 Sol LowとSonnet 5.5 lowの固定分を下げられるかを検討した記録。[設計原則](prompt-control-design-principles.md)の全文を読んだうえで、保存済みの結果と、C276からC280までの設計記録を読み取り専用で確認した。新しいモデル実行はしておらず、Candidateは作成しない。

## 検討の目的（束縛）

- 系列：汎用指示の改善系列。基準はC280（`the-caption-3ce91a4-execution-control-outcome-binding-r1`、全文1,470バイト）。
- 必要な効果：C280の機序（成果の束縛、事前の方針、担当の対応、事前調査の限定）を保ったまま、指示文の固定分を下げる。
- 背景：[判定表への追記](mechanism-establishment-table-r1.md)のとおり、Sol LowとSonnet lowのANDでC280を超える要素は見つかっていない。Sonnet lowでは、C296の増加の75%が指示文の長さとリクエスト数による固定分だった。

- C277〜C279の当初の結果は、評価環境のCodexがユーザーのグローバル指示（`~/.codex/AGENTS.md`、C276の4項目と同じ内容）を読み込んでいた時期の計測であり、項目を外した効果を正確には表していない（[C279の設計記録の追記](candidate279-empty-root-agents-design.md)）。共通指示を空にした再試験はC277だけで、A01の失点が戻った。

## 短くする案の検討

### 案A：意味を保ったまま縮める

4項目を、述語を落とさない範囲で書き直し、バイト数を数えた。

| 項目 | 現在 | 縮めた案 | 減る量 |
| --- | ---: | ---: | ---: |
| 成果の束縛 | 782 | 746 | 36 |
| 事前の方針 | 177 | 173 | 4 |
| 担当の対応 | 261 | 239 | 22 |
| 事前調査の限定 | 227 | 224 | 3 |
| 合計 | 1,447 | 1,382 | 65 |

65バイトは、Sonnet lowの1反復あたり約1.4千トークン（C280の合計の0.16%）で、5回の1反復合計の標準誤差（約2.3万トークン）の16分の1にとどまる。書式（見出しの`###`、箇条書きの`*`、強調記法）の統一も、バイト数はほとんど変わらない。成果の束縛の項目は、消去法による推測を閉じるために言葉を選んだ文であり、書き直しは機序を変える危険がある（C292、C293で、一句の欠落が機序を壊した）。

### 案B：項目を外す

- 成果の束縛を外すと、A01の誤経路（未確定の結果を推測して変更・テストへ進む）が再び開く。C280の主な機序であり、Opus・Solの両方で成立している。
- 事前の方針を外すと、共通指示を空にした条件でA01の失点が戻った（C277の再試験）。
- 担当の対応と事前調査の限定は、外した単独の効果が測られていない。外したC278はトークンが増えた。
- C280全体を外した場合（control-free）でも、Sonnet lowで減る固定分は1反復あたり約3.1万トークン（3.7%）にとどまる。Opus mediumでは、control-freeはC280よりトークンが13%多かった。

## 判定

- **案Aは`candidate_not_created`とする。** 減る量（0.16%）は計測で検出できず、成果の束縛の文を書き直す危険に見合わない。設計原則の「文字数を減らしたことだけを改善の根拠にしない」にも当たる。
- **案Bは`candidate_not_created`とする。** 外すと、C280の機序（A01の誤経路の閉鎖）か、共通指示を空にした条件で確かめた働きを失う。外すことで減る固定分は小さい。
- C280の固定分は、Sonnet lowの増加の主因ではなかった。Sonnet lowでC280を上回ったのは、C281以降に足した文（C296で1,753バイト、C295で3,424バイト）と、それに伴うリクエストの増加である。

## 残っている課題

これは、問題が解決したという判定ではない。

- Sol Low（Codex）とSonnet low（Claude）の両方で、C280を超える要素はまだ見つかっていない。Sonnet lowでは、C281以降の機序（変更前に戻る回数の減少、検証の一括化）が成立しない。
- 検討を続ける方向は二つある。一つは、主なセルの選び方を見直すこと（Opus 5.5 mediumでは、C147とC291が要求数をcontrol-free比で約19%減らした）。もう一つは、Sonnet lowで機序が成立しない理由を、保存traceから分解し直すことである。Sonnet lowはC280の時点で、変更前の要求が1.56回と少なく、検証も1要求で終える実行が9/40件と少ない。後者で減らせる余地があるのは、検証の分割である。

## 判断の限界

- C276〜C279の項目単独の証拠はGPT-6 Luna High（N=5）によるもので、Sol LowとSonnet lowで同じ働きをするかは確かめていない。
- 固定分の見積もりは、トークン/バイトの比（0.3247）と要求数の平均（64.6回/反復）による概算である。
- この記録は採用、release、本体反映を決めない。
