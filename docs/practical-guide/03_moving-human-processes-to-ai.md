# 人間の開発工程を、AIに移すとき

> 実務ガイド 3 / 3

AIにコードを書かせるとき、人間のチームのやり方を真似したくなります。

計画担当が方針を立て、実装担当が書き、レビュー担当が確認して、指摘があれば差し戻す。分かりやすく、最初の形としては悪くありません。

ただ、そのままAIに移すと、**担当の数だけ、同じファイルを読み直し、同じ判断をやり直す**ことになります。[1本目](01_why-instructions-change-your-bill.md)で見たとおり、AIでは一手ごとに料金がかかります。

この記事では、人間の工程から何を残し、何を変えればよいかを説明します。

## 担当ではなく、守りたいことを残す

人間の工程には、それぞれ守りたいことがあります。AIに移すときは、担当という箱ではなく、その中身を取り出します。

| 人間の工程 | 本当に守りたいこと |
| --- | --- |
| 計画担当が方針を立てる | やることが決まる前に変更しない |
| 監査担当が手順を確かめる | 必要なテストを省かない |
| レビュー担当が確認する | 欠陥を見逃さない |
| 全員の合意で完了する | 根拠のないまま「終わった」と言わない |

取り出してみると、そのいくつかは、担当を置かなくても指示の一文で守れます。

たとえば「やることが決まる前に変更しない」は、[2本目](02_how-to-write-instructions-that-cut-cost.md)の1行目そのものです。計画担当がいなくても、この1行で、Freeで起きていた「推測で作業を始めてしまう」失敗は、4つのAIすべてでなくなりました。

「根拠のないまま終わったと言わない」も、2本目の3行目（最後の確認を一度だけ行い、すべて成功なら報告する）で守っています。

## 例：計画役・実装役・監査役の3人を、1人にする

よくある3エージェント構成を、1つのエージェントに置き換える場合を考えてみます。

```text
計画役：依頼を読んで、方針を立てる
実装役：方針に沿ってコードを変える
監査役：テストを実行し、手順が守られたかを確かめる。だめなら実装役に差し戻す
```

この構成では、3人がそれぞれ依頼とコードを読みます。差し戻しのたびに、また全員が読み直します。

1人にするときは、各担当が守っていたことを、指示の条件として残します。

| 担当が守っていたこと | 1人のときに残す条件 |
| --- | --- |
| 計画役：結果を推測で決めない | 結果が依頼から決まらないなら、作業を始めずに確認する（2本目の1行目） |
| 計画役：必要以上に調べない | 方針が決まったら、念のための調査をしない（2本目の2行目） |
| 監査役：必要なテストを省かない | 依頼や指示が求める確認を最後の変更の後に実行し、作業ツリーの状態と一緒に確かめる（2本目の3行目） |
| 監査役：失敗を「完了」と言わない | 確認がすべて成功したときだけ報告する（2本目の3行目） |

実装役の仕事は、そのまま1人のエージェントの仕事になります。方針を立てる・コードを変える・確かめるを一人で続けて行うので、担当の間で依頼やコードを読み直すことがなくなります。

一方で、残さないものもあります。監査役が「差し戻すかどうか」を毎回判断していた部分は、テストの結果（成功か失敗か）で決まるので、判断する担当はいりません。

そして、置き換えられないものもあります。テストでは見つからない欠陥を、別の目で探すことです。これが必要なら、1人にした後も、レビューだけは別に置きます（この記事の最後で説明します）。

## 役職ではなく、壊れ方から考える

「監査担当を置く」だけでは、何を防ぎたいのかが分かりません。監査担当が防いでいたものを並べてみると、実は別々の失敗です。

- 必要なテストを省く
- 頼まれていないファイルまで変える
- 失敗しているのに「完了」と報告する

失敗が違えば、防ぎ方も違います。一つの「監査担当」に戻す前に、失敗ごとに、AIが自分で当てはめられる条件を書けないかを考えます。

## 担当を分けるのは、必要なときだけ

AIの作業を複数の担当に分けることもできます。ただ、分けると、担当の間で同じファイルを読み、同じ判断を繰り返しやすくなります。

最新版の6行には、担当の分け方を書いた項目がありません。前の版には「作業を分けるときは、担当と、それぞれが返す結果を先に決める」という項目がありました。しかし、今回の14課題では、GPT-6.1 Sol LowとClaude Code Sonnet 5.5 lowで確かめた限り、AIが作業を分けることが一度もありませんでした。効果を確かめられなかったので、外しました。

担当を分けたくなったら、先に次の3つに答えてみてください。

1. その担当にしか出せない結果は何か
2. その結果がなければ、完了できないのか
3. 同じ判断を、ほかの担当がやり直さないか

答えられなければ、担当を増やすより、今の作業に条件を一つ足すほうが効くかもしれません。

## レビューをやめろ、という話ではない

別の視点で確認するレビューには、価値があります。書いた本人とは違う目で見ることは、指示の一文では置き換えられません。

今回の6行が守れているのは、「推測で始めない」「確認を省かない」「根拠なく終わらない」といった部分です。欠陥を見つけるレビューそのものを置き換えたわけではありません。

なので、目指すのはレビューをなくすことではありません。**レビュー担当に任せていたことのうち、条件で守れるものは条件に移し、本当に別の目が必要なところにだけ担当を置く**ことです。

## これだけ覚えてください

**工程を一つ足すときは、「誰を増やすか」ではなく、「何が壊れるのを防ぐか」から決める。**
