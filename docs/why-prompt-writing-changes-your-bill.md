# 指示書を厚くしたら、実行コストが半分以下になった

AIエージェントへの指示書を147通り試した結果から、実務で効く2点だけ抜き出す。

細かい話は[技術報告](execution-control-measurement-report.md)と[課金換算比較](candidate125-billing-equivalent-cost-comparison.md)にある。

---

## 結論の表

**指示書を1文字も書いていない状態**と、**147通り試した末の到達点**を、同じ条件で比べた。14個の課題を1セットとして各5回、計70回ずつ実行している。

| | 指示書なし（0バイト） | 到達点 | 差 |
| --- | ---: | ---: | ---: |
| **最上位ファイルの分量** | **0 B** | **10,772 B** | **書き足した** |
| **実行トークン** | 3,488,611 | 1,447,626 | **`-58.5%`** |
| 所要時間 | 19.4分 | 14.2分 | `-26.9%` |
| 品質（70回中の満点数） | 65 | **70** | 5回ぶん改善 |

**指示書を1万字ぶん書き足したのに、実行トークンは6割減り、時間も短くなり、品質は上がった。**

---

## 論点1：書き足すと安くなる

普通は逆だと思われている。プロンプトを短くすればトークンが減る、と。

**測ったら成り立たなかった。**

短くする方向で7通り試した。文字数を`-1.4%`から`-39.1%`まで削った結果がこれである。

| 削った文字数 | 実行トークンの変化 |
| ---: | ---: |
| `-1.4%` | **`+31.4%`** |
| `-3.0%` | **`+1.2%`** |
| `-4.7%` | 横ばい（合計 `+0.3%`） |
| `-7.0%` | **`+14.3%`** |
| `-32.6%` | **`+6.5%`** |
| `-36.6%` | **`+9.4%`** |
| `-39.1%` | **`+13.2%`** |

**7つのうち6つで、短くしたのに実行トークンが増えた。** 残る1つも横ばいである。

念のため、逆にわざと中核を全文重複させて**増やした**対照も試した。こちらは`+28.9%`だった。**増やしても増える。**

### なぜか

**トークンを食うのは指示書そのものではなく、指示書を読んだAIが起こす行動である。**

AIは読んだあと毎回こう選んでいる。

- どのファイルを探しに行くか
- 子エージェントを起動するか
- もう一度モデルに考えさせるか
- 検証をいつ何回走らせるか

指示書を削ると、**選択肢が消えるのではなく、判断がAI任せになる**。探しに行く。念のため起動する。もう一度考える。だからトークンが増える。

逆に、書き足して選択肢を1つ潰すと、その分だけ動かなくなる。

| 書き足したこと | 効果 |
| --- | --- |
| 決まっていない値があるなら着手するな | トークン`-77%` |
| 変更前に証拠を探すのは原則禁止。見ていいものだけ列挙する | トークン`-6%` |
| 検証は変更後にまとめて出す。全部通ったら追加で調べない | 18回反復して18回とも同方向 |
| 分岐が決まっている作業は、経路を先に確定してから動く | トークン`-53%` |

**効かない書き足しもある。**

| 書き足したこと | 結果 |
| --- | --- |
| 「適切に判断せよ」 | トークン`+4.5%` |
| 「◯回まで」「◯行まで」で打ち切らせる | 正常な状態を異常と誤判定して止まった |
| 索引を置いて「ここを見ろ」と教える | 索引は読んだが探索は減らず、トークン`+8.7%` |

最後のが分かりやすい。**在り処を教えても、探すのをやめろとは言っていない。** だから両方やる。

**効くのは分量ではなく、選択肢を1つ潰す一文かどうかである。**

---

## 論点2：金額はトークンほど下がらない

トークンが6割減ったから請求も6割減る、とはならない。**単価が区分ごとに60倍違うからである。**

GPT-5.6 Solの公開単価（100万トークンあたり）。

| 区分 | 単価 | 通常入力を1としたときの倍率 |
| --- | ---: | ---: |
| 通常入力 | $5.00 | 1倍 |
| **キャッシュ入力** | **$0.50** | **0.1倍** |
| 出力 | $30.00 | **6倍** |

エージェント実行では、同じ指示書とファイルを何度も読み直すので**トークンの大半がキャッシュ入力**になる。指示書なしの条件では**85.8%**がキャッシュだった。

つまり**減らしているトークンの大半は、もともと1/10の単価だったもの**である。一方、削れずに残る出力は6倍で課金される。

実測（区分ごとに単価を当てた、14課題1セットあたりの中央値）。

| | 指示書なし | 到達点の1つ前の版 | 差 |
| --- | ---: | ---: | ---: |
| 換算額 | $5.06 | $3.05 | **`-38.2%`** |

**トークンでは6割減っても、金額では4割弱の減少にとどまる。**

出力の効きも見ておく。到達点の1つ前の版では、出力は全トークンの`2.05%`しかない。**それが金額では`27.1%`を占める。**

### キャッシュ率が高いほど安い、でもない

参考までに、指示書を人間の開発工程どおりに書いた版（この研究の出発点）はキャッシュ率`86.9%`で最も高い。**それでいて最も高額である。** 率ではなく絶対量で決まる。

## 使うときの注意

- **金額の行は、到達点ではなく1つ前の版の数字である。** 区分ごとの内訳を保存しているのがそこまでで、到達点の金額分解は出していない。また採点条件と実行環境の版が上の表と揃っていない。**桁感をつかむための数字**として読んでほしい
- **換算値であって請求書ではない。** 保存トークンに公開単価を掛けたもので、契約プランによって変わる
- **1つのリポジトリ、1つのモデル系列でしか測っていない。** 別の対象や別のモデルで同じ比率が出る保証はない
- **「選択肢を潰す」は説明の枠組みであって法則ではない。** 実際、潰したつもりで作った候補が48件中37件は採用に至っていない
- **到達点にも欠陥は残っている可能性がある。** 1,400回まわして全部満点だったが、それは1,400回では出なかったというだけである

数字の出どころと、どこまで言えてどこから言えないかは[技術報告](execution-control-measurement-report.md)に全部書いてある。
