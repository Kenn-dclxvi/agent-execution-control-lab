# Candidate319 C318に、存在を確かめていない場所へ指示や正本を探しに行かないことを加える

2026-10-15。利用者の判断（ClickのF06で、C316以降に増えた存在しない場所の探索が停止を生んだのは劣化なので直す。できればFreeでも起きていた同じ探索も正せる方向で）を受けて、Candidate本文の作成前に固定する設計記録。[設計原則](prompt-control-design-principles.md)の全文を読み、「Candidateを作成する前の確認事項」の項目1〜9に対応させた。計測と記録は[計測と記録の基準r2](shared-instruction-evaluation-criteria-r2.md)に従う。

## 目的と役割

- ベース：C318（`the-caption-3ce91a4-delegated-state-source-r1`）。Click用は`click-00e592c-delegated-state-source-r1`。
- 変更：2行目（事前調査）の1文目の後に、次の1文を加える。ほかの項目と文は変えない。

> 指示や正本は、依頼が名指ししたものと作業ツリーで見つかったものだけを使い、存在を確かめていない場所を指定して探さない。

- させたいこと：指示や正本は、依頼が名指ししたものと、作業ツリーで見つかったもの（階層ごとの`AGENTS.md`など）から読む。エージェントの決まった場所（`.agents`、`.codex`など）を、あるかどうか分からないまま指定して探さない。

## 1. 比較の基準と、正常な最短経路

基準はC318。ClickのF06の正常な最短経路は、開始時の状態（HEADと`git status --short`）を確かめ、`test_echo_color_flag`を読み、標準出力での`isatty=False`の確認を足し、3つの必須gateを通して終えることである。Freeは、識別情報を`git rev-parse`と`git status`だけで確かめていた。

## 2. 保存traceで確認した問題経路

[F06の失敗の分析](../evaluations/targets/click/results/click-f06-failure-analysis_2026-10-15.md)より。

- Clickで、存在しない`.agents`・`.codex`を指定して探したCodexのrunは、F06でFree 1 / 50、C316 25 / 40、C318 7 / 10。A02、F01、F02でもC316で16〜19 / 40に増えた。探したのは`AGENTS.md`、`*identity*`、`*verified*`、`*runner*`などで、TaskSpecの「runner-verifiedなisolated checkout」の正本を探す動きに見える。
- 探索は、存在しない場所を指定したため終了コード2で失敗した。AstraのF06で3件（C316 2 / 20、C318 1 / 5）が、この失敗をTaskSpecの「環境failureなら迂回せず停止する」に当てはめて、変更せずに停止した（1点）。
- THE-CAPTIONでも同じ探索がFreeから起きていた（Sol 22 / 70、Astra 8 / 70。C316・C318ではSol 14〜16 / 70、Astra 5〜6 / 70）。THE-CAPTIONでは停止に至っていない。

## 3. 開いている記述と、TaskSpec・正本で防げない理由

開いているのは、指示や正本をどこから探してよいかの範囲である。C316・C318の1行目は、結果が「それが従うよう求めている指示や正本」で決まるとするが、その指示や正本をどこに探すかを限っていない。Codexは、エージェントの決まった場所に指示があるかもしれないと考え、存在を確かめないまま指定して探す。

TaskSpecは作業の対象と検証を定めるもので、エージェントが自分の指示をどこに探すかは定めない。リポジトリの正本も、存在しない場所への探索を防げない。

## 4. 追加する条件の全件

2行目に1文を加えるだけである。適用は、探索のコマンドが指定する場所が、依頼で名指しされたか、作業ツリーで（それまでの出力で）見つかっているかで決まる。どちらもtraceで確かめられる事実で、必要性の判定をモデルに任せる条件ではない。

## 5. 禁止行動、開放経路、閉じる境界、反証

| 記録する内容 | 内容 |
| --- | --- |
| 禁止する行動 | 依頼が名指ししておらず、作業ツリーで見つかってもいない場所（`.agents`、`.codex`など）を、コマンドに指定して指示や正本を探すこと |
| 現在の開放経路 | 1行目の「従うよう求めている指示や正本」が、探す範囲を限っていないこと。Codexの、エージェントの決まった場所に指示を探す癖 |
| 閉じる境界 | 指示や正本を探す範囲を、依頼が名指ししたものと作業ツリーで見つかったものに限る |
| 正常な処理の保持 | 作業ツリーにある階層ごとの指示（THE-CAPTIONの`src/AGENTS.md`など、Codexで44〜51 / 70件が読む）と、依頼が名指しした指示（ClickのF10の`src/AGENTS.md`）は、これまでどおり読める。作業ツリー全体を一覧するコマンド（`rg --files`など）も禁止しない |
| 反証する構成 | 先に存在を確かめるコマンド（`ls .agents`など）を出して確かめてから探す構成がありうる。その確かめるコマンド自体が、存在を確かめていない場所を指定するので、この文に当たる。作業ツリー全体の一覧で見つからなければ、その場所はない |

この文は禁止の文で、新しい操作の発行を求めない。ただし、存在を確かめるための一覧のコマンドが増える可能性がある。標準14項目で、コマンドの数と費用を見る。

## 6. 維持する正常経路

1行目（C318）、3行目以降と、2行目の1文目・最後の文は変えない。

## 7. 新しく増える判断と、変更対象外への影響

増える判断は、探そうとする場所が、依頼で名指しされたか作業ツリーで見つかっているかを確かめることだけである。影響が出うるのは、階層ごとの指示を読む動作（THE-CAPTION）が減る方向の変化で、読むべき指示を読まなくなれば品質が下がる。THE-CAPTIONの標準14項目で品質を見る。

## 8. 評価ケース、比較単位、比較条件、記録する項目

1. **局所の確認（登録しない診断）**：ClickのF06、F01、A02を、Codex（Sol Low、Astra Low）で各5回。存在しない場所の探索の件数を、C318（F06 7 / 10）とC316（F06 25 / 40、F01 19 / 40、A02 16 / 40）と並べる。
2. **標準14項目**：通過した場合、THE-CAPTIONとClickのStandard14を4モデルで各N=5測り、C318と比べる。品質、費用、経過時間と、存在しない場所の探索の件数、階層ごとの指示を読んだ件数を記録する。

## 9. 停止条件

- 局所の確認で、存在しない場所の探索が減らない（C318と同程度に残る）場合は、標準14項目へ進まない。
- 標準14項目では、互換条件の不一致、無効なrun、採点不能を停止条件とする。品質と費用は計測として記録し、達成目標を置かない（r2）。

## 判断の限界

- 探索が、1行目の「従うよう求めている指示や正本」によって誘われているという見立ては、Codexの記録にモデルの考えが残っておらず、確かめられていない。この文は、見立てに頼らず、探してよい範囲を事実で限る。
- 停止はF06で約9%の探索からしか起きず、停止の減少はN=5では見えにくい。探索の件数を主に見る。
