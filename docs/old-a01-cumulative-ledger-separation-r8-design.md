# 累積削減版r8：初回配送からledger組立を分離

目的はr5に累積した画像・資料除外と処理分離を保持し、モード変更の判断へ混ざって配送される資産合計・利回りの組立処理を減らすこと。r6・r7のテスト共通化は含めず、全テストとその配置はr5のままにする。

## 保存ログで確認した対象

r5～r7の全6件でsrc/domain/universal_ingester.py全文がcommandの出力へ一回ずつ含まれた。その中の1,895バイトは、modeを解決した後の市場資産・外部資産・取得原価・合計値・利回りとShadowLedgerの組立である。受け取った初回情報は後続応答の履歴へ持ち越される。ここを既存の資産計算ファイルへ移すと、同じ入口読取りでこのblockが配送されなくなる。[全文一致で確認した配送証拠](old-a01-r8-delivery-selection-evidence.json)を保存する。

## 変更と保持する判断根拠

build_shadow_ledgerの署名、units_modeのdaily既定値、allow_live_csv_in_strict、日付決定、_resolve_market_unitsの呼出しを元のまま残す。解決後の組立部分だけを既存src/domain/_universal_ingester_assets.pyへ移し、元メソッドはunits_resolutionをそのまま渡して戻り値を返す。処理を削除せず、展開すると元のASTへ一致することを確認する。組立メソッドの呼出しという依存関係は増えるため、コードの配置が全く同じとは呼ばない。

元の__init__、run、daily/strictの分岐、snapshotの欠落・不正とlive CSVの許可、CSV読込みは元ファイルの同じ処理として残す。TaskSpecの変更先未指定、元仕様のdaily、snapshotテストのデータ・期待値・位置、一般テストの入口と本体も変更しない。組立の結果にsource情報が保存される処理は移動先に残り、元39テストの観測を保持する。必要なら資産側全体を読むことも合法なままにし、新しい読取り禁止・順序・停止指示は加えない。

初回配送が減る見込みを、総トークン減少の保証とは呼ばない。移動先の追加読取りで相殺されるかをN2の操作と配送で観測する。応答回数は原因診断であり、独立した合否指標やモデルへ課す工程にはしない。

## 固定条件と確認

r5の固定素材から複製する。変更2ファイルと対応する派生HEAD・tree・stage以外の204ファイル、除外55件、元JSON TaskSpec、Free、全authority・仕様、CLI0.159.0、Astra Low、共有Python・依存、元oracle・Rating14、permission、全担当トークンとCLI時間の計測境界を保持する。detached・clean、r5 HEADを親とする履歴と既存refsを維持する。別素材系列で旧run poolへ合算せず、Layer4非登録。

関数展開後の元AST一致と、元39テストの収集ID・成否を両素材で確認し、事前照合証跡を保存後に並列Low N2だけを発行する。M24・実同時2、個人指示・追加回答なし、再試行なし。N20へ自動延長しない。動作、入力の各応答への累積、実測トークン、CLI時間と待機を分けて記録する。停止とテスト先行の平均差だけを変更の効果へ帰属させない。
