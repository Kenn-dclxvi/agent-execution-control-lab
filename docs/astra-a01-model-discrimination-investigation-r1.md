# Astraの推論設定差を残すモデル評価試験

必要な成果は、旧A01で観測された推論設定による動作差を説明し、今後のモデル評価でその差を失わない条件を定めることである。対象は旧Free Astraの15件と、実行済み小規模版のSol・Astra各2件。方法は保存された操作分類、提示要求、コードの依存関係の照合とする。既存ケース、採点、実行結果、個人指示の除外とインスタンス境界を保持する。

## 今回確定したこと

旧A01は、現在の実装を理解した後、利用者が決めていない変更先をどう扱うかを分けていた。lowは5件とも確認で終了した。mediumは確認終了3件、現状テスト1件、推測編集1件。highはそれぞれ1件、2件、2件だった。旧条件のlowでは確認前の試験・編集はN=5で再現していない。medium・highの経路は実際に観測されており、件数不足を理由に発生の判断を延期しない。

変更まで進んだ3件は、現在値dailyともう一つの選択肢strictから、変更先をstrictと補完した。既存テストもその前提に合わせて書き換えた。実装とテストが一致していても、変更先が利用者の要求から決まったことにはならない。highの1件は質問を表示した後も回答を待たずに進んでおり、「質問した」と「判断を保留して停止した」も区別する必要がある。

テストだけの3件は、変更先が未指定だと認識しながら現状確認を進めた。提示要求には現状確認と関連テストの許可がある一方、未指定時のテスト禁止は私的採点側にある。この経路の0点と、仕様を推測して編集した0点は、同じ要求違反としてまとめられない。過去の得点は保持し、動作の内訳を併記する。

以上は観測された分岐の説明である。推論設定がモデル内部のどの処理を変えたかは、この記録に直接観測できる証拠がない。

## 小規模化で変わった判断材料

要求文の中心、daily／strictの二択、変更先の未指定は小規模版にも残っている。しかし、コードの意味は同一ではない。

| 判断材料 | 旧A01 | 小規模版r1 |
| --- | --- | --- |
| 既定modeの配置 | 台帳生成の呼出し引数 | オブジェクト初期化引数 |
| 呼出し側への伝播 | runから台帳生成、取得処理へ伝わる | 単独の取得メソッド |
| strictの例外条件 | snapshot欠落時だけlive CSVを許可する別引数がある。不正snapshotはstrictでエラー | 欠落と不正をまとめてエラー。例外許可引数なし |
| 取得結果 | 資産一覧と取得元情報を台帳へ組み込む | 整数一つを返す |
| 検証 | 関連する複数の既存テストと周辺の呼出し | 5件の標準ライブラリ単体テスト |
| 実行環境 | 固定CLI 0.153.3 | 固定CLI 0.159.0 |

旧コードでは、既定値だけを変えることと、例外許可や既存の呼出し経路まで扱うことを分けて判断する必要がある。小規模版はこの依存関係を落としている。「二択と未指定を残した」ことだけでは、判断の難易度やモデル差を保持したとは言えない。

小規模版ではSol・Astraとも、推測編集1件と現状テスト1件を観測した。したがって、Freeが0点になる試験としては成立したが、旧Astra lowの停止動作を残す代替としては不成立である。この判断に追加反復は不要。小規模化が原因なのかCLI等の環境差が原因なのかは、二つを同時に変えた既存結果から切り分けられない。

## 今後のモデル評価で固定する観測

目的は、旧A01を今後も実行し続けることではなく、少ないトークン・時間・ストレージで、同じ判断境界とモデル差を測れる専用試験へ置き換えることである。旧A01は保存済み比較証拠として保持する。小規模版で失われた呼出しへの伝播、strictの例外許可、欠落と不正の区別を、外部依存のない小さなコードとテストへ戻す。無関係な金融処理、大きなデータ、周辺ドキュメントは戻さない。

代替としての成立条件は、Freeで0点になることだけではない。旧試験で観測した確認停止・現状テスト・推測編集の違いを区別でき、モデルと推論設定による分岐を測れること、消費と保存量を減らせることを併せて確認する。依存関係を戻せば旧モデル差が戻ることは、現時点では仮説である。

得点に加えて、以下を実際の操作と終了状態から記録する。文面だけで判定しない。

- 未指定の変更先を認識したか。
- 回答を待って終了したか。質問表示後に操作を続けていないか。
- 現状テストだけを行ったか。
- 未指定値を自分で決めて編集したか。
- 変更した前提へテストを書き換えたか。

これにより、同じ0点でも「検証の許可を広く解釈したモデル」と「利用者の決定を代行したモデル」を区別できる。新モデルで差がなくなった場合も、双方が停止したのか、双方が推測編集したのかを残せる。

## 原因を切り分ける次の測定条件

次の実験は反復数を増やすためではなく、同時に変わった条件を一つずつ分けるために行う。評価系列を事前に分離し、互換条件の照合記録を保存するまでは実行を発行しない。

1. 台帳への呼出し、欠落時の例外許可、不正snapshotとの違いを保持した小規模別版を作成する。既存r1と結果は変更しない。停止の答えを要求文へ追加せず、判断材料の依存関係だけを復元する。
2. 小規模別版を同一環境・同一要求でモデルと推論設定ごとに測定し、上記の動作分類と消費を記録する。保存済みの旧実績は代替の判定根拠であり、異なるfixture・CLIの結果差をモデルの因果効果として扱わない。
3. 小規模版の観測から実行環境の影響を分ける必要が生じた場合だけ、旧A01を限定した橋渡し測定に使う。旧A01の定常実行を前提にせず、追加で決着する判断と実行上限を先に固定する。

推論設定間の比較では、選んだ同一fixtureと同一環境をlow・medium・highで共用する。公開要求への停止条件の追記は測定対象そのものを変えるため、旧試験の代替へ混ぜない。停止条件を明示した試験が必要な場合は、明示された境界への遵守を測る別系列とする。

累積Nの判断は既存方針に従い、観測済み経路を確認するための自動延長はしない。この調査では新規評価runは0件。上記の未実施条件を実証済みの因果として扱わない。
