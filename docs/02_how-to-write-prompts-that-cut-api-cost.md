# API料金を下げるプロンプトには、判断条件を書く

> 実務者向けExecution Controlシリーズ 2 / 8

## 結論

[前の記事](01_why-prompt-writing-changes-your-bill.md)では、指示が曖昧だとAIが迷い、余計な探索や検証でAPI料金が増えると説明しました。

では、その迷いを減らすには、実際に何を書けばよいのでしょうか。

今回は、AIが判断をやり直す場所を作業の流れに沿って見つけ、そこへ何を書くかを説明します。

**AIが作業中に迷う場所へ、「進んでよい条件」と「止まる条件」を書きます。**

長く書けば安くなるわけではありません。実運用版にはさらに細かな条件がありますが、まずは普段のプロンプトにも使える考え方だけを説明します。

## 料金が増える場所から逆算する

前の記事では、指示が曖昧なときに起きる無駄として、次の例を挙げました。

- どのファイルを見るか探し回る
- 念のための調査を始める
- 誰が作業するか考え直す
- 終わった後も確認や検証を繰り返す

これらを止めるには、ファイル名やコマンドを細かく指定するだけでは足りません。AIが判断をやり直す原因を先に閉じる必要があります。

前の記事で紹介した迷走は、主に「成果」「変更開始」「担当と結果」「調査」「完了」という5つの判断が曖昧なときに起きます。この5項目は、AIが判断をやり直す場所を、作業の順番に沿って潰していくためのものです。

## プロンプトに書く内容

5つの判断と、料金につながる無駄の関係は次のとおりです。

| 判断する場所 | 曖昧だと起きる無駄 | プロンプトに書く条件 |
| --- | --- | --- |
| 何を成果にするか | 期待する結果を推測し、違う方向へ進んでやり直す | 利用者が決める結果と、AIが選べる実装方法を分ける。結果が不足している場合だけ質問する |
| いつ変更を始めてよいか | 方針が固まる前に変更し、後から修正し直す | 必要な成果、変更箇所、直し方、維持する動作が一つの方針になってから変更する |
| 誰のどの結果で完了とするか | 同じ判断を複数回行ったり、待つべき結果を探し直したりする | 独立した作業を分ける場合だけ、担当、判定対象、必要な結果を対応づける |
| 何を調べるか | 念のための探索や、決定後の再確認を続ける | 変更箇所と方法を決めるために不足している情報だけを調べる |
| 何を確認したら終わるか | 終わった後も確認や検証を繰り返す | テスト、順序、失敗時の停止、実行中の待機、完了条件を先に決める |

成果を書くと推測が減り、変更開始を書くと早すぎる編集が減り、調査条件を書くと探索しすぎなくなり、完了条件を書くと検証の繰り返しを止められます。つまり、5項目を書く目的は、文章を増やすことではなく、AIが同じ判断に使うトークンを減らすことです。

この5項目は考え方の入口であり、実運用版の短縮ではありません。

上の表を指示として書くと、次のとおりです。

```text
利用者が決める変更後の動作や値が書かれていない場合は、現在のコードやテストから推測せず、その結果だけを質問する。ファイルの場所や実装方法が未確認なだけなら、プロジェクト内で決めて進める。
変更前に、必要な成果、変更箇所、直し方、維持する動作を一つの方針にまとめ、どれか決まらない間は変更しない。
独立した作業を分ける場合は、開始前に担当、判定対象、必要な結果を対応づけ、担当の完了結果だけを受け取り、同じ判定を別の担当や進捗報告でやり直して補わない。
変更前の調査は、変更箇所と方法を一つに決めるために不足している情報だけに絞り、決まった後は、念のための探索、再確認、履歴調査をせず変更へ進む。
変更後は、必要なテストと差分確認を一つの実行票として先に固定し、実行中は同じ結果だけを待ち、失敗なら後続を止め、全結果がそろったら追加確認せず一度だけ完了を判断する。
```

この5つの指示だけで、毎回同じ動作や料金低下が得られるわけではありません。

## 実運用版が約10kある理由

[実際に採用されたプロンプト](https://github.com/Kenn-dclxvi/the-caption/blob/3119a91d3fad63180884f80ac6b742fbae328afe/AGENTS.md)は、10.5KBあります。

上の表と5つの指示は、プロンプトへ書く内容の入口です。
実運用版では、判断条件と例外をAIが区別できるところまで具体化しています。
そのままコピーせず、自分の作業で判断が分かれる場所に条件を書いてください。

## この例文の位置づけ

上の5つの指示は、実運用版を置き換える完成済みの万能プロンプトではありません。自分の作業で起きる無駄を見つけ、進行条件と停止条件を書くための出発点です。

## これだけ覚えてください

長いプロンプトを書くこと自体が目的ではありません。

**AIが判断をやり直す場所を見つけ、次へ進める条件と、そこで止まる条件を書く。**

成果、変更開始、担当と結果、調査、完了を順に確認すると、必要な条件を見つけやすくなります。

次は、条件を足す前に減らせる無駄を[「AIプロンプトに書かなくてよかった7つのこと」](03_what-not-to-write-in-ai-prompts.md)で説明します。プロンプトだけで制御できる範囲を先に知りたい場合は、[4本目](04_what-prompts-can-and-cannot-control.md)へ進んでください。
