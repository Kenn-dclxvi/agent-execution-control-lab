# Candidate RequiredValueCarrier r1 設計記録

## 観測した問題

`chat-control-free-core-r1-n5-baseline-r1`では40件すべてが有効だった。品質4は36件、品質3は4件で、品質3はすべて`GCR-Q02`に集中した。

4件とも、質問、根拠要求、未解決扱いは増えていない。一方で、利用者が要約対象として与え、oracleが保持必須とした`120件`、`90件`、`8時間`、`5時間`の全部または一部を回答へ運ばないまま、`support_summary`を回答済みとしていた。うち3件は`4.1`と`4.4`も運ばなかった。

## 境界

- 直接の親: `chat-control-free-r1`
- 許可する差分: 利用者が与えた値のうち、依頼の成果を成立させるために保持が必要な値を、回答へ運ぶdependencyを一件追加する。
- 閉じる経路: 保持必須値を回答へ運ばず、その値に依存する話題を回答済みとして完了する経路。
- 正常経路: 言い換え、比較、計算、文章構成は自由に選べる。保持必須値を運んだ回答だけを完了可能とする。

## 維持する動作

- 利用者だけが決められる値が欠けた場合だけ、その値を質問する。
- 回答を変え得る根拠だけを求める。
- 独立した既知の話題は回答する。
- 受領済みの十分な根拠を再要求しない。
- 根拠が得られなかった話題について、確認できないことを伝える。
- 必要な回答が完了した後に、追加の質問や確認を付けない。
- 自然な一つのチャット応答として返す。

## 採用しない設計

- 成功runの要約文、数値の並び順または文章構成を手順として転記しない。
- 要約Caseだけの特別な処理順、自己点検票、役割名または状態報告を加えない。
- 入力上の全値を常に逐語で列挙させない。依頼の成果に不要な値まで運ぶ義務へ広げない。
- C147の制御原文、評価結果またはコード変更向けの工程を継承しない。

## 評価gate

固定Case、oracle、rating、TaskSpec wrapper、model、reasoning、CLI、権限、token契約および集計をbaseline N=5から変更しない。Candidate差分はisolated workspaceの`AGENTS.md`だけとする。

最初に`GCR-Q02`だけをN=5で評価する。5件すべてが有効かつ品質4であり、clarification、evidence requestおよびunresolved topicを増やさない場合だけ、保持対象の正常経路を壊していないかを総合Caseで評価する。条件を満たさない場合は後続を発行しない。
