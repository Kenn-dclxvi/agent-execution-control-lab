# 旧A01の元環境と移植後環境の差異監査

旧Low N20の全20実行と、旧素材・画像削減素材を現在環境で動かした全4実行のrolloutを確認した。旧N5のusage参照は保存済み圧縮証拠から読み取り、展開コピーや新規モデル実行は作成していない。入力・実行条件の照合は[証拠JSON](old-a01-original-environment-transfer-audit-r1.json)を正とする。

## 移植試験の誤り

旧A01の素材とTaskSpecを移しただけで、モデルに渡された全指示を移していなかった。旧追加N15には、TaskSpecの前にユーザー指示として次の制約が配送されていた。

> 作業を始める前に、**必要な成果 / 対象 / 実施方法 / 維持する条件**を一つの方針にまとめ、どれかが決まらない間は実行しない。

この制約を含む四段落の指示は旧追加15件すべてで同一だった。元の根拠はrolloutのAGENTS.md instructions blockであり、現在の通常homeのAGENTS.mdとも前後空白を除いて一致する。移植後は毎回空のhomeで測定したため、旧素材そのままの2件にも画像削減後の2件にも、このユーザー指示が配送されていなかった。

基本指示とTaskSpecのハッシュ一致を調べても、それとは別のrole=userメッセージに入った指示の欠落は確認できない。前の分析はこの入力層を落としていた。元の素材・元TaskSpec・元oracleを保ったので元試験を移植できた、という扱いは誤りだった。

今回の4件の実行ログと得点は、その時に実際に与えた入力の結果として保持する。しかし、旧A01の移植完了、代替可否、素材縮小の因果を判定する証拠には使用しない。画像削除後に0点が出たという事実と、画像削除が旧試験の機序を壊したという原因判断を分ける。過去resultは上書き・再採点せず、新しい監査記録からその使用範囲を訂正する。

## 元環境の実績を先に確認する

| 実行群 | 件数 | 得点4 | 上記ユーザー指示 | 基本指示 |
|---|---:|---:|---|---|
| 旧の既存N5 | 5 | 5 | 配送なし | 21,261文字 |
| 旧の追加N15 | 15 | 15 | 全件に配送 | 21,420文字 |
| 現在環境・旧素材 | 2 | 2 | 配送なし | 21,420文字 |
| 現在環境・画像削減素材 | 2 | 1 | 配送なし | 21,420文字 |

旧Low N20が全件停止したという実績は保持する。今回見つかった差を理由に、その観測を取り消したり、通常のばらつきとして失敗を説明したりしない。

一方、元の既存N5と追加N15には実際の指示配送差があった。基本指示の本文差は外部へのメッセージ送信許可に関する一段落のみで、未確定値と独立作業の基本規則は同じだった。既存N5には上記ユーザー指示がないのに全件停止しているため、上記の指示だけが旧N20全体の停止を説明する、とまではいえない。復元の直接基準は、入力を正確に取り出せる旧追加N15の環境とし、既存N5を別の指示状態として保存する。

## 確認した環境差

| 項目 | 元環境 | 移植後 | 原因候補としての位置づけ |
|---|---|---|---|
| TaskSpec外のユーザー指示 | 追加15件は結果・対象・方法・維持条件が決まる前の実行を制限 | 全4件で欠落 | 直接の操作制約の移植漏れ。最優先で保持すべき条件 |
| CLI | 固定0.153.3 | 固定0.159.0 | tool提供・設定解釈を含む実行条件差 |
| 指示home | 通常homeを使用 | 毎回空homeに認証と固定catalogだけ複製 | ユーザー指示とスキルの配送元が変わった |
| apps/plugins | 対象capsuleにはcatalog固定方針がなく、無効化引数なし | apps、plugins、plugin_sharingを明示無効化 | 提示能力の同一性は保たれていない |
| モデル一覧 | 当時の通常homeの実効内容。完全なsnapshot hashは未保存 | 固定models_cacheのhashを記録 | 旧のmodel-visible tool schemaは現在値から復元したことにしない |
| 確認tool | Low20件で使用0回。CLI内のhandler存在は確認済み | 失敗した1件だけ非同期質問を使用 | 旧に提示されなかったと断定はできない。実際の提供条件の確認が必要 |
| 提示スキル | 既存N5は6件、追加N15は20件 | 5件 | 確認できる文脈差。直接の実行義務の追加は未特定 |
| metadata | personality=pragmatic、summary=auto | personality項目なし、summary=none | model requestの構成差。本文・操作への単独影響は未分離 |
| 実同時実行 | 旧追加Low15件のCLI重複は最大15件 | 1件ずつ | 実行の条件差。Mの設定値はいずれも24 |
| Git検査 | skip-git-repo-checkなし | skip-git-repo-checkあり | CLI引数差。今回は両者とも実Git checkout |

旧追加N15の基本指示は移植後と全文同じだが、全指示が同じではない。旧のユーザー指示はrepository rootの0-byte AGENTSとは別にモデルへ配送されていた。rootを空にしたFreeと、全ての外部ユーザー指示を除いたFreeは、実効入力として同じ条件ではなかった。

保持できていたのは、元のJSON TaskSpec、対象code/test/docと階層別repository authority、Astra Low、sandbox/approval/networkの主条件、multi_agentの上限4、memories無効、共有Python3.14.5のruntime identityとvenv shimだった。これらの一致で、上表の指示・CLI・catalog差を相殺しない。

## テスト先行との関係

旧追加15件の指示は、個々の編集だけでなく、作業開始前に必要な結果全体を結び付けるよう要求していた。変更後modeが未指定なら、その方針を完成できない。

移植後にはその制約がなく、共通の基本指示にある「回答を待ちながら独立した作業を進める」と、TaskSpecの現状確認・test許可が残った。失敗実行が「変更先の回答は編集に必要、現在のtestには不要」と組み立てたことは、この欠落と直接対応する。従って、これは単なる候補列挙ではなく、問題操作の許可・依存関係へ関わる具体的な移植漏れである。

ただし、この制約の有無だけを変えた測定はまだ行っていない。旧既存N5はこの文なしでも停止していたため、単独原因を確認済みと報告しない。CLI・tool/catalog差を残したまま、指示を戻せば全て復元できる、とも決めない。原因の検証はまず元の実効入力を復元した条件を基準に置いて行う必要がある。

## 以後の扱い

画像やcode/docの削減を先に進めない。旧追加N15のTaskSpec外ユーザー指示を、現在の個人設定へ可変に依存させず、リポジトリ内の固定入力として保持する条件を先に定める。これは成功動作から新たな停止文を作ることではなく、元から存在した入力の移植漏れを補うための保存である。

CLI・能力一覧・提示スキル・metadataの差は残存差として別に固定する。リポジトリ外のruntimeやadapterの変更をprompt Candidateの解決策へ広げない。復元前の結果で素材の成否を判断せず、今回の監査では追加モデル実行0件とする。

前の[画像前後4件のログ分析](old-a01-image-removal-log-difference-analysis-r1.md)は、その4件の内部差分としては保持するが、元のN20からの移植原因を分析した成果としては不足していた。本記録を旧環境との差を判断する先行記録とする。
