# THE-CAPTION execution control

- OPERATION_SPEC: 実行前にrequired outcomeをoperation identityへ分け、`predicate / criterion owner / permission source / required result kind / result consumer / constraint / dependency`をTaskSpecへ固定する。`spec_ready := required outcome valueが、明示user inputまたはそのvalueを直接要求する一意なrepository authorityへbind済み`。required outcome valueはTaskSpecが利用者に観測可能な成果として選択を要求する値とし、target artifact / path / module / command / methodはTaskSpecが成果として要求しない限りimplementation choiceとする。current value / option set / complement / test expectation / convenienceはrequired outcome valueをbindしない。falseの間はproducer binding / predicate / artifact変更 / testを開始せず、TaskSpec本文と明示開始状態だけを直接観測し、未固定valueをclarification resultにする。外側admission、review、観測、変更、validationは別operation identityとし、result / constraint / terminalを別operationまたはtask全体へ伝播させない。
- PRODUCER_BINDING: 初回predicate前に各operationへrootまたはworkerのproducer execution identityを一つbindし、同一predicateを他producerへ順次・並行に割り当てない。TaskSpecが独立producer executionを明示した場合だけ指定identityをbindしてpredicate前に起動し、criterion owner、risk、roleまたは有用性だけでproducerを選ばない。producer変更は旧bindingを失効し、新operation identityと新TaskSpecで行う。先行resultまたはartifactを対象とする別operationには固有predicate、ownerおよびproducerを事前固定する。
- PRODUCER_RESULT: `delegated_result_ready := spawn result.task_name == task identity ∧ FINAL_ANSWER.Sender == task identity ∧ final resultをbind済みcriterionとtargetへbind可能`。`wait`、root宣言、進行記述、異Sender messageまたはroot要約はidentity証跡にならない。falseの間はcriterionをpassedにせず、producer terminal後もfalseなら`unavailable`にする。bind済みcriterionの`false / failed`はそのoperationのterminal resultとして保持し、別operation resultを失効させない。rootがproducerでないoperationではpacket、result admission、terminal集約だけを行い、predicateまたは意味resultを再生成しない。
- OWNER_ROLE: criterion owner、non_machine_risk、risk、role、静的確認、独立確認、成果確認、test-contract確認または有用性の語列はnon-machine riskの担当情報だけとして保持し、`explicit_review_operation_fixed`、review operation identity、task identity、worker、producerまたはspawnを成立させない。TaskSpecまたは適用authorityがreviewを必要な独立operationとして直接名指しし、独立producer execution identityを明示した場合だけ、そのidentityをreview operationとproducerへbindしてpredicate前に起動する。それ以外ではowner語列に対応するreview operation、packet、producer、spawn、review resultまたはreview admissionを作らず、root宣言または事後のworker起動で補完しない。
- OPERATION_TERMINAL: 全predicateにbind済みproducerのterminal resultがある場合だけoperationをterminalにする。invocation / worker / sessionがnonterminal、producer result identity不一致、またはrequired result欠落ならoperationもnonterminalとする。外側operationも必要な全operation、許可された変更およびrequired validationのterminal resultが揃うまでterminalにせず、進行報告 / 集約結果 / final responseで補完しない。
- WORKER_CONTEXT: 全worker packetへ`criterion / owner / pass condition / TaskSpec該当範囲 / target identity / scoped diffまたはresult / required evidence / allowed read / forbidden input`を固定する。これだけで判定可能なら`fork_turns=none`、不足時は意味保持に必要な最小turnだけを継承し、利便性や無関係なtool outputのために全履歴を継承しない。review packetにもこの共通contractを適用し、固有fieldだけを`REVIEW_PACKET`で加える。
- EVIDENCE_ADMISSION: repository evidenceは全lifecycleでdefault denyとする。`required_predicate_state := satisfied | unsatisfied | unobserved`、`evidence_consumer_ready := required predicateがnonterminal ∧ state=unobserved ∧ 欠けた観測値がbind済み ∧ requested resultがそのstateをbind可能`の場合だけ発行する。validation predicate固定後はcommand / locator / symbol / 慣行が未固定なだけで`unobserved`へ戻さずmethod選択用evidenceを追加しない。変更または失敗resultは入力を変えたpredicateだけを失効し、consumer terminal後は未発行evidenceを失効する。`spec_ready=false`ではOPERATION_SPEC許可外を発行しない。true後の変更前evidenceは`target artifact / 明示read-only path / 適用repository instruction / implementation choiceを解決するauthority`だけを許可し、required outcomeを事後補完しない。`implementation_bound := 許可resultからtargetと適用instructionがbindされ、全change effectとartifact間relationがadmission済みcontent上で実行可能な一変更predicateと保持constraintへbind済み`。trueだけを変更前operationのterminal resultとし、未発行evidenceを失効して変更へ進む。変更後に確定するvalidation identityは`VALIDATION_PLAN`で扱う。追加evidenceは許可resultが`missing / unreadable / bind済み値との具体的矛盾 / allowed path内で充足不能 / 別authorityの明示`を観測した場合だけ、そのresultと次identityをbindして一件許可する。permission / allowed read / tool / 一般的安全確認は開放条件にしない。
- REVIEW_REQUIREMENT: `subject`は`implementation_bound=true`の一変更predicateとし、target数、field数、artifact数、open classまたはreview都合で再分解しない。`explicit_review_operation_fixed := TaskSpecまたは適用authorityがreviewを現在subjectへ必要な独立operationとして直接名指しし、そのreview criterion / allowed result kind / result consumer / execution independenceを明示値で固定済み`、`review_control_applicable := explicit_review_operation_fixed`とする。criterion owner、non_machine_risk、静的確認、独立確認、成果確認またはtest-contract確認だけでは`explicit_review_operation_fixed=false`であり、欠けたreview fieldを推論または一般的慣行で補完しない。`finite_direct_match := 先行する一意なTaskSpecまたはauthorityが全target / effect / end stateまたはtransform / 保持constraint / artifact間relation / 集合全件性を直接固定 ∧ 既存machine-bound resultだけで変更predicateとの過不足ない一致を判定可能 ∧ 追加選択 / 除外 / 探索 / fallback / normalization / 完全性判断なし`。`review_requirement := not_applicable if review_control_applicable=false; not_required if applicable ∧ finite_direct_match; required otherwise`。非適用ではreview operation、packet、producer、spawn、review resultまたはreview admissionを作らず共通coreだけを使い、not-requiredではreview一式を作らず変更admissionへ進む。
- REVIEW_EXECUTION_PERMISSION: requiredでは新規permissionより先に保存review resultを`REVIEW_RESULT_ADMISSION`と`RESULT_EFFECT`で照合し、admittedかつactiveで`result_use_permission=allowed`なら新reviewを作らず使う。それがない場合だけ`review_execution_permission := allowed | denied`をTaskSpecまたはauthorityからbindする。`review_operation_ready := required ∧ active prior resultなし ∧ permission=allowed ∧ review operation identity固定済み ∧ 独立producer bind済み ∧ review_packet_ready`。deniedではreview operation / packet / producer / spawn / deliveryを作らず、prior resultもなければroot producerの外側admissionを`unavailable`にする。新規実行permissionは保存result利用permissionを兼ねず、tool・method failure、missingまたはreviewer unavailableをdeniedへ変換しない。
- REVIEW_PACKET: `review_packet_ready := WORKER_CONTEXT全field ∧ subject / 保持constraint / semantic design input / authority / 規範predicate / review scope identity集合 / 各observation identity・target・allowed read・success condition / allowed result kindが固定済み`。評価case、private oracle、期待terminal、過去finding、旧prompt、修正案、実装後diffまたは禁止履歴を含めず、許可artifactの必要projectionだけを入れる。target存在、read成功または全atom valueはreadinessに含めない。identity未固定、projection不能、allowed read未固定、または禁止情報を分離不能な場合だけpacketを`unavailable`にし、reviewer resultを作らず外側admissionを`unavailable`にする。
- OBSERVATION_RESULT: `observation_atom := observation identity + target identity + predicate identity + producer identity + invocation result identity + invocation result contract identity + terminal state`、`terminal state := value | missing | unreadable | terminal_failure`。producerはbind済みreview producer、tool invocationは観測源とする。正常観測した不存在だけをmissing、resultを返せないinvocationをterminal-failureとし、permission deniedをatom stateにしない。root推測、reviewer宣言、別atom成功またはaggregate exitからvalueを作らない。相互非依存atomは同じmodel stepから発行できるが、`observation_integration_allowed := 各atomのterminal stateを直接返す ∧ 一atom失敗が他atom stateを消さない ∧ result contractがaggregate non-success時も個別successをauthoritativeと固定`の場合だけ統合し、それ以外は別invocationにする。実invocationなしのsuccess receiptをadmitしない。
- REVIEW_JUDGEMENT: bind済みreviewerはreview packetとadmitted observationだけから`counterexample_found | no_counterexample_found | unavailable`を形成する。`counterexample_certificate_ready := concrete witnessがvalue ∧ applicabilityの規範predicateと全入力がvalue ∧ positive applicability ∧ 固定処遇との直接矛盾 ∧ 解消に一般設計のtarget / rule / permission / method / stop condition変更が必要`。実際に使ったobservationだけへ依存し、certificate外missingで失効させない。`no_counterexample_certificate_ready := 固定review scope全件review済み ∧ manifest全atomがauthenticなvalue ∧ 全規範predicate適用後もcounterexampleなし`。未来全域は要求しないが一atomでもnon-valueなら成立させない。`review_unavailable_ready := 前二certificateがfalse ∧ 未解決predicate固定済み ∧ それを閉じ得るnon-value atom固定済み`。一般的不確実性だけでunavailableにしない。counterexample成立時は無関係な未発行observationを失効し、それ以外だけ全scopeを判定する。
- REVIEW_RESULT_ADMISSION: rootは意味判断を再実施せず、current resultと保存済みprior resultを別predicateで機械照合する。`current_review_result_admissible := operation identityがcurrent bound review operation identityと一致 ∧ review_execution_permission=allowed ∧ producerとsenderがbinding一致 ∧ result kindがallowed ∧ 参照observationが実在・authentic・current ∧ terminal certificate充足 ∧ forbidden inputなし`。`prior_review_result_admissible := operation identityがTaskSpec許可prior identityと一致 ∧ result_use_permission=allowed ∧ current subject / criterion / allowed kind / packet basis / producer / dependency一致 ∧ result_still_valid=true ∧ producer・sender・observation・certificate・forbidden input条件充足`。current review resultへ別の`result_use_permission`を追加要求せず、保存resultへ新規`review_execution_permission`を要求しない。canonical locator、集合順、文字列またはroot独自projectionとの完全一致を要求しない。inadmissible resultを再割当てまたは補完しない。
- RESULT_EFFECT: `result_effect_scope := resultがtarget / permission / method / stop conditionを変え得る未発行operation class集合`、`decision_boundary(next) := next.class ∈ result_effect_scope`。効果をtask全体へ伝播させず、falseの既知相互非依存invocationは同一model stepから発行する。開始identity resultはTaskSpecがdrift時に禁止するclassだけへ効かせる。driftが変更とrequired commandだけを禁止するなら許可・固定済みreadを同じstepから発行し、read禁止またはread target / permissionが変わり得る場合だけ分ける。review resultの`dependency_set := subject + criterion + review scope + certificate observation集合 + 保存済みprior resultの場合だけresult use permission`、`result_still_valid := dependency内identityまたはvalueを変えた新resultなし`。新規review execution permissionは保存result dependencyにしない。counterexampleはwitness、no-counterexampleはscope全atom、unavailableは未解決predicateとnon-value atomへ依存し、対応subjectの未発行変更と外側admissionだけへ効かせる。terminal reviewを再開せず、再判定は新operation / packet / producer / result identityで行い、禁止なら固定stopへ閉じる。
- CHANGE_ADMISSION: `subject_change_allowed := review_requirement=not_applicable ∨ review_requirement=not_required ∨ (required ∧ admitted no_counterexample_foundがactive)`。これは`implementation_bound`、明示permission、change predicate、保持constraintおよびvalidation gateを置換せず全件必要とする。`subject_change_denied := admitted counterexample_found active ∨ admitted review unavailable active ∨ (review permission denied ∧ active prior resultなし) ∨ review packet unavailable`。counterexampleは対応変更を`blocked`、判断材料不足は`unavailable`にする。複数subjectを一invocationへ含む場合は全subject allowedかつ全relation成立を要求し、禁止subject除外でrequired outcome、relationまたは実行可能性を壊すなら一部変更しない。別implementation choiceは新identityで変更前gateから行う。no-counterexampleでは変更・validation全success後に`completion_ready`、counterexampleでは`blocked`、review unavailableまたはpermission deniedでは`unavailable`とする。
- VALIDATION_CLOSURE: `validation_predicate_ready := artifact変更完了 ∧ TaskSpec-required validationのpredicate / order / individual pass condition / stop conditionが全件bind済み ∧ TaskSpecまたはcommand evidence protocolがexact commandを明示したvalidationだけそのcommandがbind済み`。`validation_predicate_ready=true ∧ producer=root`の場合、TaskSpecまたはcommand evidence protocolの「順に」「1 commandずつ個別」は、1回のcustom exec wrapper内で全required validationをbind順の個別`exec_command`として発行することを意味し、command resultをmodelへ返して次commandを別custom tool callで発行することを意味しない。各exit codeをwrapper内で確認し、nonzeroまたはunavailableなら後続を発行せず、shell compound commandへ結合しない。producerがroot以外の場合も全required validationを個別invocationとして同一model stepから発行する。完了済みの全resultを一度だけmodelへ返す。全件successかつ全result bind済みなら、TaskSpec追加要求またはresult失効がない限りread / validationを追加せずterminalを判断する。欠落 / non-success / unexpected stateはoperationをnonterminalにする。target探索 / 変更前 / review finding / 未固定methodまたはrecoveryへ適用しない。
- VALIDATION_PLAN: artifact変更後の検証開始前に、required validationと完了判定に必要と確定しているdiff / status等を一つの実行票へ順にbindする。TaskSpecまたはcommand evidence protocolがexact commandを明示しない場合、その未固定commandをmissing validation identityまたはrepository evidenceの開放条件にせず、既に受領したTaskSpec / 適用中instruction / target evidenceの範囲から`METHOD`として選び、実行票発行時にcommandへbindする。検証success後はmodelへ戻らず実行票の残りを発行し、全result受領後に一度だけ完了を判断する。実行票完了後はTaskSpec追加要求またはresult失効がない限りtoolを追加しない。validation wrapperがcell ID付きnonterminal resultを返した場合、その返却を実行票の完了判定へ使わず、実行票全体がterminalになるまで同じcell IDへのwaitだけを発行する。commentary / 進捗報告 / 判断 / 別toolを先に発行しない。
- METHOD: TaskSpec明示手段だけを固定する。未固定手段はpredicateを変えずpermission内で選び、validationでは既存のTaskSpec / instruction / target evidenceから実行票発行時にcommandへbindする。command選択だけでevidenceを追加しない。invocation failed / unavailableをpermission否定またはterminalにせず、未固定手段があれば同じpredicateへ継続する。tool failure、target missing、review unavailable、permission denialを相互変換しない。明示禁止 / permission否定は停止し回避しない。
- RECOVERY: `environment recovery := environment-only repair + same required command rerun`。組の開始時だけ`environment_recovery_max`を消費し、未固定手段の選択は数えない。review judgement、review result生成、失効result再利用またはterminal review再開を含めない。
