# 【衝撃】AIへの指示を1万バイト増やしたら、トークン代が安くなった

「AIのプロンプトは短いほど安い」

そう思っているなら、たぶん逆である。

同じAIに、同じ14課題を、同じ条件でやらせた。変えたのは、最上位の静的プロンプトだけ。**指示ゼロのFree版**と、147通り試した末の**最新版**を殴り合わせた結果がこれである。

|  | 0バイト（Free・基準） | 最新版 | Free比 |
| --- | ---: | ---: | ---: |
| 静的プロンプト | 0 B | **10,772 B** | **1万バイト増** |
| 実行中に使ったトークン | 3,488,611 | **1,447,626** | **58.50%削減** |
| API料金換算 | $5.08 | **$3.05** | **39.95%削減** |
| 最高評価だった実行 | 65 / 70件 | **70 / 70件** | **全件満点** |

**プロンプトを1万バイト増やしたら、実行トークンは半分以下。料金は約4割引。しかも品質は全勝。**

14課題を1,000セット回すと、API料金換算は約`$5,083 → $3,052`。差額は約`$2,031`である。日本円換算を持ち出すまでもなく、ちょっとした工夫で消える金額ではない。

## なぜ、文字を増やしたのに安くなるのか

AIが金を食うのは、プロンプトを読む瞬間だけではない。

本当に金を食うのは、指示が曖昧なせいで始まる**迷走**である。

- どのファイルを見るか迷う
- 念のため余計な調査をする
- 誰が作業するか考え直す
- 同じ確認を何度も繰り返す
- 終わっているのに、さらに検証する

短いプロンプトは、この判断をAIへ丸投げしやすい。AIは迷うたびに考え、読み、試し、また考える。**そのたびにトークンメーターが回る。**

最新版は逆である。「どこを見るか」「誰がやるか」「いつ終わるか」を先回りして決めた。読む量は増えたが、実行中の迷い、探索、やり直しが減った。その結果、動的な実行トークンは**58.50%減った。**

## 結論

**プロンプトをケチると、AIが勝手に残業する。**

削るべきなのはプロンプトの文字ではない。AIが実行中に迷う余地である。

良いプロンプトは長文だから安いのではない。**AIの無駄足を止める一文が入っているから安い。**

なお、金額は保存済みの通常入力・キャッシュ入力・出力トークンへGPT-5.6 SolのAPI単価を区分別に掛けた換算値であり、実際の請求額ではない。数値は各課題を5回ずつ実行した中央値である。他のリポジトリやモデルでも同じ削減率になるとは限らない。
